# KT Auto Code 产品功能归属矩阵

状态：current

Owner：KT Auto Code maintainers

适用版本：0.6.x

最后核验：2026-08-08

本文由 KT Auto Code 维护，只记录基础插件的能力应共享到 Phoenix Wing 的层级，以及必须保留在 VS Code Host 的责任。KT Auto CAD 在[自己的产品功能归属矩阵](https://gitee.com/PhoenixWing321/kt-auto-cad/blob/master/doc/产品功能归属矩阵.md)中维护 CAD 能力；Phoenix Desk Tools 维护自己的[对应矩阵](https://gitee.com/phoenixwing/phoenix-desk-tools/blob/develop/doc/产品功能归属矩阵.md)。各表使用相同的 `featureId` 对齐，但不互相复制状态。

Wing 已实际导出的能力只认 [Wing 共享能力目录](https://gitee.com/phoenixwing/phoenix-wing/blob/develop/doc/共享能力目录.md)中的 `capabilityId`、export 和源码相对路径。跨库盘点过程与阶段决策归档在本机 Phoenix AI Workspaces 的 `wing-projects/work/三库功能归属与迁移协调-2026-07-22.md`；该内部工作记录不是发布包依赖。

## 维护规则

- 两张产品表出现相同 `featureId`，表示需要核对行为、契约或 UI；只出现在一张表中，默认是产品专有能力。
- `共享完成` 只用于本仓库已经消费 Wing 正式 export 的能力。Wing 已提供但本仓库仍用私有实现时标为 `部分共享`。
- VS Code Commands、Settings、QuickPick、Problems、Output、SCM、编辑器定位和 `workspaceState` 是 Host 能力，不因为 Desk 有对应页面就迁入 Wing。
- 新增跨产品能力时，先同时核对两张矩阵，再按“Wing 契约/core → 各 Host adapter → 共用 UI → 删除重复实现”推进。
- 协同优先级：`P0` 当前收口；`P1` 已有双端重复，紧接处理；`P2` 先共享契约或等待第二个真实消费者；`—` 产品/宿主专有，不做对端追平。

## 变更流程

1. 在本表找到 `featureId`，再打开 Desk 对应矩阵检查同名行。
2. 如果 Wing 已有能力，必须引用共享能力目录中的 `capabilityId` 和 export；不得只凭相似文件名判断已共享。
3. 若是 `P0/P1`，改代码前写清行为真源、双方 Host adapter、共同 fixture 和最终删除对象。
4. Wing 先提供正式或受控本地入口；本仓库继续锁 Registry 精确版本，本地联调只用既有 resolver。
5. 两端消费并通过共同 fixture 后，才把状态改成 `共享完成`；没有第二消费者时保持专有。
