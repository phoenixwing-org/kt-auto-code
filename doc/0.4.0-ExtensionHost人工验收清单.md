# 0.4.0 Extension Host 人工验收清单

> 本清单验证单 Block 样板、Ribbon、Block 内范围选择与 Git 集成。请使用临时工作区或干净分支；写盘操作完成后用 Git Diff 确认并还原。

## Ribbon 与 Block

1. 按 F5 打开 Extension Development Host，进入 `KT Auto Code` 侧栏。
2. 默认只显示最小高度 Ribbon；它不应占用侧栏剩余高度。
3. 依次点击“头文件、编码、忽略、替换、排序、UUID、CAA”，确认 Ribbon 本身不执行扫描，而是在正下方展开对应的原工具界面 Block。
4. 每个模块在界面内点击预检/扫描/分析后，状态与结果直接接在同一 Block 下方；当前 Block 不得收起或被另一个结果 Block 替换。
5. 再次点击其他 Ribbon 模块，确认新工具界面保持在 Ribbon 正下方；切回任一模块时缓存不清空。
6. 工具界面标题有 `×`；关闭再打开任一模块后缓存仍可重放。
7. 扫描没有命中时，当前 Block 显示明确的扫描状态和空结果分组，而不是空白区域。
8. 连续打开至少三个模块：当前 Ribbon 按钮使用活动高亮，已打开但隐藏的按钮使用次级强调色；悬停应显示已打开总数。
9. 关闭当前模块后应按最近使用顺序恢复上一个；逐个关闭至最后一个时才收起模块区，重新打开后原结果缓存仍在。

## C++ 成员排序单 Block

1. 点击“排序”只展开一个模块 Block；点击“扫描”后不得再出现第二个“成员排序”View。
2. 默认只显示变更文件；勾选“显示无变更文件”后出现独立无变更分组。
3. 取消部分 checkbox 后执行“应用所选”，只修改仍勾选的 pending 文件；未勾选状态不得被刷新重置。
4. 单文件预览只打开该文件的预览 Diff；批量/单文件应用后不自动弹出任何 Diff。
5. 写盘行原地变为“已写盘”，并提供按需 Git Diff 与还原；还原后原地显示“已还原”。
6. 扫描后外部修改文件时，应用必须阻止覆盖；写盘后外部修改时，还原也必须阻止覆盖。
7. 行内 `×` 只从当前缓存隐藏候选，不重新扫描；“加入工作集”继续可用。

## 搜索替换

1. 点击 Ribbon“替换”，确认原来的完整搜索替换表单出现在 Ribbon 下方，而不是立即弹出输入或执行预览。
2. 选择“预览”，确认结果直接进入当前“搜索替换”Block 下部，文件行仍由 VS Code 编辑器打开，不出现独立结果 View。
3. 多规则、关联规则和规则档案仍位于同一个工具界面 Block；关闭后只保留 Ribbon 和已有结果。
4. 选择“替换”时，仍必须经过写盘确认；完成后只查看 VS Code Git Diff，不自动弹出多个 Diff。
5. 用文件名和正文都包含搜索词的样例预览：Block 结果行文件名中的匹配片段应使用 VS Code 查找主题色高亮；点击行后，右侧编辑器全部正文命中使用醒目的黄/浅黄色背景，并在概览尺显示标记。
6. 写盘后重新打开结果，右侧应高亮替换后的新词；切换到无关编辑器后，上一文件的黄色装饰应自动清除。

## 头文件 ASCII 高亮

1. 预检包含多个问题位置的头文件并从当前 Block 结果行打开；右侧编辑器应同时标出全部问题字节位置，而不只移动到第一行。
2. 文件名本身包含非 ASCII 字符时，只高亮文件名中的非 ASCII 片段；普通 ASCII 文件名不整行染色。
3. 高亮使用 VS Code 查找匹配主题色和概览尺标记；切换到无关编辑器后不应残留。

## Ignore 推荐

1. 点击 Ribbon“忽略”，确认先展开原 Ignore 设置界面；点击分析后规则组显示在当前 Block 下部，不出现第二个 `Ignore 推荐` View。
2. 查看建议规则；勾选一组后，顶部“追加所选推荐”按钮可用。
3. 含“需确认”标识的组在追加前必须弹出原生二次确认。
4. 标题中的“打开规则”“同步”“高级配置”继续可用；高级配置仅在需要预设编辑时打开。

## 工作集与 Desk Tools 复用项

1. 点击主侧栏标题的“工作集”图标；不存在配置时应创建并打开 `.phoenix/worksets.json`，且插件的普通源文件扫描仍不得把 `.phoenix/` 当作输入。
2. 保存至少两个工作集后，确认 ASCII、编码、搜索替换、成员排序、UUID、CAA 的 Block 顶部都有“整个工作区/工作集”下拉框；选择不会弹出 QuickPick，切换模块再返回仍保留各自选择。
3. 搜索替换保留独立“工作目录”：目录位于当前工作区时，再受 Block 顶部工作集约束；目录位于工作区外时明确提示不使用工作集。连续预览不得反复要求选择范围。
4. 从成员排序单 Block 的“加入工作集”及其他结果入口把文件加入已有工作集；重复执行不得添加同一条精确路径。`worksets.json` 有未保存修改时必须阻止覆盖。
5. UUID 扫描分别选择“同值同替换”和“每处独立新值”；结果根行显示当前策略，后者不得在应用阶段悄悄改回前者。
6. 在工作区根创建 `build-local/`、`bin/` 等目录后分析 Ignore；应出现“顶层构建与缓存目录”建议，但不会自动写规则；目录内有 Git 已跟踪文件时建议应被阻断。
7. 搜索替换无命中、配置错误或工作集失效时，Block 必须结束转圈并显示“没有匹配结果”或具体错误，不得无限保持运行态。

## 工程环境 Block（Windows 重点）

1. 点击主侧栏标题齿轮，确认打开“工程环境”Block；VS Code Settings 中不再出现四个 `ktAutoCode.environment.*` 覆盖项。
2. Block 显示 `ROOT_DIR`、`ROOT_DIR_3rdParty`、`ROOT_DIR_CORE` 与可选的 `CAA_MK_VERSION`；缺失必需值、路径不存在和建议值 `19` 显示正确。
3. 在 Windows 系统环境变量界面修改当前用户值，不退出 VS Code，返回点击“刷新系统值”；应直接读取注册表中的新值。
4. 手工输入并点击“新建/修改”，确认只写当前用户环境；“选择…”允许选择目录或文件；清除前必须二次确认。
5. 已存在机器级同名值时，修改产生用户级覆盖；清除用户值后机器级值重新显示，机器级注册表不得被插件修改。
6. 修改后当前扩展功能立即使用新值；新终端和其他应用仍需重新启动。macOS 修改仅承诺当前 `launchctl` 登录会话，不宣称跨重启持久。

## 原生 Diff 与写盘

- 成员排序单 Block 与 UUID 结果的单文件操作保留查看、预览 Diff、应用/撤销或 Git Diff 图标。
- 所有已写盘文件均使用 VS Code 原生 Git Diff；插件不创建 untitled 预览页，不逐文件自动弹 Diff。
- 头文件 ASCII、编码、Ignore、搜索替换、CAA 的原操作表单位于 Ribbon 下方工具界面 Block，结果紧随其后；系统级设置仍打开 VS Code Settings。
