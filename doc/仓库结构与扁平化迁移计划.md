# 仓库结构与扁平化迁移记录

状态：completed

Owner：KT Auto Code maintainers

适用版本：0.6.3+

最后核验：2026-08-08

## 结论

KT Auto Code 已完成根目录扁平化。仓库根现在同时是唯一 pnpm 包、VS Code 扩展包和版本真源；不再存在仅容纳一个成员的 `extension/` workspace。

这是常见的单扩展仓库结构：根 `package.json` 提供 Marketplace manifest，`src/extension.ts` 是 Extension Host 入口，`media/`、`resources/` 与 `dist/` 均相对包根。KT Auto CAD 已采用相同的根包惯例，不需要再次迁移；两仓内部可以按复杂度保留不同分层。

## 当前结构

```text
package.json          # 唯一扩展 manifest、版本与开发/验证/发布入口
src/
  extension.ts        # Extension Host 激活入口
  core/               # Auto 专属 Host-neutral 模型、工作流和算法
  sidebar/            # Sidebar/Primary Webview 与 Host adapter
  tools/              # 各工具的 VS Code adapter 与界面实现
media/                # Marketplace、Activity Bar 与工具图标
resources/            # 随 VSIX 发布的只读 runner
scripts/              # CLI、开发、构建、测试、打包与发布门禁
tests/
  fixtures/           # 核心、CLI 与 Extension Host 代表夹具
  webview/            # 浏览器/Webview 结构夹具
doc/                  # 当前文档、专项计划和历史归档
dist/                 # Git ignored 的运行 bundle
  vsix/               # VSIX 与 SHA-256 本地归档
```

`src/core/` 不是所有跨产品核心能力的总库。真正跨宿主、跨产品共享的算法与契约以 Phoenix Wing 为真源；这里仅保留 Auto Code 自身仍需复用的 Host-neutral 模型、工作流和兼容算法。

## 迁移决策

1. 合并原根编排 manifest 与扩展 manifest，根 `package.json` 成为唯一版本和 Marketplace 配置真源。
2. 原根 `src/` 迁入 `src/core/`，保持无 `vscode`、DOM 和 Webview 依赖的架构边界。
3. 原 Extension Host 与 Webview 源码上移到 `src/`；标准入口为 `src/extension.ts`。
4. 图标、runner、浏览器夹具、CHANGELOG、VSCE ignore 和 esbuild 配置全部上移到包根。
5. 删除 `pnpm-workspace.yaml`、嵌套 manifest、重复 TypeScript/F5 配置以及 `pnpm -C extension` 转发。
6. F5、Host smoke、Registry/本地 Wing 构建、VSCE 和制品门禁均从根目录解析扩展。
7. 历史 VSIX 从旧目录迁到 Git ignored 的 `dist/vsix/`，源码树不再保留发布制品。

## 不变量

- 正式 Phoenix Wing 依赖仍精确来自 npm Registry；manifest 与 lockfile 不得出现 `link:`、`file:`、workspace override 或本地 Wing 路径。
- `pnpm dev` 继续只通过受控 wrapper 使用并列 `../phoenix-wing`，并由 metafile 门禁证明来源。
- CAD 继续由并列 `../kt-auto-cad` 独立构建和发布；Auto 根结构不重新引入 CAD 源码。
- VSIX 压缩包内部仍使用 VSCE 规定的 `extension/` 前缀；这只是制品内部目录，不代表源码仓库重新存在 `extension/`。
