# 搜索替换编码规则

本文定义工作区搜索替换处理文本文件时的编码算法。目标是：替换命中文本，不重写未命中的字节、BOM 或换行；只有原文件纯 ASCII 且替换目标引入双字节字符时，才要求用户选择目标编码。

## 基本原则

1. 先检测原文件编码，再以该编码生成搜索与替换字节序列。
2. 原文件不是纯 ASCII 时，编码已有证据，应保持原编码。
3. ASCII 是 UTF-8 与 GBK 的共同子集；因此它本身无法说明用户希望将新加入的双字节字符写成 UTF-8 还是 GBK。
4. 只有第 3 种歧义场景才读取界面中的 **默认编码**。默认编码可选 `UTF-8` 或 `GBK（本地）`，初始值为 UTF-8。
5. 自动匹配大小写当前禁用；规则始终精确匹配大小写，不派生全大写规则。

## 决策表

| 原文件检测结果 | 命中规则的目标文本 | 写入编码 | 原因 |
| --- | --- | --- | --- |
| ASCII | 全部为 ASCII | ASCII | 替换前后均无歧义，保持 ASCII 字节。 |
| ASCII | 任一目标含非 ASCII 字符 | 界面选择的默认编码 | ASCII 无法区分 UTF-8 与 GBK。 |
| UTF-8 / UTF-8 BOM | 任意 | 原 UTF-8 形式 | 原文件已提供 UTF-8 证据；BOM 保留。 |
| GBK | 任意可表示字符 | GBK | 原文件已提供本地 GBK 证据。 |
| UTF-16 / UTF-32 / unknown | 任意 | 跳过 | 当前字节级替换不处理宽字节或未知编码。 |

例如，ASCII 文件中 `AutoCode → 自动代码`：选择 UTF-8 时写入 UTF-8 字节；选择 GBK（本地）时写入 GBK 字节。相反，原文件已经检测为 GBK 时，即使界面默认编码选 UTF-8，`旧名 → 新名` 仍保持 GBK。

## 安全边界

- GBK 目标文本必须可以无损编码为 GBK；不能表示时替换失败，不以 `?` 等替代字符静默写入。
- 默认编码不改变已有 UTF-8、UTF-8 BOM 或 GBK 文件。
- 文件名和目录名使用 JavaScript 字符串改名，不受此默认编码选项影响。
- 预览与写盘使用同一决策规则；结果 View 显示检测到的原始编码与处理状态。
