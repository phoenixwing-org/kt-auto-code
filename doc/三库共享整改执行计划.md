# KT Auto Code：三库共享整改执行计划

> 本文是 VS Code 插件侧的执行计划；跨仓库目标、公共接口和版本策略以 `phoenix-wing/doc/三库共享核心整改计划.md` 为唯一权威来源。成员排序算法统一见 [phoenix-wing · C++成员排序算法规范](../../phoenix-wing/doc/C++成员排序算法规范.md)，不得在此复制或更新规则。

## 目标

让函数排序在 VS Code 离线可用，并与 Phoenix Desk Tools 使用同一份 `phoenix-wing` core：扫描后在**编辑区结果 View**预览差异，用户选择并确认后才写回。Side Bar 只承载范围、选项、触发和摘要，交互模式与现有搜索替换/改名一致。

## P0：一小时基线整改

- [x] 根包、扩展包和根许可证均为 Apache-2.0。
- [x] 权利人统一为“上海锟钛”。
- [x] 记录共享 core、View 预览与文档归属边界。
- [x] 复核现有 VSIX：包含 `extension/LICENSE.txt` 与 `extension/NOTICE`，市场元数据为 Apache-2.0；每次发布仍须复核新产物。

## P1：共享排序预览

1. 接入 `phoenix-wing/code-core` 的稳定版本；Extension Host 不复制排序规则，也不调用 Python 或 desk-tools HTTP 服务。
2. [x] 在 Host 中按工作区范围读取 UTF-8/UTF-8 BOM 候选文件，调用 core 获得只读预览；GBK 暂显示明确诊断，待 `file-core` adapter 接入。
3. [~] 新建“C++ 成员排序预览”编辑区结果 View：已显示文件、变更数和锁定区/解析诊断；待补文件勾选、单文件 diff 和确认应用。
4. `应用` 前再次检查文件指纹；只写入用户勾选且仍与预览一致的文件。取消或冲突不写盘。
5. 增加 fixture 契约测试：同一输入与 desk-tools 的 core 结果一致；插件只测试 Host 编排、消息校验和 View 状态。

## P1a：`src/` 按能力解耦（排序接入前完成）

当前 `src/` 将 Ignore、编码、搜索替换、路径和 ViewModel 平铺在同一目录。新增排序功能前先按**领域能力**整理，测试与实现同目录，保持现有 `ktc*` / `Ktc*` 导出名称和 CLI API 不变：

```text
src/
  ignore/          .phoenix/.ignore、预设、推荐、规则 catalog、工作区快照
  encoding/        字节扫描、文件编码、BOM、全角字符、扫描/转换遍历
  searchReplace/   规则、关联规则、profile、重命名工作流、结果 ViewModel
  workspace/       路径安全、扫描范围、工作目录
  shared/          跨领域且无业务语义的最小工具（仅确有需要时新增）
```

- 每个移动单元包含实现、同名测试和必要 JSON；只改 import 路径，不同时改变行为。
- `src/` 不导入 `vscode`、DOM 或 Webview；Node 文件系统只能存在于明确的 workspace/IO 编排模块，纯算法保持可移植。
- `extension/src/tools/<feature>/` 保留每个工具的 VS Code command/controller；`extension/src/workbench/` 仅保留编辑区结果 View。
- `reorderMembers` 只在 `extension/src/tools/reorderMembers/` 增加 Host adapter 和结果 View controller；排序规则本身只能来自 Wing 的 `pnw*` / `Pnw*` API。
- 迁移按 `ignore → encoding → searchReplace → workspace` 小批提交，每批运行对应单测和全量 `pnpm test`，不做一次性大搬家。

首批已完成：`workspacePath` 与 `scanScope`（含测试）迁入 `src/workspace/`；根测试与 Extension 构建均通过。其余领域目录按上述顺序继续迁移。

## P2：CAA 轻量入口

- 在编辑区结果 View 提供 `.CATDlg` 解析摘要、诊断和 diff；大型画布、拖动和多 Tab 不进入 VS Code Webview。
- 通过版本化任务协议启动 desk-tools/Tauri companion；返回后刷新文档并展示实际变更。
- CAA 写回始终由共享 `catdlg-core` 的 patch/validate 流程完成，Wizard marker 外代码不可修改。

## 完成标准

1. VSIX 离线运行函数排序，不依赖 Python 或已启动的 desk-tools。
2. Side Bar 不出现复杂结果表；预览、勾选、diff、确认均在编辑区 View。
3. 同一 fixture 在 desk-tools 和插件产生相同文本、编辑列表与诊断。
4. 产品元数据、README 和许可证附录的权利人、SPDX 都一致。
