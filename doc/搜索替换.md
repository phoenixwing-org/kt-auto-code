# 工作区搜索替换

工作区搜索替换用于在当前 VS Code 工作区或其内部指定工作目录中预览和执行三类精确修改，不限于源码文件：

- 文件夹名中的命中片段替换。
- 文件名中的命中片段替换。
- 文本内容替换。

## 使用方式

1. 打开 Activity Bar 的 **KT Auto Code**。
2. 选择 **搜索替换**，在 Side Bar 填写搜索值、替换值和范围。
3. 点击 **预览**在当前编辑分栏的 View 查看结果，确认后再点击 **替换**。

搜索、替换、前缀或工作目录输入框中的 `Enter` 不触发操作。预览和替换必须点击明确按钮；写盘前仍会弹出确认框。

**工作目录**留空时使用当前 VS Code 工作区根目录。也可填写工作区内的相对路径（如 `src/OldModule`）或绝对路径；指定非根目录时，该目录本身会参与文件夹改名。越出当前工作区、指向单个文件或经过符号链接的输入会被拒绝。

## 关联规则

点击 **展开关联规则**可增加多行搜索/替换，每行可启用、排序、删除或通过末尾菜单添加一种关联。输入母规则后可填写源、目标前缀，并分别使用 **常用规则**或 **CAA 规则 ▾**：

```text
CaaStudy → TomBuild
Caa Study → Tom Build
KTCCaaStudy → KTMTomBuild
```

源、目标前缀是普通文本，例如 `KTC → KTM`；不输入源前缀时不生成前缀或 CAA 规则。自动生成行被手工修改后转为自定义规则，之后重新生成不会覆盖它。

`CAA 规则 ▾`要求用户选择一种互斥模式：

- **完整名称 I/E**：`PNXITemplateFeature → PNXICurveDivision`。
- **仅替换末词段 I/E**：`KTCIAutoCode → KTCIAutoBuild`。

逐行菜单使用相同算法，可单独添加空格、前缀、CAA I 或 CAA E 规则。真实依据与边界见 [PNXCaaStudy CAA 命名规则调查](./PNXCaaStudy-CAA命名规则调查.md)。

## 工作区规则档案

关联规则区提供 **规则档案…** 下拉和 **保存规则**按钮：

- 下拉只把已保存档案填入当前草稿，不自动预览、替换或再次保存。
- 只有点击 **保存规则**并确认名称后，才写入当前工作区 `.phoenix/search-replace.json`。
- 档案包含母规则、源/目标前缀、关联规则、替换范围、工作目录和 Ignore 选项。
- 同名档案由用户明确选择更新或另存；取消不会写文件。
- 文件缺失时只显示空列表，不自动创建；现有 JSON 损坏时拒绝覆盖。
- 不写入 VS Code 机器级 `globalState`，避免不同客户或工作区之间自动混入搜索词。

`.phoenix/search-replace.json` 是可读的项目配置，是否提交 Git 由项目决定。临时输入仍保存在 Webview state，与共享档案分离。

勾选 **保持大小写** 后，每条规则自动派生全大写形式。引擎对显式与派生规则仍做精确匹配；最长匹配优先，同长度按界面顺序，替换结果不再级联进入后续规则。

## 安全策略

- 文件名和文件夹名在单个 basename 内替换所有命中片段，不直接替换完整路径字符串。
- 当用户同时勾选多个级别时，执行顺序固定为**文件夹 → 文件名 → 文本**；未勾选的级别跳过，不改变其余级别的相对顺序。
- 文件夹阶段先递归收集并按最深层到最浅层改名；每完成一个阶段都重新收集当前工作区条目。若指定工作目录本身被改名，后续文件名和文本阶段会从它的新路径继续执行。
- 文本阶段最后遍历当前路径下的文件。每个文件只读取一次，并对同一份原始字节应用全部启用的关联规则：最长匹配优先、同长度按规则顺序，替换结果不再进入下一条规则。
- **工作目录留空时，当前 VS Code 工作区根目录永不改名**：扫描只收集其内部条目，不会使打开的工作区失效。
- 工作目录指向工作区内部的非根目录时，该目录本身属于扫描条目，可以被改名。
- 当勾选“文件夹名”并运行预览/替换时，若根目录名称命中任一启用规则，Primary 面板下方显示建议的新名称；插件不提供自动改名，用户自行在 VS Code 外部完成根目录改名后再重新打开工作区。
- 提示中的“创建 TODO”会在工作区根目录创建并打开 `KT-AUTO-CODE-TODO.md`，列出当前名、建议名和手动改名步骤；仅在用户点击时写入，已有同名文件不覆盖。
- 目标路径已存在或多个源映射到同一目标时，预检返回 `blocked`，不弹写盘确认框，也不执行部分改名。
- 写盘后结果行指向新路径，可继续定位文件或文件夹。
- 支持大小写-only 改名，通过临时名称保证在大小写不敏感文件系统上可执行。
- 自动跳过符号链接、常见构建目录、二进制后缀和含 NUL 的文件。
- 默认读取 `.phoenix/.ignore`；“包含 Ignore 路径”只用于明确的人工操作。
- 预览不写盘，写盘前插件再次显示 Modal 确认。

## 编码行为

文本替换先检测文件编码，再按该编码生成匹配字节并在原始 Buffer 上精确替换；**替换前后检测到的编码必须一致**，不重新格式化或以默认 UTF-8 重写整文件。

| 文件编码 | 当前行为 |
| --- | --- |
| ASCII / UTF-8 / UTF-8 BOM | 支持任意 UTF-8 旧名和新名；保留 UTF-8 是否带 BOM、换行和其他字节 |
| GBK | 首版支持 ASCII 旧名和新名；保持 GBK，原始中文、换行和其他字节不变 |
| UTF-16 / UTF-32 / unknown | 列为跳过，不写盘 |

GBK 限制是有意的安全边界：Node.js 没有内置 GBK 编码器，在未引入经过验证的转码依赖前，不对包含非 ASCII 新旧名的 GBK 文件写盘。

## 当前界面形态

搜索值、替换值、级别、工作目录和 Ignore 选项放在 Side Bar；`WebviewPanel` 在当前编辑分栏打开，只展示详细预览与执行结果。完整结果保留在 Host，Webview 每次只接收 300 行；点击“继续加载”时按报告版本请求下一页，避免旧分页混入新预览。
