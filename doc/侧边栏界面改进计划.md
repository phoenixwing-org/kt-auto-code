# Side Bar 界面改进计划

> **历史方案说明（2026-07-15）：** 本文记录早期“四个原生 View + 编辑区 Workbench”规划，不再作为当前实现依据。当前采用“最小 Ribbon + 单显示、多打开的 Module Block”，权威交互规范见 [UI 开发规则](./前端开发规则.md)，当前实施进度见 [0.4.0 Block 工作流改造计划](./0.4.0-Block工作流改造计划.md)。

> 目标：将现有 Side Bar 改造成四个相对独立、风格统一的功能入口，并通过共享 Ignore Service 复用忽略规则。
> 前端边界遵循[前端开发规则](./前端开发规则.md)，总体插件架构见[VS Code 插件规划](./vscode插件规划.md)。

## 当前简单版（2026-07-11）

已先完成不破坏现有界面的最小版本：

- 现有 Side Bar 增加 Ignore 设置和搜索替换两个正式工具 Tab。
- 四个工具使用统一风格 SVG 身份图标。
- 工具切换器已提供大图标迷你 Ribbon，并可通过 `ktAutoCode.sidebar.toolPickerStyle` 切换为紧凑 Tab。
- 搜索替换在 Side Bar 配置主要条件，当前编辑分栏的 `WebviewPanel` 提供完整预览、写盘状态和结果表格。
- 头文件 ASCII 预检同样在当前编辑分栏打开结果 View，Side Bar 不重复渲染明细。
- Ignore 设置是唯一规则管理入口；解析结果由 Extension Host 按文件修改状态缓存，其他工具共用。
- 改名核心位于根 `src/`，插件层只负责工作目录、Ignore、确认框和 View。
- 头文件编码修正、文件转码与原 Ignore 行为保持兼容。

本计划后续的 Vue 迁移、原生四 Block、共享状态和 Workbench 壳仍为增量升级，不是简单版完成条件。

## 1. 功能范围

Side Bar 首期固定四个功能：

| Feature ID | 界面名称 | 主要职责 | 现有实现 |
| --- | --- | --- | --- |
| `headerAscii` | 头文件编码修正 | 扫描并清理头文件中的弯引号、NBSP、全角标点、BOM 和非 ASCII 内容 | `tools/headerAscii/` |
| `encodingFix` | 文件转码 | 检测整文件编码，执行 GBK / UTF-8 BOM / UTF-16 → UTF-8 无 BOM | `tools/encodingFix/` |
| `ignoreSettings` | 忽略设置 | 查看、打开、同步和刷新 `.phoenix/.ignore`，向其他功能提供规则 | 目前散落在 `ignoreConfig.ts` 和 `SidebarViewProvider` |
| `codeRename` | 搜索替换 | 文本、文件名、文件夹名三级预览与替换 | `tools/codeRename/` + `workbench/codeRenamePanel.ts` |

内部 ID 保持兼容，界面名称可以更清楚：原“编码修正”改为“文件转码”，避免与“头文件编码修正”混淆。

## 2. Side Bar 信息架构

采用同一 Activity Bar 容器下的四个 VS Code 原生可伸缩 View：

```text
┌─ KT Auto Code ─────────────────────────────┐
│ ▼ 工具                              [↻] […]│
│   [头文件修正] [文件转码] [忽略设置]        │  ← SVG 图标 Tab
│   当前功能主操作                            │
├────────────────────────────────────────────┤
│ ▼ 属性                                  […]│
│   当前功能的选项、范围或 Ignore 状态         │
├────────────────────────────────────────────┤
│ ▼ 结果                               12  […]│
│   当前功能的文件、问题或 Ignore 规则树        │
├────────────────────────────────────────────┤
│ ▶ 任务与日志                          1  […]│
└────────────────────────────────────────────┘
```

### 2.1 工具 Block

第一块使用 Vue `WebviewView`，顶部为四个等宽或可换行的图标 Tab：

- 头文件编码修正：`预检`、`修正`、`打开工作台`。
- 文件转码：`预检`、`转换`、`打开工作台`。
- 忽略设置：`打开规则`、`从 .gitignore 同步`、`刷新`。
- 搜索替换：Side Bar 放搜索值、替换值、三级范围、工作目录、Ignore 和预览/替换按钮；工作目录默认空，右侧文件夹按钮可选择任意本地目录，输入框下拉先显示当前工作区相对目录，再显示全局外部目录；编辑区 Workbench 只展示详细结果。

Tab 只负责切换 `activeFeatureId`。操作按钮来自 Feature manifest，不在 Vue 组件中按 ID 写 `if/else`。

### 2.2 属性 Block

第二块使用同一份 Side Bar Vue bundle，根据当前 Feature 渲染属性 Schema：

| 功能 | 属性 |
| --- | --- |
| 头文件编码修正 | 头文件/源文件范围、保留 GBK 中文、去除 BOM、显示详细 |
| 文件转码 | 头文件/源文件/Markdown 范围、目标 UTF-8 无 BOM、显示详细 |
| 忽略设置 | 规则文件路径、规则数量、`.gitignore` 是否存在、同步状态 |

属性值由 Controller 读取和更新；Vue 组件不直接访问 VS Code 配置或文件系统。

### 2.3 结果 Block

第三块优先使用原生 `TreeView`，根据当前 Feature 切换数据模型：

- 头文件编码修正：文件 → 字节问题 → 行列位置。
- 文件转码：状态分组 → 文件 → 检测编码和建议操作。
- 忽略设置：规则来源 → 规则列表；提供复制、定位和禁用提示。

扫描结果较多或需要批量选择时，通过“查看全部”打开右侧 Workbench，不在窄 Side Bar 中堆复杂表格。

### 2.4 任务与日志 Block

第四块使用原生 `TreeView`：显示运行中任务、最近完成任务、进度、取消和 Output Channel 入口。它订阅统一任务状态，不绑定某个 Feature。

## 3. SVG 图标计划

新增工具身份图标：

| 文件 | 含义 | 造型建议 |
| --- | --- | --- |
| `media/tools/header-ascii.svg` | 头文件编码修正 | 文件轮廓 + `A` + 小型修正标记 |
| `media/tools/encoding-convert.svg` | 文件转码 | 文件轮廓 + 双向/循环转换箭头 |
| `media/tools/ignore-settings.svg` | 忽略设置 | 规则列表或漏斗 + 斜线/隐藏标记 |
| `media/tools/code-rename.svg` | 搜索替换 | 文件或符号 + 双向替换箭头 |

图标规则：

- 使用统一的 `20 × 20` viewBox、圆角线帽和一致描边粗细，不使用渐变、阴影或文字说明。
- Webview 内图标使用 `currentColor`，未选中跟随 `--vscode-descriptionForeground`，选中跟随 `--vscode-focusBorder` 或按钮前景色。
- Activity Bar 继续使用独立的 `24 × 24` 单色品牌 SVG。
- View Title 和 Tree Item 的常见操作优先使用 codicon；自定义 SVG 只表达四个 Feature 身份，避免图标资产泛滥。
- 每个图标按钮必须有 tooltip、`aria-label` 和清晰的选中状态；不能只靠颜色区分。

资产目录：

```text
extension/media/
├── kt-auto-code.svg
└── tools/
    ├── header-ascii.svg
    ├── encoding-convert.svg
    ├── ignore-settings.svg
    └── code-rename.svg
```

## 4. MVC 与模块边界

### 4.1 Feature 合约

四个功能实现同一份声明式合约：

```typescript
interface SidebarFeature {
  id: "headerAscii" | "encodingFix" | "ignoreSettings" | "codeRename";
  title: string;
  shortTitle: string;
  iconPath: string;
  actions: readonly FeatureAction[];
  getProperties(context: FeatureContext): Promise<PropertyViewModel>;
  getResults(context: FeatureContext): Promise<ResultTreeModel>;
  handleAction(actionId: string, context: FeatureContext): Promise<void>;
}
```

注册表只认识 `SidebarFeature`。增加新功能时注册一个模块，不修改 Tools View、Properties View 或 Results Tree 的通用渲染逻辑。

### 4.2 分层职责

| 层 | 职责 | 禁止事项 |
| --- | --- | --- |
| Model | 核心扫描/转码、Feature 状态、Ignore 规则与配置快照 | 不依赖 Vue、DOM 或 `vscode` |
| Controller | Feature 切换、消息校验、命令编排、确认框、状态广播 | 不生成 HTML，不实现编码算法 |
| View | Tab、属性和结果展示，发送语义化 action | 不读文件、不调用扫描函数、不按 Feature ID 写业务分支 |

### 4.3 建议目录

```text
extension/src/
├── features/
│   ├── headerAscii/
│   │   ├── manifest.ts
│   │   ├── controller.ts
│   │   └── viewModel.ts
│   ├── encodingFix/
│   │   ├── manifest.ts
│   │   ├── controller.ts
│   │   └── viewModel.ts
│   └── ignoreSettings/
│       ├── manifest.ts
│       ├── controller.ts
│       └── viewModel.ts
├── ignore/
│   ├── ignoreRepository.ts
│   ├── ignoreService.ts
│   └── types.ts
├── sidebar/
│   ├── featureRegistry.ts
│   ├── sidebarController.ts
│   ├── toolsViewProvider.ts
│   ├── propertiesViewProvider.ts
│   ├── resultsTreeProvider.ts
│   └── tasksTreeProvider.ts
└── models/
    └── toolStateStore.ts
```

现有根目录 `src/dotIgnore.ts` 已同时包含规则匹配和 Node 文件读写。迁移时保留其 CLI 可复用能力，并把工作区解析、文件监听、VS Code 文档打开等宿主行为封装进 Extension 层的 `IgnoreRepository`；`IgnoreService` 在其上提供统一用例 API。后续若继续拆分，优先把规则解析/匹配提成无 I/O 的纯模块。

## 5. Ignore Service 共享设计

忽略设置是独立 Feature，但 Ignore 能力是共享服务：

```text
headerAscii Controller ─┐
                       ├── IgnoreRuleProvider ── IgnoreService ── .phoenix/.ignore
encodingFix Controller ─┘

ignoreSettings Controller ── IgnoreService（查看、打开、同步、刷新）
```

建议接口：

```typescript
interface IgnoreRuleProvider {
  getPatterns(workspaceRoot: string): readonly string[];
  getSnapshot(workspaceRoot: string): IgnoreSnapshot;
  onDidChange(listener: (snapshot: IgnoreSnapshot) => void): () => void;
}

interface IgnoreSettingsService extends IgnoreRuleProvider {
  ensure(workspaceRoot: string): Promise<IgnoreSnapshot>;
  open(workspaceRoot: string): Promise<void>;
  syncFromGit(workspaceRoot: string): Promise<IgnoreSnapshot>;
  refresh(workspaceRoot: string): Promise<IgnoreSnapshot>;
}
```

约束：

- `headerAscii` 和 `encodingFix` 只依赖只读 `IgnoreRuleProvider`，不能调用同步或打开文件。
- `ignoreSettings` 依赖完整 `IgnoreSettingsService`，但不调用扫描或转码。
- `.phoenix/.ignore` 变化后 Service 发布事件，四个 Feature 的属性与结果 ViewModel 同步刷新。
- 扫描启动时固定一份 Ignore snapshot，任务运行中规则变化不改变本次扫描，下一次任务再使用新规则。
- “从 .gitignore 同步”覆盖文件前必须显示确认和规则数量变化摘要。

## 5.1 VS Code 工作目录边界

插件运行时不迁移 `phoenix-desk-tools` 的完整工作区管理体系：

- 搜索替换的工作目录留空时来自 `vscode.workspace.workspaceFolders[0].uri.fsPath`。
- 搜索替换提供轻量目录输入、文件夹选择和本机最近目录，但不引入服务端 workspace prefs、workset 或完整工作区切换器。
- 工作区外绝对目录作为独立扫描根；没有打开工作区时仍可选择绝对目录运行。
- 内部最近目录写 `workspaceState` 相对路径，外部最近目录写 `globalState` 绝对路径；两组分别最近优先、限制数量且不参与 Settings Sync。
- 多根工作区若以后需要，只使用 VS Code 的 `WorkspaceFolder` context，不新增一套 Phoenix 业务 workspace。

开发期通过 `pnpm-workspace.yaml` 链接同级 `phoenix-wing` 仅属于依赖管理，不参与上述运行时目录选择。

## 6. 状态与消息

Extension Host 保存：

- `activeFeatureId`
- 四个 Feature 各自的配置和最近结果
- 当前 Ignore snapshot
- 任务状态和 Workbench Panel 状态

View 只保存 Tab 焦点、展开、滚动等临时 UI 状态。消息使用统一信封：

```typescript
type FeatureMessage = {
  sourceView: "tools" | "properties";
  featureId: SidebarFeature["id"];
  action: string;
  requestId: string;
  payload?: unknown;
};
```

Controller 必须校验 `sourceView`、`featureId`、action 和 payload；执行后通过统一 State Store 广播新的 ViewModel。

## 8. 验收标准

1. 四个 Feature 可独立注册、测试和执行；停用或取消注册任一 Feature 不需要修改通用 View。
2. 两个扫描 Feature 共用 Ignore 规则，但不依赖 Ignore 设置界面。
3. Ignore 文件变化可刷新属性和结果；运行中的扫描使用启动时 snapshot。
4. Tools/Properties/Results/Tasks 可独立折叠和调整高度，交互符合 VS Code 原生 Side Bar。
5. 四个 SVG 图标风格一致，在深色、浅色和高对比度主题中清晰。
6. Vue 组件无文件系统和扫描逻辑，Controller 无 HTML，Model 无 VS Code/DOM 依赖。
7. Side Bar 与右侧 Workbench 状态一致，关闭重开不丢失 Host 中结果。
8. CLI 行为和核心编码算法在界面重构前后保持一致。
