# 0.3.0 Extension Host 人工验收清单

> 自动门禁已覆盖 TypeScript、打包、manifest 和纯 core。此清单只覆盖必须由图形化 VS Code 验证的原生 View、QuickPick 与 Git 命令交互。请使用临时工作区或干净的测试分支，不在真实工程直接点击写盘。

## 启动

1. 在本仓库执行 `pnpm ext:build`。
2. 按 F5，或执行 `pnpm ext:launch`，确认窗口标题含 `[Extension Development Host]`。
3. 在 Host 中打开一个临时文件夹，并放入：
   - 至少两个可排序的 `.cpp/.h`；
   - `uuid.txt`，含两个相同 UUID 和一个不同 UUID；
   - 空白或最小 `.CATDlg` 文件（CAA P0 只定位文件，不解析内容）。

## C++ 成员排序

- Side Bar 选择“排序”→“扫描并打开结果”；确认 Primary Sidebar 内保留原 `KT Auto Code` 工具面板，并在其下方展开 `成员排序` 原生结果 View；不新建 Webview/untitled 标签或底部 Panel。
- 默认只有“变更文件”分组；点击 `$(filter)` 后才显示“无变更文件”。文件名按大小写不敏感的 basename + 相对路径排序。
- 取消一个待写盘复选框→“应用所选”，确认未勾选文件未写盘，且写盘后不会逐个弹 Git Diff。
- 已写盘行出现 `$(compare-changes)` 与 `$(discard)`；前者只打开该文件的 VS Code Git Diff，后者只在文件仍等于本会话输出时恢复原字节。
- 手工改动已写盘文件后点还原，确认显示“文件已被修改，未执行还原”，不会覆盖外部改动。

## UUID 替换

- Side Bar 选择“UUID”→“扫描 UUID”；确认 Primary Sidebar 内的 `KT Auto Code / UUID 替换` 原生结果 View 出现，侧栏工具页不重复列出文件。
- 一个 UUID 映射是一级分组，子项显示文件、行列、原 token 与格式保持后的新 token。取消一个子项或整个映射组后，确认未勾选项不写盘。
- 点击 `$(check)` 应用所选；确认同一旧 UUID 的所有出现均替换为同一个新 UUID，写盘后仅对应命中状态变为“已写盘”，不会重扫或自动打开多个 Diff。
- 已写盘行的 `$(compare-changes)` 只打开该文件的 VS Code Git Diff；对包含 nested / flat brace / flat run CAA GUID 的文件，三种 CAA 格式、大小写和紧凑 GUID32 必须保持。
- 重扫前后映射不跨会话复用；修改文件后再应用，写前指纹检查必须拒绝写盘。
- 可额外用含 GBK 中文注释、UUID 为 ASCII 的 `.cpp` 验证文件仍保持 GBK。

## CAA 对话框 / 外部编辑器 / Desk Tools 交接

- Side Bar 选择“CAA”→“扫描 CATDlg”；确认只定位 `.CATDlg`，不读取/修改其语义内容，工具页不再重复显示长文件列表。
- 确认 Primary Sidebar 内 `KT Auto Code / CAA 对话框` 使用文件优先的一行列表：文件名在前、目录弱化；右侧只有打开 VS Code 文件和 `$(link-external)` 两个图标。
- 点击“CAA 设置”，确认打开 VS Code 原生 Settings，并能设置 `ktAutoCode.caa.externalEditor.command` 与 `args`。例如 macOS 可设 `command: open`、`args: ["-a", "你的编辑器名", "${file}"]`；Windows 可设编辑器 `.exe` 和 `["${file}"]`。
- 未配置 command 时点击外部编辑器图标必须打开设置并报告错误；配置后仅在这次用户点击时启动外部程序，插件不使用 shell，也不修改 `.CATDlg/.CATNls`。
- `Kt Auto Code › Environment` 内四个全局工程环境工作区覆盖值是 `ROOT_DIR`、`ROOT_DIR_3rdParty`、`ROOT_DIR_CORE`、`CAA_MK_VERSION`；留空时读取继承的系统环境，`CAA_MK_VERSION` 都未设定时提示建议值 `19`。
- `ktAutoCode.caaDialog.getHandoff` 仍保留 v1 兼容：外部打开的最近一个文件可作为单文件交接；它只返回 `workspaceUri`、文件 URI 和相对路径。
