### 1.1 搜索替换规则的缓存决策

不把搜索词和替换词默认写入机器级全局缓存。它们往往包含工作区命名、客户缩写或尚未公开的重构意图；全局缓存会混入不同项目，也不利于团队复用和清理。

采用三层状态，职责明确：

| 层级 | 位置 | 内容 | 写入时机 |
| --- | --- | --- | --- |
| 临时草稿 | Webview state | 当前输入、展开状态、未保存关联行 | 实时；关闭 View 可丢失 |
| 工作区规则档案 | `<workspace>/.phoenix/search-replace.json` | 用户命名的母规则、前缀、关联规则和选项 | 用户点击“保存规则档案”时 |
| 内部最近目录 | VS Code `workspaceState` | 当前工作区内最近 12 个相对路径 | 选择目录或实际运行时更新，不参与 Settings Sync |
| 外部最近目录 | VS Code `globalState` | 工作区外最近 12 个绝对路径 | 选择目录或实际运行时更新，不参与 Settings Sync |

- `.phoenix/search-replace.json` 是可读的项目配置，不是隐式缓存；是否提交 Git 由用户和项目决定。
- 不在每次输入、预览或替换后自动落盘；预览始终使用临时草稿的规则快照。
- Side Bar 提供 `规则档案 ▾` 下拉，用于“填入当前工作区已保存规则”；另提供明确的“保存规则档案”。
- [x] 内部最近目录只在当前工作区显示，外部最近目录跨工作区显示；两者都不自动填入搜索词、替换词或关联规则。

## 3. Ignore 预设与编辑流程

### 3.1 产品交互

Ignore Tab 保持紧凑，增加预设类型和两个语义化操作：

```text
忽略设置
工作区：Example
.phoenix/.ignore · 20 条

预设：[ CAA v ]    [追加] [去除]
       C++
       Web

[编辑规则] [从 .gitignore 追加]
```

- `追加`：将选中预设的规则块合并到已打开文档。
- `去除`：仅删除该预设的受管规则块，不删除用户自定义行。
- `从 .gitignore 追加`：合并到文档缓冲区，不覆盖整个 `.phoenix/.ignore`。
- 所有操作完成后文档保持 dirty，保存/放弃交由 VS Code 原生流程处理。

## 4. 关联规则搜索替换

### 4.0 名称与模型决策

用户界面将“多规则”改称为 **关联规则**。

- “多规则”只说明数量，无法表达它们来自同一个命名迁移意图。
- “关联规则”表示每一行由母规则或另一行经过前缀、中间词缀、空格化、大小写等变形而来。
- 引擎仍接收扁平的有序规则快照；关联关系用于生成、解释、重新生成和 UI 管理，不改变底层匹配算法。


### 4.2 动态命名派生

关联规则不应固定围绕 `AutoCode`。当前单行“搜索 → 替换”是**母规则**，用户点击展开时，系统根据已输入的两个词动态分析并生成可编辑规则。

例如母规则为：

```text
CaaStudy → TomBuild
```

先按 PascalCase/缩写边界拆分：

```text
源词段：[Caa, Study]
目标词段：[Tom, Build]
```

基础派生：

| 类型 | 搜索 | 替换 |
| --- | --- | --- |
| 母规则 | `CaaStudy` | `TomBuild` |
| 空格形式 | `Caa Study` | `Tom Build` |
| 全大写（勾选保持大小写） | `CAASTUDY` | `TOMBUILD` |
| 全大写空格形式 | `CAA STUDY` | `TOM BUILD` |

- [x] 实现 PascalCase、连续大写缩写、数字边界和空格词段解析。
- [x] 基于当前母规则生成空格和通用前缀关联，不写死 `AutoCode`。
- [x] 重新生成只替换 `source: generated` 行，不覆盖用户自定义行。
- [x] 每条派生规则记录 `source = generated | user`，用户修改后转为 `user`。

#### 关联规则数据模型

```typescript
type RelationKind =
  | "root"
  | "spaced"
  | "uppercase"
  | "prefix"
  | "caa-i"
  | "caa-e"
  | "caa-i-full"
  | "caa-e-full"
  | "custom";

interface AssociatedReplacementRule {
  id: string;
  parentId?: string;
  relationKind: RelationKind;
  relationArgs?: {
    prefix?: string;
    infix?: string;
  };
  search: string;
  replace: string;
  enabled: boolean;
  source: "generated" | "user";
  order: number;
}
```

- `parentId` 表示该行由哪一行派生，用于解释和重新生成。
- `relationKind` 表示变形类型，底层执行前仍展平成有序 `search/replace` 列表。
- 用户手工修改搜索或替换后，`source` 改为 `user`；之后父规则改变不自动覆盖该行。
- 删除父规则时，如果存在子规则，先询问“一并删除”或“转为自定义规则”。

#### 通用名称前缀

展开区增加源、目标两个可编辑前缀文本框：

```text
源前缀：[ KTC ] → 目标前缀：[ KTM ]
```

- 前缀是通用原始文本，不绑定 CAA，也不自动改变大小写或分隔符。
- 源前缀不输入：只生成母规则、空格形式和大小写变体，不添加前缀。
- 源、目标前缀分别表示“从什么前缀改成什么前缀”；例如 `KTC → KTM`。
- 目标前缀可与源前缀相同，也可为空以表达去除前缀。
- CAA 的 `I/E` 是独立的专用关联类型，只在用户选择 CAA 关系时出现。
- 修改前缀后只提示重新生成，不覆盖已转为 `source: "user"` 的关联行。

普通前缀派生：

```text
KTCCaaStudy → KTMTomBuild
```

### 4.4 `保持大小写` 语义

首版采用可预测的派生，不猜测任意混合大小写：

1. 总是使用用户显式填写的规则。
2. 勾选后，为每条规则派生 `search.toUpperCase() → replace.toUpperCase()`。
3. 若派生搜索值与显式搜索值相同，只保留一条。
4. 首版不自动派生 camelCase、lowercase 或任意混合形式。

复选框不代表普通的 case-insensitive 模糊匹配；引擎仍对显式规则和派生规则做精确匹配。

### 4.5 匹配与冲突语义

- 所有规则基于同一份原始字节/名称计算，替换结果不再进入后续规则。
- 同一起点多条命中时，选择搜索字节更长的规则。
- 长度相同时，使用界面中更靠前的规则。
- 命中区间已被接受后，忽略与该区间重叠的其他命中。
- 文件夹、文件名和文本共用同一规则集和竞争策略。
- 当同时勾选多个级别时，执行流水线固定为：**文件夹 → 文件名 → 文本**。文件夹从最深层开始改名；每个阶段之后重新收集工作区条目；文本阶段最后逐文件读取，并在同一份原始字节上应用全部启用关联规则。
- 父子目录同时改名时，Model 将中间路径重基到最终目标路径；结果 View 打开写盘后的实际目录，不打开已失效的中间地址。
- “工作目录”初始为空；留空、`.` 或 `/` 时解析为当前 VS Code 工作区根目录。根目录本身不是可改名对象，只扫描其内部文件/文件夹。
- 工作区内相对路径或绝对路径继续作为 scope；指定内部非根目录时，该目录本身属于扫描条目，可以作为文件夹改名。
- 工作区外绝对目录作为独立扫描根，可在未打开工作区时运行；只处理其内部条目，不自动改名该根目录。
- 外部扫描根读取自身已有 `.phoenix/.ignore`，不复用当前工作区的未保存 Ignore snapshot，也不因预览创建配置。
- 工作目录必须存在且必须是目录；工作区内 scope 经过符号链接时在预览前拒绝执行。
- [x] 输入框使用分层最近目录下拉，右侧文件夹 SVG 按钮调用 VS Code 目录选择器；内部相对路径存 `workspaceState`，外部绝对路径存 `globalState`，各自去重并按使用时间倒序排列。
- [x] 目录名勾选且根目录命中时，Primary 面板提示“建议改为的新根目录名”；只提示，用户自行在外部改名并重新打开工作区。
- [x] 用户可从该提示显式创建根目录 `KT-AUTO-CODE-TODO.md`；内容说明手动改名步骤，已有同名文件只打开不覆盖。

### 4.6 编码语义

- ASCII / UTF-8 / UTF-8 BOM：为所有启用规则生成 UTF-8 字节。
- GBK：首版仍只允许 ASCII 搜索值和替换值。
- UTF-16 / UTF-32 / unknown：列为跳过，不写盘。
- BOM、换行和未命中字节必须原样保留。
- 文本替换前后 `DetectedEncoding` 必须一致；不得因替换把 UTF-8 BOM 变为 UTF-8、把 GBK 转为 UTF-8，或反向改变编码。

界面文案约定：

- 转码操作写为 **`GBK → UTF-8`**。
- 界面中 **`UTF-8` / `utf-8` 默认表示 UTF-8 无 BOM**，不重复显示“无 BOM”。
- 只有当文件实际含 BOM 或操作与 BOM 有关时，才明确写 **`UTF-8 BOM`**。
- 内部类型和测试仍可使用 `utf8-bom` / `UTF-8 no BOM` 等精确名称，不影响用户界面简写。
