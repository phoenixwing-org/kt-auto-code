# 0.4.0 Block 工作流改造计划

> 2026-07-15 方案校正：不再把操作界面与结果拆成两个 Block。“编码修正”验证多控件操作区，“C++ 成员排序”验证缓存、勾选、Diff、写盘和还原的完整结果工作流。点检见 [编码试点](0.4.0-单Block编码试点点检.md)与[成员排序试点](0.4.0-单Block成员排序点检.md)；两者通过前不继续推广。
> 通用 Ribbon、Block、范围、结果、Diff 和状态规则统一见 [UI 开发规则](前端开发规则.md)；本计划不再复制维护规则正文。

逐项证据和剩余人工门槛见 [0.4.0 单 Block 完成审计](0.4.0-单Block完成审计.md)。

## 目标

将 KT Auto Code 的日常工作收敛为同一种路径：

1. Ribbon 仅用作模块入口和全局命令。
2. Ribbon 点击后在其正下方展开一个模块 Block；预览、应用与配置仍由 Block 内按钮触发。
3. 原操作界面位于 Block 上部，缓存结果位于同一 Block 下部；执行任务只刷新内部状态，不得再创建第二个结果 Block。
4. 文件打开、预览 Diff、已写盘 Diff 继续使用 VS Code 原生编辑器和 Git。
5. 不在扩展内维护第二套文件预览或 Diff UI。

## VS Code 视图约束与选择

VS Code 内建 Search/Git 能在同一视图内组合输入框、命令、分组和文件结果，但普通扩展无法调用全部内部工作台组件。公开 API 中，原生 `TreeView` 能提供分组、checkbox、文件图标和行内图标，却不能嵌入搜索替换所需的输入框、下拉框和规则编辑器。

0.4.0 试点使用一个 `WebviewView` 承载完整模块 Block：复用原操作界面，并在其下方渲染 Git/Search 风格结果。后端扫描、缓存、Diff、写盘和还原逻辑保持不变；不复制算法，也不在 Webview 中自行实现 Diff。

因此统一交互为：

- Ribbon：只选择并展开模块，不直接扫描或预览；自身保持最小高度。
- 模块 Block 上部：承载原来的选项、规则和预览/执行按钮，可用标题 `×` 关闭。
- 模块 Block 下部：承载状态、结果计数、分组、checkbox、文件行和行内图标。
- 扫描后保持当前 Block；只替换内部结果缓存，不自动打开 Diff，也不弹出另一视图。
- 默认使用排他展开：Ribbon 始终保留，最近使用的模块 Block 获得主要空间；切回时缓存不丢失。
- 排他显示采用“单显示、多打开”：当前按钮使用活动高亮，后台已打开按钮使用次级强调色；关闭当前 Block 后按最近使用顺序恢复上一个，最后一个关闭后才收起模块区。

## 模块映射

| 模块 | 同一 Block 上部 | 同一 Block 下部 |
| --- | --- | --- |
| 头文件 ASCII 修正 | 原 ASCII/GBK/BOM 选项、预检与修复按钮 | 问题文件 |
| 编码修正 | 原范围/详情选项、预检与转换按钮 | 编码异常文件 |
| C++ 成员排序 | 扫描、应用、过滤；预留排序规则选项 | 待写盘/无变更/已写盘 |
| UUID 替换 | 原扫描、策略选择和应用入口 | 待写盘/已写盘 |
| CAA 对话框 | 原扫描与环境设置入口 | `.CATDlg` 文件 |
| 搜索替换 | 原完整规则表单、工作目录、预览与替换按钮 | 预览/已替换文件 |
| Ignore | 原规则、预设、同步与分析界面 | 推荐分组 |
| 工程环境 | 刷新、打开系统环境变量和插件设置 | 四个变量的当前值、路径状态、新建/修改/清除与路径选择 |

## 验收标准

- 点击 Ribbon 只在正下方打开一个模块 Block，不产生扫描结果；只有 Block 内按钮才执行任务。
- Ribbon 保持最小高度；模块操作区与结果列表不得分裂成两个 Block。
- 扫描、重新扫描和执行修改均更新同一份缓存列表；运行过程中旧结果不闪退。
- 写盘后仍可在原 Block 看到状态，并通过 VS Code 原生 Git Diff 查看变更。
- 高级配置只有一个权威入口，结果不重复显示。
- 模块 Block 切换时保持现有缓存和 Accordion 行为。
- 工作集非法或越界时停止运行，不得静默退回整个工作区；`.phoenix/` 始终是源文件扫描硬排除目录。
- UUID 默认保持“同值同替换”，只有用户在扫描前明确选择时才使用逐命中新值。
- 0.4.0 完成前不执行 Marketplace 发布。
