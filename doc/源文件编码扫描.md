# 源文件编码扫描与修复

消除 MSVC **C4819**（「该文件包含不能在当前代码页(936)中表示的字符」）等告警。

常见原因：达索 CAA 头文件注释里从 Word 粘贴的 **Windows-1252 弯引号**（字节 `0x93` / `0x94`），在中文 Windows（CP936）下无法正确表示。

## 安装

```bash
cd kt-auto-code
pnpm install
```

## 命令

| 命令 | 说明 |
| --- | --- |
| `pnpm scan-encoding --headers` | **仅扫描头文件** |
| `pnpm scan-encoding --headers --ascii` | 头文件预检（含 GBK 中文、BOM） |
| `pnpm fix-encoding` | 扫描并修复全部源文件（默认保留 GBK） |
| `pnpm fix-headers` | 头文件修复（纯 ASCII + 可选去 BOM，见插件选项） |

也可指定工程根目录（路径放最后）：

```bash
pnpm scan-encoding --headers D:\path\to\caa\project
pnpm fix-headers D:\path\to\caa\project
```

## 典型工作流

在 CAA 工程根目录执行（或在插件目录用绝对路径）：

```bash
# 1. 先扫描，看哪些头文件有问题
pnpm scan-encoding --headers D:\path\to\MyCaaModule

# 2. 确认无误后修复
pnpm fix-headers D:\path\to\MyCaaModule
```

输出示例：

```text
...\MultiCharSample.h: 4 处问题
  L18:C33 offset=414 invalid_gbk byte=0x94 → 建议 '"'
    字节 0x94 为 Windows-1252 西欧标点（弯引号/破折号等），在 CP936 下会触发 MSVC C4819
     *        add_sample(GlobalUndo,”MyStep”);
```

修复会把 `0x94` 映射为 ASCII `"`。头文件专用命令 `fix-headers`（及 VS Code 插件）还会将 GBK 中文替换为空格，使头文件保持纯 ASCII；**全角标点**（如 `：` `，`）会映射为对应 ASCII（`:` `,`），而非空格。通用 `fix-encoding` 仍保留合法 GBK 中文。

## 字符修正映射表（在哪里）

**源码是权威**；本节为可读摘要，改映射时请同步改代码并更新本文档。

| 类别 | 源码位置 | 说明 |
| --- | --- | --- |
| **Windows-1252 弯引号等** | [`src/sourceEncodingScan.ts`](../src/sourceEncodingScan.ts) 内 `CP1252_TO_ASCII` | 字节 `0x80–0x9F` 区段，CAA 注释从 Word 粘贴最常见 |
| **NBSP 不换行空格** | 同上，`isNbspBeforeAscii`（`0xA0`） | 后跟 ASCII 时视为 NBSP → 空格 |
| **全角 / 中文标点** | [`src/fullwidthPunct.ts`](../src/fullwidthPunct.ts) | `FULL_WIDTH_TO_ASCII`（Unicode）、`GBK_PAIR_TO_ASCII`（双字节） |
| **GBK 中文** | `sanitizeSourceForGbk` 的 `preserveGbk` | 头文件修复默认 **不保留** → 替换为空格（无逐字映射表） |
| **插件预检展示名** | [`extension/src/tools/headerAscii/formatIssue.ts`](../extension/src/tools/headerAscii/formatIssue.ts) 内 `BYTE_NAMES` | 仅 UI 文案，不参与修复逻辑 |

### Windows-1252 → ASCII（`CP1252_TO_ASCII`）

在 ASCII 源文件里，单字节 `0x80–0x9F` 若后跟 ASCII 可打印字符，按 CP1252 误粘贴处理并映射：

| 字节 | CP1252 含义 | 修正为 | 字节 | CP1252 含义 | 修正为 |
| --- | --- | --- | --- | --- | --- |
| `0x82` | ‚ | `,` | `0x91` | ‘ | `'` |
| `0x84` | „ | `,,` | `0x92` | ’ | `'` |
| `0x85` | … | `...` | `0x93` | “ | `"` |
| `0x86` | † | `+` | `0x94` | ” | `"` |
| `0x87` | ‡ | `++` | `0x95` | • | `*` |
| `0x88` | ˆ | `^` | `0x96` | – | `-` |
| `0x89` | ‰ | `%` | `0x97` | — | `-` |
| `0x8A` | Š | `S` | `0x98` | ˜ | `~` |
| `0x8B` | ‹ | `<` | `0x99` | ™ | `(TM)` |
| `0x8C` | Œ | `OE` | `0x9A` | š | `s` |
| `0x8E` | Ž | `Z` | `0x9B` | › | `>` |
| `0x9C` | œ | `oe` | `0x9E` | ž | `z` |
| `0x80` | € | `EUR` | `0x9F` | Ÿ | `Y` |
| `0x83` | ƒ | `f` | | | |

**最常见**（C4819 样例）：`0x93` / `0x94` → `"`，`0x91` / `0x92` → `'`，`0x96` / `0x97` → `-`。

### 特殊单字节

| 字节 | 含义 | 修正为 |
| --- | --- | --- |
| `0xA0` | NBSP（Word/PDF 粘贴，外观像空格） | 空格 `0x20` |

### 全角标点 → ASCII

常见于注释从 Word、输入法粘贴。扫描会报告 `fullwidth_punct`，修复时替换为 ASCII：

| 全角 | ASCII | GBK 字节 | UTF-8 字节 |
| --- | --- | --- | --- |
| `：` | `:` | `A3 BA` | `EF BC 9A` |
| `，` | `,` | `A3 AC` | `EF BC 8C` |
| `；` | `;` | `A3 BB` | `EF BC 9B` |
| `？` | `?` | `A3 BF` | `EF BC 9F` |
| `！` | `!` | `A3 A1` | `EF BC 81` |
| `（` `）` | `(` `)` | `A3 A8` / `A3 A9` | `EF BC 88` / `EF BC 89` |
| `．` `。` | `.` | `A3 AE` / `A1 A3` | `EF BC 8E` / `E3 80 82` |
| `＝` `－` | `=` `-` | `A3 BD` / `A3 AD` | … |
| `＜` `＞` | `<` `>` | `A3 BC` / `A3 BE` | … |
| `＂` `＇` | `"` `'` | `A3 A2` / `A3 A7` | … |
| `＃` `％` `＆` `＋` | `#` `%` `&` `+` | `A3 A3` … | … |
| `＠` `／` `＼` `～` | `@` `/` `\` `~` | `A3 A0` … | … |
| `［` `］` `｛` `｝` | `[` `]` `{` `}` | `A3 DB` … | … |
| 弯引号 `"` `"` `'` `'` | `"` `"` `'` `'` | — | `E2 80 9C` 等（见 `FULL_WIDTH_TO_ASCII`） |
| `ε` `Ε` | `e` `E` | `CE B5` / `CE D5` | `CE B5`（U+03B5）/ `CE 95`（U+0395） |

**完整列表**以 [`src/fullwidthPunct.ts`](../src/fullwidthPunct.ts) 为准。

## 扫描范围

**包含扩展名**

- 头文件：`.h` `.hh` `.hpp` `.hxx` `.inl`
- 源文件：`.c` `.cc` `.cpp` `.cxx` `.m` `.mm`
- CAA：`.catdlg` `.catnls` `.catrsc`

**自动跳过目录**

`.git`、`node_modules`、`build` / `Debug` / `Release`、`dist`、`out`、`bin`、`obj`、`.venv` 等。
