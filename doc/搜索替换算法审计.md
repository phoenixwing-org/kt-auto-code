# 搜索替换算法审计

## 目标

以旧版 Windows 工具的稳定行为为基线，保留其明确的替换顺序与编码决策；同时保留 VS Code 插件在预览、冲突阻断和多规则治理方面的改进。

## 旧版基线

旧版核心位于 `KtaAutoCodeBase/KevinFileOperate.vb`：

- 单一、区分大小写的 `source → target` 字符串替换。
- 固定顺序：**文本 → 文件名 → 文件夹名**。
- 文件文本按检测到的编码读写；若文件原先为 ASCII，写入时使用用户设置的默认 UTF-8（无 BOM）或 GBK。
- 文件与文件夹使用直接重命名，不预先汇总同名目标冲突。

## 当前插件的保留与改进

| 项目 | 当前行为 |
| --- | --- |
| 基础规则 | 精确大小写匹配；自动匹配大小写暂时灰化，不生成全大写派生规则。 |
| 执行顺序 | 文本 → 文件名 → 文件夹名，与旧版一致。 |
| 多规则 | 支持关联规则和自定义规则；同一位置最长匹配优先，同长度按规则顺序；替换结果不再次进入规则匹配。 |
| 文本写入 | 在原始字节流中替换命中片段，保留其余字节、BOM 与换行。 |
| ASCII 歧义 | 仅 ASCII 原文件且目标含非 ASCII 字符时，采用界面的默认 UTF-8 / GBK 选择。详情见[搜索替换编码规则](./搜索替换编码规则.md)。 |
| 写盘安全 | 先预览；目标已存在或多个来源映射到同一目标时整批阻断；大小写-only 改名采用临时路径。 |

## 本轮已确认的改进项

1. 将执行顺序从曾经的“文件夹 → 文件名 → 文本”恢复为旧版顺序。
2. 将自动匹配大小写改为不可用状态，避免未经充分验证的规则扩张。
3. 增加默认编码选择，并将其严格限定在 ASCII 原文件引入双字节目标的歧义场景。
4. GBK 文件中的双字节搜索和替换保持 GBK；无法无损表示为 GBK 的目标会报错，不静默替换为问号。

## 后续验证项

- 用真实 CAA / MSVC 工作区分别验证 UTF-8、UTF-8 BOM、GBK 与纯 ASCII 文件的预览和写盘结果。
- 在恢复自动匹配大小写前，补充混合大小写、缩写、I/E 名称和规则重叠的测试矩阵。
- 对超大文件和大量规则测量预览性能，必要时增加规则索引；不改变当前最长匹配语义。
- 验证 Windows 上大小写不敏感文件系统的批量改名、同名冲突和回滚路径。
