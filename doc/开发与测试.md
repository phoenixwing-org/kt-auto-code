# 开发与测试

## 环境

```bash
pnpm install
```

需要 Node.js 22 LTS、pnpm 10；Cursor / VS Code ≥ 1.85。

## 测试层级

| 层级 | 命令 | 说明 |
| --- | --- | --- |
| 单元测试 | `pnpm test` | `src/` 核心逻辑 |
| Auto 类型检查 | `pnpm ext:typecheck` | 使用 VS Code 1.85 精确类型检查 KT Auto Code |
| CLI 对照 | 见下文 | 应与插件结果一致 |
| Auto 构建 | `pnpm ext:build` | 独立构建 KT Auto Code；CAD 在并列仓库运行自己的构建 |
| 插件手工 | F5 | Side Bar、模块筛选、BOM、GBK 开关 |

样例：`tests/fixtures/multiChar/MultiCharSample.h`（第 18 行弯引号 `0x94`）。

```bash
pnpm scan-encoding --headers --ascii tests/fixtures/multiChar
pnpm fix-headers tests/fixtures/multiChar
pnpm test
```

## 插件开发（F5）

1. `pnpm ext:watch` 保持编译  
2. 本仓库按 **F5**（`Run Code + CAD Extensions`）→ 同时加载本仓和 `../kt-auto-cad`
3. Host 里点**最近工程**或 **文件 → 打开文件夹**  
4. Activity Bar → **KT Auto Code** → 预检 / 修复
5. 改代码后 Host 窗口 **Ctrl+R** 重载  

`pnpm ext:launch` 与默认 F5 配置等效，同时加载 Code 与 CAD（仅启动 Host，不传工作区目录）。只调试基础插件时使用 `pnpm ext:launch:code`。

自动跨仓宿主验收使用 `pnpm ext:test:host:cad`。它同时加载本仓 Code 与 `../kt-auto-cad`，验证 CAD 扩展发现、Shell API v2 注册、CAD 模块状态和代表命令；该命令属于集成门禁，不进入 Auto 单仓正式发布门禁。

### 两种窗口

| 窗口 | 插件 |
| --- | --- |
| 标题含 `[Extension Development Host]` | ✅ 开发版已加载 |
| 普通 VS Code | ❌ 无开发插件 |

### Launch 配置

| 配置 | 说明 |
| --- | --- |
| Run Code + CAD Extensions | 默认；同时加载基础插件与 CAD 依赖插件，共用一个 Activity Bar 入口 |
| Run Code Extension Only | 只加载基础插件，空窗 + 自选目录 |
| Run Code Extension Only (样例 multiChar) | 只加载基础插件并直接打开测试样例 |

### 扫描范围（两个工具共用）

| 选项 | 默认 | 说明 |
| --- | --- | --- |
| 头文件 | 开 | `.h` / `.hpp` … |
| 源文件 | 开 | `.cpp` / `.c` … |
| .md 文档 | 开 | **仅「编码修正」**；头文件 ASCII 工具忽略此项 |

工作区 **`.phoenix/.ignore`**（语法类似 `.gitignore`）中的路径/目录会跳过，避免全库扫描。

设置：`ktAutoCode.scope.includeHeaders`、`includeSource`、`includeMarkdown`

### 插件选项（预检前确认）

| 选项 | 默认 | 说明 |
| --- | --- | --- |
| 保留 GBK 中文 | 关 | 关 = 纯 ASCII |
| 去除 BOM / 转 UTF-8 无 BOM | 关 | 关时 UTF-16 **不做字节修复** |
| 显示详细 | 关 | 原字符 → 修正为 |

设置：`ktAutoCode.headerAscii.preserveGbk`、`ktAutoCode.headerAscii.stripBom`

### 检查清单

- [ ] `pnpm test` 全绿  
- [ ] CLI 与插件预检 `multiChar` 结果一致  
- [ ] UTF-16 头文件未勾选去 BOM 时修复不写盘  
- [ ] Output 通道 **KT Auto Code** 有报告

### 打包

```bash
pnpm ext:release-candidate
```

本仓生成 `dist/vsix/kt-auto-code-<version>.vsix` 及相邻的 `.vsix.sha256`；仓库根 `dist/` 已忽略，仅存放本地构建制品，不参与提交。`extension/dist/` 则是扩展运行所需的编译 bundle，两者职责不同。根 `pnpm package` 与 `pnpm ext:package` 等价。CAD 在 `../kt-auto-cad` 独立打包；安装时仍先安装 `kt-auto-code`，再安装声明了 `extensionDependencies` 的 `kt-auto-cad`。
