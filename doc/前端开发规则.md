# UI 开发规则

> 适用范围：KT Auto Code 的 VS Code / Cursor 插件界面。
> 本文是当前 UI 的权威规则；功能计划只记录目标和进度，不重复维护交互规范。
> 2026-07-15 起以“最小 Ribbon + 单显示、多打开的模块 Block”为基线。旧的多 View、独立结果 TreeView 和编辑区 Workbench 方案仅作历史参考。

## 1. 当前界面架构

插件只贡献两个主侧栏 Webview：

```text
KT AUTO CODE
├─ Ribbon：模块入口，始终保持最小高度
└─ Module Block：当前模块的操作、状态和结果
```

术语统一：

| 术语 | 定义 |
| --- | --- |
| Ribbon | 顶部模块入口 Webview，不承载任务结果 |
| Module Block | 下方唯一可见的模块 Webview，物理上只有一个 |
| 逻辑 Block | 某模块在 MRU 打开栈中的状态；可以当前显示，也可以后台隐藏 |
| 结果分组 | Module Block 内的待写盘、已写盘、无变更等列表分组，不是独立 Block |

- Ribbon 只负责打开、切换模块和表达打开状态，不直接扫描、预览或写盘。
- 同一时刻只显示一个 Module Block，但允许多个模块处于逻辑打开状态。
- Module Block 上部放操作界面，下部放本次会话缓存结果；不得再创建第二个结果 View。
- 文件预览、文本编辑、Diff 和 Git 变更继续使用 VS Code 原生编辑器与 SCM。
- 工程环境等全局功能可以由 View Title 按钮打开独立模块，但仍复用同一个 Module Block。

### 1.1 Codegen 数据编辑 View 例外

Codegen 的17列参数表属于结构化文档编辑，不属于扫描结果，因此允许在编辑区打开专用 Webview View：

- 左侧仍只复用一个 Module Block，负责 JSON 列表、打开、CSV 导入、刷新、活动文档摘要和 Prefix/Middle/Namespace/Append 属性。
- 一份 JSON 对应一个右侧编辑 View；重复打开同一 JSON 时复用原 View。
- 当前编辑区的 Codegen 标签激活时，必须把活动 JSON、打开状态和未保存状态同步回左侧 Block。
- View 组合文档级工具栏和独立 `KtCodegenTable`；属性由活动文档 Block 编辑，表格组件不负责文件选择、写盘和生成动作。
- 表格内部可以逐格编辑，但跨 Webview/Host 边界只发送首次 dirty 通知，并在保存或生命周期同步点交换整份草稿，禁止每个单元格都与 Host 往返。

## 2. 分层和运行时边界

### Extension Host

- 负责文件系统、扫描、转换、工作集解析、确认框、配置、缓存和 VS Code 命令。
- `ToolUiState` 及工具会话是任务状态和结果的权威来源。
- 状态更新必须广播给已解析的 Ribbon 与 Module Block；Block 重建后必须能重放快照。
- 捕获工具入口的未处理异常，并把状态从 `running` 收敛到 `error`，不得无限转圈。

### Webview

- 只负责展示、收集输入、筛选、勾选和发送语义化消息。
- 不直接读写工作区、环境变量或 VS Code 配置。
- 不实现成员排序、UUID、编码、搜索替换等领域算法。
- 只保存界面局部状态，例如表单草稿、展开、筛选和当前选择。

### 共享核心

- 可跨产品复用的纯算法放根目录 `src/` 或 `phoenix-wing/code-core`。
- VS Code API、Git 命令、Webview、QuickPick 和工作区生命周期不得进入 Wing。

## 3. Ribbon 规则

### 3.1 入口行为

- 点击 Ribbon 只打开或切换模块，不自动执行扫描、预览、替换或修复。
- Ribbon 不随模块内容增高；模块内容只能出现在下方 Module Block。
- 大图标 Ribbon 与 compact 样式行为一致，仅尺寸不同。

### 3.2 三种状态

| 状态 | 表现 | 含义 |
| --- | --- | --- |
| 当前显示 | 强活动高亮、活动边框 | 当前 Module Block |
| 已打开但隐藏 | 次级强调色、底部强调线 | 有逻辑 Block，可切回 |
| 未打开 | 普通背景和前景 | 当前没有逻辑 Block |

- 不得只靠颜色传达状态；tooltip 和 `aria-label` 必须写明“当前显示”或“已打开，当前隐藏”。
- 已打开按钮的 tooltip 应显示当前打开总数。
- 切换模块不得清除其他模块的工具状态或结果缓存。

### 3.3 单显示、多打开与关闭顺序

- 打开顺序使用 MRU（最近使用优先）记录，最近使用项位于栈顶。
- 点击已打开的后台模块时，将其移到 MRU 栈顶并显示。
- 关闭当前 Block 时，只移除当前逻辑 Block，随后显示 MRU 中最近使用的剩余模块。
- 关闭最后一个逻辑 Block 后才隐藏 Module Block，只保留 Ribbon。
- 关闭逻辑 Block 不等于清空工具结果；重新打开时允许重放 Host 缓存。
- VS Code 重启后的打开栈默认不持久化；如以后持久化，必须按工作区保存并处理已删除模块。

示例：依次打开 `头文件 → 搜索替换 → 编码`，关闭编码后显示搜索替换，再关闭后显示头文件。

### 3.4 Ribbon 高度

- Ribbon 内容必须紧贴按钮行，不在 Webview 内设置额外最小高度或占位空白。
- Ribbon 和 Module Block 是两个 VS Code 原生 View；扩展没有按 Webview 内容像素高度自动收缩 View 的公开 API。
- 新布局使用较小的 Ribbon 初始权重和较大的 Module Block 初始权重，让一排按钮默认尽量贴顶。
- 两个 View 之间的原生分隔线必须保留可拖动；VS Code 保存用户调整后的高度，扩展不在每次切换时强制改写。
- 已安装版本可能已保存旧高度；升级后允许用户拖动一次分隔线，之后应保持该高度。

## 4. Module Block 布局

一个模块只允许有一个 Block，按下列顺序组织：

1. VS Code 原生 View Header：模块名、全局图标和关闭按钮。
2. 工作区摘要：只保留必要路径或工作区名称，尽量一行。
3. 扫描/搜索范围：支持工作集的模块放固定下拉框。
4. 主操作：预览、扫描、修复、替换、应用等高频按钮放在操作区第一行。
5. 模块选项：输入框、checkbox、策略、过滤和高级规则。
6. 运行状态：明确说明动作、范围、数量、成功、无结果或错误。
7. 结果列表：紧跟状态，不跳到第二个 View。
8. 说明文字和低频入口：放在操作区尾部，避免把主按钮推到首屏外。

布局约束：

- Block 使用侧栏全部可用宽度，不设置页面式 `max-width`。
- Header 和摘要应紧凑，通常控制在 2～3 行内。
- 不重复显示 View Header 已经包含的模块标题。
- 不在 Module Block 内再套一个视觉上等价的“大卡片 Block”。
- 主操作不得因说明文字、其他模块或长结果而需要先滚动才能看到。
- 复杂选项可以渐进展开，但基础操作和当前范围始终可见。

## 5. 扫描范围和工作集

- 日常扫描范围必须放在 Module Block 顶部的固定下拉框，不得在点击预览/扫描后临时弹 QuickPick。
- 下拉项至少包含“整个工作区”和 `.phoenix/worksets.json` 中的命名工作集。
- 范围按模块分别记忆；切换模块或连续预览不得重复询问。
- 工作集保存后刷新下拉项；已选工作集被删除或配置非法时必须明确报错，不得静默扩大为整个工作区。
- 工作集约束与文件类型 checkbox 是两个维度：最终输入为“工作集文件 ∩ 模块文件类型 ∩ Ignore”。
- 搜索替换的“工作目录”与“搜索范围”分开：
  - 当前工作区及其子目录继续受工作集约束。
  - 工作区外绝对目录不使用当前工作区工作集，并在界面上明确提示。
- `.phoenix/` 是普通源文件扫描的硬排除目录；显式读取工作集配置不算源文件扫描。
- “把结果加入工作集”属于显式一次性操作，可以选择目标工作集，但不得与扫描范围选择混为一套流程。

## 6. 操作、运行状态与缓存

### 6.1 运行入口

- 用户点击 Block 内主按钮后才进入 `running`。
- `running` 时禁用会产生重复任务的按钮，并显示正在执行的动作和有效范围。
- 光标或按钮转圈不能成为唯一反馈。
- 只有 `running` 状态可以使用进度/繁忙光标；因输入不完整而禁用的按钮使用普通禁用光标，并在按钮附近说明缺少的条件。
- 禁用按钮必须提供可操作原因的 tooltip 和可访问文案；由于原生 `disabled` 元素可能不触发悬停，tooltip 应挂在外层容器，按钮使用 `aria-describedby` 或等价语义关联原因。
- Activity Bar 容器已经显示产品名，容器内第一个 View/Block 应使用“工具栏”等职责名称，不再重复产品名。
- 不得把多个连续 QuickPick/InputBox 当作常规配置界面；多字段配置必须留在 Block。
- 扫描策略、转换方式、过滤、搜索条件等常规参数必须在 Block 中直接选择，不得在点击主按钮后再弹 QuickPick。
- QuickPick 仅用于明确的一次性低频选择，例如“加入哪个工作集”，且不得形成无法判断进度的长链。
- 写盘、还原、清除系统值等高风险动作保留模态确认；文件/目录选择保留系统选择器。
- 普通成功、无结果和可恢复错误只更新 Block 状态，不再同时弹出重复通知。

### 6.2 终止状态

每次任务必须结束为以下之一：

- `done`：成功，有结果或明确无结果。
- `idle`：用户主动取消且没有错误。
- `error`：输入、工作集、文件系统或算法执行失败，并显示可操作原因。

所有异常路径都必须结束 `running`，恢复按钮状态。

### 6.3 结果缓存

- 新扫描完成后替换该模块的会话缓存。
- 运行期间保留旧结果，避免列表闪空；状态明确写“正在重新扫描”。
- 应用写盘后只更新缓存行的状态、选择和诊断，不自动重新扫描或重新生成预览。
- 用户取消勾选后，应用其余文件不得恢复已取消的选择。
- 从后台 Block 切回时重放同一缓存，不重新执行任务。
- “关闭候选”只从当前缓存隐藏/取消该行，不删除文件，也不触发重扫。

## 7. 结果列表规则

结果列表参考 VS Code Search 与 Source Control，而不是桌面表格：

- 文件名在前，目录在后，二者属于同一弹性行。
- 文件名尽量完整显示，不先压缩；目录使用剩余宽度并从尾部省略。
- 右侧依次放悬停操作和短状态，操作不得挤掉文件名。
- 常见分组包括：待写盘、已写盘、变更文件、无变更文件、错误或已阻止。
- 支持批量操作时，组和行使用统一 checkbox；组 checkbox 正确表达全选、部分选择和禁用。
- 默认只显示有改动的文件；“显示无变更文件”作为显式筛选。
- 行点击的默认行为是打开文件；Diff、应用、Git Diff、还原和取消使用独立图标按钮。
- 行内按钮默认可在悬停/聚焦时出现，但键盘用户必须能够访问。
- 没有结果时显示明确空状态，例如“没有匹配结果”或“未发现需修正文件”，不得只留下空白。

### 命中高亮

- 搜索替换结果的文件名仅高亮匹配片段，不整行染色。
- 打开文件后，编辑器命中使用统一的问题高亮及 VS Code 概览尺警告标记。
- 头文件 ASCII 在纯 ASCII 模式下按连续的非 ASCII 文本整段高亮，不得把字节列号直接当作混合中英文的编辑器字符列。
- 问题位置使用黄色半透明底色与警告色边框，同时保留概览尺标记，确保浅色和深色主题都醒目。
- 编码结果打开文件只定位文件，不生成字符问题高亮；若同一编辑器残留其他模块的装饰，必须先清除。
- 切换到无关编辑器后清除上一文件的装饰。

## 8. 预览、写盘、Diff 与还原

- 预览默认只更新结果缓存，不自动逐文件弹出 Diff。
- 用户点击某一行的“预览差异”后，才打开该文件的只读预览 Diff。
- 预览不得创建难以管理的 untitled 文件；使用只读内容提供器或 VS Code 支持的资源 URI。
- 批量应用前必须确认；写盘前比较预览快照，阻止覆盖外部修改。
- 应用后不得自动逐个打开 Diff，只更新行状态为“已写盘”。
- 已写盘行提供按需 Git Diff，调用 VS Code SCM/Git，不自行实现 Git 差异界面。
- 还原仅允许撤销本次会话写入；还原前再次核对文件内容，阻止覆盖用户后续修改。

## 9. 按钮和图标

- 主按钮使用文字，低频行内操作优先使用 VS Code 常见图标语义。
- 打开、预览 Diff、应用、Git Diff、还原、取消等图标在各模块保持一致。
- 优先使用 codicon 或现有统一 SVG，不为同一语义重复创建图标。
- 不支持的图标动作应隐藏或禁用，不得留下无图标的空白按钮。
- 每个图标按钮必须有 tooltip、`aria-label`、键盘焦点和足够点击区域。
- `×` 在结果行表示取消当前候选；View Header 的 `×` 表示关闭当前逻辑 Block，两者不可混用。

## 10. 配置界面边界

- 多字段、需要反复调整的功能配置放 Module Block。
- VS Code Settings 只保留真正的插件偏好，例如默认行为、外部编辑器和显示模式。
- 操作系统环境变量不伪装成 VS Code Settings；使用“工程环境”Block 展示、刷新和修改。
- 系统级设置、外部编辑器和 Git 等宿主能力优先调用原生界面。
- 高级界面只能有一个权威入口；不得在 Block、旧 Webview 和 QuickPick 中维护三份相同配置。

## 11. 状态和消息协议

- Webview 与 Extension Host 的消息类型集中定义在 `tools/types.ts`。
- 跨边界数据必须可结构化克隆，不传函数、URI 类实例、DOM 节点或不可序列化对象。
- Host 合并更新工具状态；局部状态更新不得意外清空旧结果。
- 一次性 UI 请求（例如临时规则选择器）不进入可重放的持久工具状态。
- 新增消息必须包含明确 `type` 和必要的 `toolId`，Provider 负责兜底异常。

## 12. 样式、主题与可访问性

- 使用 VS Code CSS variables，不硬编码只适合浅色或深色主题的前景/背景。
- 验证深色、浅色和高对比度主题；状态不能只靠红/绿/蓝区分。
- 侧栏窄宽度不得产生页面级横向滚动。
- 文本输入、select、checkbox 和按钮使用原生 HTML 控件即可，不为基础控件引入 Element Plus。
- 当前 Webview 使用轻量 TypeScript/HTML；未来引入 Vue 或组件库必须单独证明复杂度和体积收益，且不得改变本文的 Host/View 边界。
- 文件路径、状态和按钮在 300～500px 常见侧栏宽度下均应可用。

### 12.1 界面文案

- 动作词统一：未运行用“扫描/预览”，计划修改用“待写盘”，成功修改用“已写盘”，撤销本次修改用“已还原”。
- 结果已在当前 Block 时，不再写“扫描并打开结果”或“请到底部结果 View 查看”。
- 范围统一写“整个工作区”或“工作集：名称”；工作区外目录明确写“外部工作目录”。
- 转码目标在界面简写为 `UTF-8`，默认含义为 UTF-8 无 BOM。
- GBK 转码统一写 `GBK → UTF-8`；只有文件实际带 BOM 或操作专门讨论 BOM 时才写 `UTF-8 BOM`。
- 错误文案说明原因和下一步，不只写“失败”或“请重试”。

## 13. Webview 安全和资源

- 使用严格 CSP；脚本通过随机 nonce 授权，不允许远程脚本或宽泛 `unsafe-eval`。
- 图片和资源通过 `webview.asWebviewUri()` 或 CSP 允许的安全数据源加载。
- 不把用户文本拼入 `innerHTML`；必须使用 `textContent`，必要的模板文本要进行转义。
- Extension Host 校验消息类型、工具 ID、路径和工作集范围；Webview 输入不能被当作可信路径。
- 生产 VSIX 不包含 source map、测试文件、示例源码或未使用资源。

## 14. UI 变更验收

每次改变 Ribbon、Block 或结果行时至少检查：

- [ ] 点击 Ribbon 只打开/切换，不自动运行。
- [ ] 当前、后台已打开、未打开三态清晰，tooltip 与 `aria-label` 完整。
- [ ] 关闭当前 Block 按 MRU 恢复上一个，最后一个关闭后只留 Ribbon。
- [ ] 主按钮位于首屏上部，状态和结果位于同一个 Block。
- [ ] 连续运行不重复弹扫描范围，所有异常都能结束转圈。
- [ ] 工作集、文件类型和 Ignore 的交集正确，非法范围不静默扩大。
- [ ] 运行中保留旧结果；应用后原地更新，不自动重扫或弹多个 Diff。
- [ ] 文件名优先完整显示，目录和状态按剩余宽度压缩。
- [ ] checkbox、行内按钮、空状态、键盘操作正常。
- [ ] 深色、浅色、高对比度及窄侧栏无明显问题。
- [ ] TypeScript、DOM 脚本解析、状态纯函数和相关领域测试通过。
- [ ] Extension Host 人工确认原生 View、编辑器、Git Diff 和关闭顺序。

## 15. 规则维护

- 新增通用 UI 行为时，先更新本文，再更新实现和自动化点检。
- `0.x` 功能计划只链接本文并记录偏差，不复制整套规则。
- 临时试验若与本文冲突，必须在试点文档中写明范围和退出条件。
- 已废弃方案应标记为历史，不与当前规则并列陈述。
