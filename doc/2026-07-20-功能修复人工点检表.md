# 2026-07-20 功能修复人工点检表

状态：current

Owner：KT Auto Code maintainers

适用版本：KT Auto Code 0.5.x、KT Auto CAD 0.1.x、Desk Tools 0.2.x

最后核验：2026-07-20

## 1. 准备与记录

- [ ] 使用临时 Git 工作区或干净分支，记录初始 `git status --short`。
- [ ] 安装本轮生成的 `kt-auto-code-0.5.2.vsix`；测试 CAD 时同时安装 `kt-auto-cad-0.1.0.vsix`。
- [ ] 准备包含 `.h/.cpp/.md`、UTF-8 中文、GBK 中文、`.CATDlg`、`.FCStd` 和 `.gitignore` 的小型工作区。
- [ ] 记录 VS Code、Windows/macOS、三个产品版本与实际 Desk Tools 端口。

## 2. 搜索替换：全大写派生

1. 打开“搜索替换” Block，输入 `AutoCode → TomBuild`，勾选“文本”和“同时匹配全大写”。
2. 在同一文件中准备 `AutoCode` 和 `AUTOCODE`，点击“预览”。
3. [ ] 确认两处分别预览为 `TomBuild` 和 `TOMBUILD`；任意混合大小写不被猜测匹配。
4. [ ] 关闭再打开 Block，勾选状态保留；保存规则档案、切换其他档案后重新加载，状态仍保留。
5. [ ] 取消勾选后重新预览，只匹配 `AutoCode`，不匹配 `AUTOCODE`。
6. [ ] 点击“替换”但在 Modal 中取消，旧预览仍在，Block 不保持转圈，磁盘内容不变。

## 3. 关联规则候选摘要

1. 输入 `AutoCode → TomBuild`，源/目标前缀填 `KTC → KTM`。
2. [ ] 点击“常用规则”，标题区显示候选数和默认选中数，数量与列表 checkbox 一致。
3. [ ] 点击“CAA 规则”，确认摘要为 4 条候选、默认选中 2 条，默认项为 I/E 完整名称。
4. [ ] 已有搜索词被去重后，摘要数随剩余候选变化；无候选时提示可填写自定义规则。

## 4. 编码修正：UTF-8 / GBK 切换

1. 打开“编码修正” Block，先以 UTF-8 默认目标执行一次预检。
2. [ ] 将“默认目标”改为 GBK：下拉框不回弹，旧结果立即清空，状态显示“项目编码目标已更新，请重新预检”。
3. [ ] 关闭再打开 Block，仍显示 GBK；重载 VS Code 窗口后仍保留。
4. 若“项目覆盖”把源文件设为 UTF-8，先在“更多设置”改为继承；默认目标不应暗中覆盖显式分类策略。
5. [ ] 预检可无损转为 GBK 的 UTF-8 中文 `.cpp`，确认显示 UTF-8 → GBK；确认转换后检测为 GBK。
6. [ ] 再准备一次待转换结果，点击“按目标转换”后取消 Modal：状态回到 idle、旧结果保留、无文件写盘。

## 5. 头文件 ASCII 取消路径

1. 对包含弯引号或非 ASCII 内容的 `.h/.cpp` 执行预检。
2. [ ] 点击“修复”并取消 Modal：Block 结束转圈，显示“已取消修复”，旧问题列表保留，磁盘字节不变。
3. [ ] 未打开工作区时从命令面板触发预检，显示明确错误且不进入持续 running。

## 6. Ignore 分析、默认单选与缓冲区

1. 在包含 C++/Web 构建目录的工作区打开“忽略设置”，点击“分析当前工作区”。
2. [ ] 有多个安全建议组时，默认只勾选第一个可追加组；`review-required` 不默认勾选。
3. [ ] 手动多选后，主按钮显示“追加所选推荐（N）”，每组仍显示建议规则、已有数和阻止数摘要。
4. [ ] 追加所选组后，`.phoenix/.ignore` 文档为 dirty，未手工保存前磁盘字节不变；其他扫描立即读取打开缓冲区规则。
5. [ ] 手工保存后重新扫描，确认缓存失效并使用新磁盘规则。

自动边界证据：非法 preset ID/action、缺失或空推荐组 ID 会在 Host 入站守卫处拒绝；不需要在生产 Webview 中伪造恶意消息。

## 7. 工作集 dirty 防覆盖

1. 生成一组搜索替换、UUID、CAA 或成员排序结果，确保“加入工作集”可用。
2. 打开 `.phoenix/worksets.json`，做一个合法但不保存的修改。
3. [ ] 点击“加入工作集”，立即提示“有未保存修改”；不读取旧磁盘配置、不弹出工作集选择、不写盘。
4. [ ] 确认文档仍为 dirty，缓冲区修改原样保留。
5. [ ] 保存后重试，可正常选择工作集，且同一精确文件规则不重复追加。

## 8. CAA UI / Desk Tools 动态发现

1. [ ] 完全退出 Desk Tools，打开 CAA UI 并点击检测：显示离线，VS Code 不冻结。
2. [ ] 启动 Desk Tools，确认 CAA UI 显示 `127.0.0.1:<实际端口>`，且 `service.v1.json` 端口一致。
3. [ ] 事先占用 `48375` 后重启 Desk Tools，确认它在 `48376..48406` 中选择后续端口；插件不扫描猜测端口，仍通过注册文件连接。
4. [ ] 从 CAA 结果打开 `.CATDlg`，确认 Desk Tools 切换到正确工作区和文件。
5. [ ] 退出 Desk Tools 后重新检测，stale 注册不被当作在线服务。

## 9. 旧设置迁移与 Auto CAD 深度读取

1. [ ] 在旧 key 中填写 CAA command/args/endpoint 或 CAD provider manifest，启动新扩展；确认只迁入用户明确配置的值。
2. [ ] 预先填写不同的 `ktAutoCode.deskTools.*` 新值，确认旧值不覆盖新值；显式空新值也不复活旧值。
3. [ ] 只迁移旧 endpoint 时，`Discovery Mode` 为 `custom`；手动改回 `auto` 后重新使用动态注册。
4. [ ] Desk Tools 至少启动一次以生成 `installation.v1.json`，随后完全退出 Desk Tools。
5. [ ] 在 Auto CAD“读取”中执行 `.FCStd` 深度分析：读取器可用，不要求 Desk Tools 窗口或 HTTP 服务运行。
6. [ ] 填写错误 manifest 或篡改读取器，确认平台、Schema、SHA-256 或 protocol v1 验证失败，不降级绕过。
7. [ ] Auto CAD Ribbon 不出现独立“连接 Desk Tools”工具；服务连接属于 CAA UI，安装读取器状态属于 Auto CAD 读取功能。
