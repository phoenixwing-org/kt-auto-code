# 工作目录、Ignore 与设置 View 改造计划

状态：in progress（2026-08-21 已获用户确认；目录单行试验版）

Owner：KT Auto Code maintainers

## 1. 背景与目标

现有第二个 Shell Block 曾同时常驻“工作目录”下拉和完整 Ignore 管理，低频规则编辑占用侧栏首屏。用户确认将其收敛为一行工作目录选择。2026-09-05 又确认将 Ignore 与设置拆为两个同级逻辑工具 View，并把两个入口放到原生 View Header。

这是一项经用户确认的外层职责调整：三个一级区域的数量、顺序和当前工具 `×` 不变；第二段从“工作目录与 Ignore”改为固定的一行“目录”。用户同时确认该行隐藏折叠箭头，因而不再具有独立展开/收起状态。

目标布局：

```text
原生 Header                                             [忽略] [设置]
⌄ [图标+文字 Ribbon，可自然多行]                                 […]
目录  [当前目录 · 名称                                  v] [文件夹]
当前工具
  忽略设置（由原生 Header“忽略”打开）
    ▾ 来源与写入
    ▸ 插件内置规则
    ▾ 有效规则
    ▾ 推荐规则
  设置（由原生 Header“设置”打开）
    ▸ 工程环境
    ▾ 插件设置（1 项）
        VS Code 插件设置
```

## 2. 职责与交互

- 第一段是无独立“工具栏”标题行的两态 Toolbar Strip；箭头、同一份 Ribbon 和唯一 `…` 共用一层，展开态允许多行，紧凑态是一行小图标。
- 第二 Block 只表达和切换共享工作目录：左侧不放装饰文件夹，只用内边距对齐“目录”文字；右侧文件夹是唯一目录选择按钮。不常驻显示 Ignore、设置或规则编辑入口。
- 原生 View Header 固定显示“忽略、设置”，按此顺序分别打开独立的 `ignoreSettings` 与 `environmentSettings` 逻辑工具 View；搜索预览不再占用 Header。
- Ignore View 显示默认开启的插件内置/Git 与默认关闭的自定义三个来源，并承载分析、目标文件选择、规则增删、有效规则和推荐结果。它与设置 View 同级，不再嵌套在设置内。
- 工程环境、插件设置是设置 View 的内部可折叠 Block；它们不得新增 Primary 的第四个 Shell Block。最下面的“插件设置”使用默认展开的紧凑功能 Tree，当前先提供 `VS Code 插件设置`，以后新增入口时只增加 Tree 节点。
- 工程环境变量按“必需项在前、可选项在后”稳定排列；每个变量压缩为一行，变量名/状态、输入框和图标操作同排。默认只保留一个修改图标，不为空闲操作永久预留宽度；当前行悬停或键盘聚焦时，目录选择与清除图标才出现并向左占用输入框空间。必需项只用紧凑的红色 `*` 标识；正常系统来源不重复占位，仅“路径不存在、未设定、默认值”等需要关注的状态显示文字，完整来源保留在悬停提示中。
- 所有目录型环境变量共用相同选择器规则：当前输入值指向已存在目录时从该目录打开；为空、无效或不存在时从当前用户主目录打开。普通文本变量不显示目录选择入口。
- 设置 View 内部 Block 的展开状态是本机/会话 UI 状态；不写进工程配置。工作目录和三个 Ignore 来源开关保存在 `workspaceState`，自定义内容才写 `.phoenix/.ignore`。
- 文件扫描、搜索替换、编码、头文件、UUID、排序、CAA UI 等仍只消费 Host 已解析的工作目录和 Ignore 结果；本次不改领域算法。

## 3. 视觉与无障碍

- 第二 Block 使用一行紧凑控件：下拉占剩余宽度，文件夹为独立、有标题和 `aria-label` 的图标按钮。
- 第一与第三个 Shell Header 继续使用已锁定的 VS Code Section 基线；目录行沿用相同全宽分隔线，但不再在左侧放装饰文件夹。`目录` 仅用与 16px 箭头基线等效的内边距对齐，右侧文件夹是整行唯一的文件夹图标和目录选择入口；目录行固定为单行且不提供空的 Body。
- 设置 View 的内部 Block 先使用本地语义化 `details`（Wing 尚无可消费的 Shell/Section Block），但必须以显式 16px SVG 箭头、连续上下分隔线、Section Header 主题色和旋转 disclosure 表达，可独立折叠；不使用松散卡片外边距。
- 窄侧栏中目录名称整体省略，文件夹始终可达；键盘 Tab 可进入原生 Header 操作、下拉、文件夹和两个工具 View 的内部控件。

## 4. 实施步骤

1. 将第二 Shell 标题、ARIA 和规则文案改为“目录”，将其收为无箭头、无 Body 的单行目录控件，删除左侧装饰文件夹及其测试，并删除常驻 Ignore DOM。
2. 保留 `ignoreSettings` 与 `environmentSettings` 两个同级逻辑工具，分别承载 Ignore 和设置能力；二者复用当前工具 Block 与 MRU。
3. 将原生 View Header 收敛为 Ignore 和 Settings；删除搜索放大镜、目录齿轮和内部工具栏 Ignore 图标。
4. Ignore 内部按“来源与写入 → 插件内置规则 → 有效规则 → 推荐规则”组织；规则算法、Controller 与 Webview 渲染保持 MVC 分层。
5. 更新 Shell/设置工具自动测试、文档索引与人工点检表。

## 5. 验收

- [x] 第二 Block 只占一行，文案为“目录”，左侧只以间距对齐，显示当前目录、下拉和右侧唯一文件夹按钮。
- [x] 第二 Block 不再常驻显示 Ignore 管理内容。
- [ ] 原生 Header 只显示 Ignore、Settings；两者分别打开独立逻辑工具 View，搜索放大镜和 Webview 内重复入口均不存在。
- [ ] Ignore View 的三个来源、独立插件内置规则 Block、Git/Phoenix radio 写入目标和逐条规则管理能力可达；设置 View 只保留工程环境和插件设置。
- [x] 设置内部各项可独立折叠，底部“插件设置”以默认展开的功能 Tree 显示且入口可用；窄侧栏和键盘焦点可用。
- [ ] 工程环境必需项位于可选项之前；每个变量只占一行，图标操作悬停/聚焦可达。
- [ ] 目录变量的有效原值成为选择器起点；空值或无效路径回退到用户主目录。
- [ ] 三个一级区域数量、顺序、第三 Block 的内部滚动与 `×` 语义不变；Toolbar Strip 在展开/紧凑间切换且无独立标题行，当前工具仍可折叠，目录行固定单行。
- [ ] 工作目录切换后，所有文件工具仍按相同目录和 Ignore 交集工作。
