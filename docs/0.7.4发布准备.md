# KT Auto Code 0.7.4 发布准备

状态：superseded（未公开发布；内容已并入 0.8.0 测试候选）

Owner：KT Auto Code maintainers

适用版本：KT Auto Code 0.7.4；Phoenix Wing root 0.7.1 / scoped 0.6.4、0.6.3

最后核验：2026-08-27

## 版本边界

本补丁不升级 Phoenix Wing Registry 依赖，不修改 locked Primary 三段式外壳，也不写入本地路径、`link:`、`file:`、workspace override 或本地 Wing 回退。正式 manifest 继续精确消费已发布的 `@phoenix-wing/code-core`、`git-core`、`git-node`、`kt-codegen` `0.6.4` 与 `run-core`、`run-node` `0.6.3`。

该补丁候选没有单独发布。后续新增大型项目改名用户工具触发次版本规则，因此本页内容整体并入 [`0.8.0 发布准备`](0.8.0发布准备.md)。

## 本轮内容

- 修复代码辅助 Webview 把头文件 ASCII、编码、UUID 与 CAA UI 的叶子动作误发给外层 `codeAssistant` 容器的问题。
- 所有 Webview `run` 信号使用真实叶子工具 ID，并由工具声明允许动作；未知工具或动作写入 `[Primary][信号][ERROR]`，同时回传当前 Block 错误状态。
- Primary 内部叶子统一使用仓内 `ktcCodeAssistantFeatureBlock` 外壳；Header、折叠、`×`、操作区、临时结果清理与无障碍属性保持一致。
- 内部 Block 全部收起后再次选择功能，会恢复至少一个操作 Block；“头文件引用修正”等独立编辑器 View 功能不创建内部 Block，也不自动收起功能目录。
- 新增 Host 路由、动作契约、关闭清理、独立 View 与重新展开行为的回归测试，并同步前端和必要日志规则。

## 重点人工点检

1. 点击头文件 ASCII、编码、UUID、CAA UI 与成员排序叶子，确认目录按规则收起、对应操作 Block 立即出现，入口日志不抢焦点。
2. 分别执行一次预检/扫描；确认真实动作执行，成功、取消或错误进入 `KT Auto Code` Output，而不是只留下入口日志。
3. 点击内部功能 Block 的 `×`；确认只关闭当前叶子、释放临时结果、返回功能目录，不关闭第三个当前工具 Block。
4. 将成员排序的操作与结果 Block 都折叠，再次选择成员排序；确认至少“排序操作”重新展开。折叠任一通用内部 Block 后再次选择同一叶子，也应恢复操作区。
5. 点击“头文件引用修正”；确认打开独立编辑器 View，Primary 功能目录保持展开，不出现空的内部功能 Block。
6. 通过回归测试发送不存在的工具或未声明动作；确认 Output 与当前 Block 均显示错误，不再静默返回。
