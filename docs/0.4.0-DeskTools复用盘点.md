# 0.4.0 Desk Tools 复用盘点

## 结论

0.4.0 不复制 Desk Tools 的页面，而是复用其中已经验证过的领域语义，并继续使用 KT Auto Code 已经更成熟的 VS Code 原生 Block、逐文件状态和 Git Diff 工作流。

本轮纳入 0.4.0 的能力只有三组：

1. 工作集：复用 `phoenix-wing/code-core` 的 `.phoenix/worksets.json` 契约，让 ASCII、编码、成员排序、UUID、搜索替换和 CAA 扫描可以选择明确范围。
2. UUID 策略：在现有 `map_per_value` 之外暴露 Desk Tools 已有、Wing 已实现的 `fresh_per_hit`，默认仍保持同值同替换。
3. Ignore 进程目录建议：吸收 Desk Tools 对顶层构建/缓存目录的识别，但接入 KT Auto Code 现有的证据、Git 跟踪阻断和勾选应用流程。

代码索引、CATDlg 完整编辑器、CAD 文件改名、Git 页面和桌面运行配置不进入本版。

## 0.4.0 实施边界

### R0：工作集范围

- 权威格式为 `.phoenix/worksets.json`，schema 与安全路径校验继续放在 `phoenix-wing/code-core`。
- Extension Host 负责读取、glob 展开、Ignore 合并和文件类型二次过滤；Wing 不访问文件系统。
- ASCII、编码、成员排序、UUID、搜索替换和 CAA 在各自 Block 顶部选择“整个工作区”或一个工作集；扫描动作不得再次弹范围选择。
- 扫描完成后使用文件快照，写盘阶段不得重新展开工作集并静默扩大范围。
- 结果文件可加入已有工作集；没有工作集时提供打开/创建 JSON 的原生命令，不新建复杂表单。
- `.phoenix/` 仍是所有源文件扫描的硬排除目录；读取工作集是显式配置读取，不等于扫描 `.phoenix`。

### R1：UUID 策略

- 默认 `map_per_value`：同一个旧 UUID 在所有命中位置替换为同一个新 UUID。
- 可选 `fresh_per_hit`：每个命中独立生成新 UUID；选择时必须明确提示可能打破引用关系。
- 策略在扫描前确定，并显示在结果根节点/摘要；已有会话不得在应用阶段临时换策略。
- 两种策略共用 Wing 计划和现有逐命中写盘流程，不保留 Desk Tools 的第二套替换实现。

### R1：Ignore 顶层进程目录建议

- 识别 `build`、`debug`、`release`、`out`、`bin`、`obj`、`dist`、`.cache`、`_build`、`build-*`、`cmake-build-*`。
- 只产生建议，不在首次扫描时自动写入规则。
- 已被现有规则覆盖的不重复提示；包含 Git 已跟踪文件时继续阻断默认勾选。
- 通配模式收敛为最小安全规则，例如多个 `build-*` 目录可建议 `build-*/`。

### R2：操作报告（不阻塞 0.4.0）

- UUID 和批量改名可提供“导出本次计划”命令，输出 JSON-safe DTO。
- 不默认写报告；如用户导出到 `.phoenix/reports/`，该目录必须继续被所有扫描器排除。
- 报告是审计产物，不作为再次写盘的隐式输入。

## 反向复用到 Desk Tools

以下能力以 KT Auto Code/Wing 为准，Desk Tools 后续应接共享 core 或对齐交互，不应再从 Desk 反向覆盖插件：

- 成员排序的预览快照、逐文件应用状态、失败阻断和 Git Diff/回退入口。
- UUID 的稳定计划、格式保持、逐命中选择、编码保持与写前指纹检查。
- 搜索替换的关联规则、CAA I/E 规则和配置/结果分离。
- Ignore 的证据化推荐、Git 已跟踪文件保护和显式勾选应用。
- Git 风格的文件在前、相对目录在后、行内图标和结果分组。

## 明确延期

- 完整持久化 Code Index：需要先证明 VS Code Search/Explorer 不能满足的场景。
- CATDlg 图形编辑和 NLS/代码生成：先完成 `catdlg-core` 到 Wing 的无宿主迁移，再决定 KT Auto Code 只读摘要与未来 KT CAD 的写入边界。
- FCStd/CAD 引用修复式改名：只进入未来 KT CAD。
- Desk Tools 的 SQLite、HTTP route、Vue/Tauri 页面与 server prefs：全部属于宿主层，不进入 Wing 或 VS Code 插件。

## 验收

- 选中工作集后，六个文件型工具的扫描文件均为“工作集展开结果 ∩ 工具文件类型 ∩ Ignore”。
- 工作集非法、越界或不存在时停止运行并给出可定位的诊断，不回退为全工作区扫描。
- UUID 两种策略都有 Wing core 测试和 Extension Host 流程测试；默认行为与 0.3.0 一致。
- Ignore 新建议不会自动写盘，不会重复 `.phoenix/`，不会默认忽略 Git 已跟踪文件。
- 不新增 Desk Tools 风格的大 Webview、内建 Git 页面或 SQLite 依赖。
