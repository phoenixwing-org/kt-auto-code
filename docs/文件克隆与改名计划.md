# 文件克隆与改名计划

> 状态：仅规划，尚未实现。

## 1. 目标与使用场景

在保留原文件的前提下，按独立的文件名基名规则复制一批文件、生成新文件名，并在新副本内部完成文本替换。

这里要明确区分两个输入：

- **搜索替换工具**处理文本内容时，示例是 `搜索 = AutoCode`、`替换 = NewTool`。
- **批量克隆与改名**不直接复用这个搜索框，而有独立的 `BaseName`。例如 `BaseName = KtaAutoCodeTool`，文件名搜索模式为 `**/KtaAutoCodeTool*.*`；目标基名可填 `NewTool`。

典型文件名搜索结果为：

```text
KtaAutoCodeToolDlg.ui
KtaAutoCodeToolDlg.cpp
KtaAutoCodeToolParamDlg.xxx
```

用户把批量克隆中的 `BaseName: KtaAutoCodeTool → TargetBaseName: NewTool` 后，可生成对应的新文件；原文件与原内容保持不变。副本内部的文本替换则按普通搜索替换规则执行，例如将内容中的 `AutoCode` 替换为 `NewTool`。该能力适合从一套 CAA / C++ 模板、对话框或模块骨架派生新模块，避免“先整批改名、再手工恢复原模板”的高风险操作。

## 2. 产品定位与价值判断

该功能有明确价值，但应定位为**受控的模板派生**，而不是通用目录复制工具：

- 对有统一命名的成组源码、`.ui`、配置和说明文件，可显著减少重复创建与内部名称遗漏。
- 复用既有的关联规则、编码处理和预览能力，学习成本较低。
- 保留源文件是与现有“工作区改名”最重要的语义差异，必须在界面和确认框中反复明确。

不适合首版自动处理的情况包括：跨模块 include 依赖自动改写、构建系统登记、二进制资源内容替换、任意目录的隐式全量复制。这些行为应由用户在预览后自行处理，或作为后续独立能力设计。

## 3. 建议交互

在现有“搜索替换”工具的下方增加可展开/收起的 **文件克隆与改名** Block。它复用工作目录、Ignore、关联规则和默认编码设置，但文件名扫描使用独立的 `BaseName` / `TargetBaseName`；上方普通搜索框仍用于副本内部的文本替换。

Block 默认收起，避免干扰普通工作区替换；标题栏沿用 VS Code 常见的折叠区样式，显示摘要与展开箭头。用户展开后才看到克隆位置和预览入口。

### 3.1 Side Bar 文本 UI 示意

```text
搜索替换
搜索： [ AutoCode                            ]
替换： [ NewTool                             ]
[x] 文本  [x] 文件名  [ ] 文件夹名  默认编码 [ UTF-8 v ]

▾ 展开关联规则
  …现有规则、前缀与档案区域…

────────────────────────────────────────────
▸ 文件克隆与改名                              0 个待预览

  （收起时只显示标题；不占用普通替换流程空间）
```

展开后的形态：

```text
▾ 文件克隆与改名
  文件名 BaseName：       [ KtaAutoCodeTool       ]
  目标文件名 BaseName：   [ NewTool               ]
  文件名模式（预览）：     **/KtaAutoCodeTool*.*
  副本内部文本规则：       AutoCode → NewTool（使用上方规则）
  复制位置： (•) 原位置创建副本
            ( ) 复制到目录 [ clone/          ] [选择文件夹]
  [预览匹配文件]

  预览完成后在当前编辑分栏打开结果 View：
  [☑] Source                         Target                  路径
  [☑] KtaAutoCodeToolDlg.cpp         NewToolDlg.cpp          src/ui/
  [☐] KtaAutoCodeToolParamDlg.xxx    NewToolParamDlg.xxx     src/ui/ 目标已存在

  已选 1 / 2 · 冲突 1
  [创建 1 个副本]
```

预览表仍放在当前编辑分栏的结果 View，以容纳多行、勾选框和冲突详情；Side Bar Block 只负责配置、摘要与触发操作。这样既符合现有工具的布局，也避免在窄侧栏中堆叠复杂表格。

### 3.2 操作流程

1. 用户在普通搜索替换区域填写副本内部文本规则，例如 `AutoCode → NewTool`。
2. 用户在克隆 Block 填写 `BaseName`（例如 `KtaAutoCodeTool`）和目标基名（例如 `NewTool`）。
3. 系统按文件名模式 `**/KtaAutoCodeTool*.*` 搜索文件，遵守当前工作目录与 Ignore 规则；不把普通文本搜索词 `AutoCode` 当成文件扫描基名。
4. 在当前编辑分栏的 View 展示克隆预览表；每一行均有勾选框，默认全选。
5. 用户可取消某些文件，选择目标位置后点击 **创建副本**。
6. 系统再次预检、弹出确认框，并写入新文件；源文件不修改。

### 3.3 预览表

建议列保持简洁：

| 选择 | 原文件名 | 目标文件名 | 相对路径 | 内部替换 |
| --- | --- | --- | --- | --- |
| ☑ | `KtaAutoCodeToolDlg.cpp` | `NewToolDlg.cpp` | `src/ui/` | 12 处，UTF-8 |

- 顶部提供“全选 / 全不选”和“仅保留无冲突项”。
- 目标文件名由 `BaseName → TargetBaseName` 计算后，仅替换 basename 中的基名片段；例如 `KtaAutoCodeToolDlg.cpp → NewToolDlg.cpp`。
- 内部替换只针对即将创建的副本，并使用上方 `AutoCode → NewTool` 及关联规则；预览应显示命中数量、跳过原因和编码决策。
- 出现目标冲突、无法编码或无文件名变化时，行标红且默认不选。

### 3.4 目标位置

提供两个互斥选项：

1. **原位置创建副本**：例如 `src/ui/KtaAutoCodeToolDlg.cpp` 生成 `src/ui/NewToolDlg.cpp`。
2. **复制到目标目录**：输入或选择一个目录；默认建议为当前工作目录下的 `clone/`。从扫描根开始保留相对目录结构，例如：

```text
扫描根/src/ui/KtaAutoCodeToolDlg.cpp
→ clone/src/ui/NewToolDlg.cpp
```

目标目录不能位于所选源文件的子树中，避免下一次扫描把新副本当作源文件再次克隆。

## 4. 算法与写盘规则

### 4.1 预览阶段

1. 复用当前文件遍历、Ignore、符号链接跳过和二进制识别规则。
2. 对每个命中文件生成 `sourcePath → targetPath` 映射；按 `**/BaseName*.*` 搜索，文件名只替换 basename，不替换父路径。
3. 对选中目标检查：目标已存在、多个源映射到同一目标、目标目录不可写、路径越界。
4. 对可识别文本文件，复用现有文本替换与编码决策；二进制或未知编码文件可复制原字节，但不做内部替换，并在表中明确标注。

### 4.2 写盘阶段

- 再次执行预览，只有全部选中的行均无冲突才允许确认。
- 每个副本先复制原始字节；仅对副本应用内部文本替换，绝不写回源文件。
- 原文件为 ASCII 且目标文本含非 ASCII 字符时，使用界面的默认 UTF-8 / GBK 选择；其余编码规则见[搜索替换编码规则](./搜索替换编码规则.md)。
- 任一副本写入失败时应报告已完成项和失败项；首版优先保证“不覆盖已有文件”，后续可增加临时目录 + 整体提交式写入与回滚。

### 4.3 目标冲突决策

目标冲突是此功能的首要安全边界，首版采用以下固定规则：

| 情况 | 预览显示 | 默认选择 | 写盘行为 |
| --- | --- | --- | --- |
| 目标文件已存在 | 红色“目标已存在” | 不选中 | 绝不覆盖；用户必须取消该行后才能执行其他选中项。 |
| 两个或多个源文件映射到同一目标 | 红色“多个源映射同一目标” | 相关行全部不选中 | 不选择其中任意一行；用户可重新调整规则或取消全部冲突行。 |
| 源文件与目标路径相同 | 灰色“无文件名变化” | 不选中 | 不创建副本，避免把“克隆”误当作原地内部替换。 |
| 目标目录不存在 | 正常提示“将创建目录” | 选中 | 确认后按相对路径创建必要的父目录。 |

确认框应汇总“将创建 N 个副本、跳过 M 个冲突项”，并再次强调不会修改或覆盖源文件。后续若加入“覆盖已有目标”，必须作为独立的危险选项，默认关闭，并要求逐项或二次确认；不纳入首版。

## 5. 关键边界

- 首版只克隆文件，不因文件名命中而自动克隆整个父目录。
- 保留文件权限、时间戳、Git 状态和可执行位的具体策略需按平台验证；首版至少保证内容正确且不覆盖现有目标。
- 不自动更新 `.vcxproj`、`CMakeLists.txt`、CATIA 配置或其他未命中文件中的引用；用户可在同一次规则预览中另行处理。
- 不复制符号链接；隐藏目录、Ignore 路径和常见构建目录沿用现有跳过策略。
- 空替换不允许生成目标文件名；仅内部文本替换为空仍可沿用已有规则，但不作为首版主路径。
- 克隆任务必须在结果 View 中保留源路径、目标路径、编码和规则命中摘要，方便 Git diff 审核。

## 6. 实施分期

### Phase 1：安全最小版本

- 文件 basename 搜索、勾选预览、原位置 / `clone/` 目标目录。
- 单条和既有多规则生成目标文件名。
- 复制文本文件并在副本内替换；二进制仅复制并标记。
- 冲突阻断、确认框、结果 View、单元测试。

### Phase 2：体验完善

- 目标目录选择器、最近克隆目录、按扩展名筛选。
- 预览中的文件打开、单行排除、冲突批量处理提示。
- 写盘失败的临时文件清理与可审计的操作日志。

### Phase 3：项目级派生

- 可选的目录克隆与目录名替换。
- `.vcxproj` / CMake 等项目清单的显式更新候选；必须单独勾选，不能隐式修改。
- 将常用克隆方案保存为工作区档案。

## 7. 验收建议

- 选择 3 个同名前缀文件，只生成对应 3 个新文件，源文件哈希不变。
- 原位置模式与 `clone/` 模式均保留正确相对路径。
- 多个源映射到同一目标或目标已存在时，整批不写盘。
- UTF-8、UTF-8 BOM、GBK 和 ASCII→中文目标均按[编码规则](./搜索替换编码规则.md)验证。
- 取消任意预览行后，不创建该行副本，也不影响其他选中行。
- Git diff 仅包含新文件；不应出现源文件修改或未预期的项目清单改动。
