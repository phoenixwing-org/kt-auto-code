## 0.9.3 紧急修复与验收（2026-09-11）

- 用户确认市场安装、本地正式 VSIX 和 `pnpm dev:registry` 均出现 Primary 工具栏空白。浏览器报错为 `els.runCleanupDialog.close is not a function`，来自 `renderRunCleanup → renderWorkingContext → render`。
- 根因是 Auto 将编译工具清理迁入 Right 时移除了 Primary 的共享注册，但 Run 仍保留清理弹窗并在首次初始化时关闭它。Wing `code-core@0.6.6` 的组件本身含有正确接口；隔离页只注册同一包内的原组件即可恢复，不需要修改或重发 Wing。
- 修复由 `KtcRunPrimaryPanelEntry` 明确注册自身所需弹窗；不改变清理安全规则、Primary/Right 外层契约、Wing 精确依赖或生成规则版本。
- 工具栏恢复后发现编译工具 Right「清理」持续置灰：VS Code 外层 Webview 通过 `postMessage` 转发 Host 状态，同时启动脚本将 `window.parent = window`。因此仅允许自身或 `window.parent` 都会丢弃真实 Host 消息。修复按非 opaque 的 Webview 同源转发接收，拒绝外部来源；回归须模拟 **隐藏 parent 后再从外层 iframe 转发**，不能只测普通 iframe。保留 session/context/revision 核对。`.js.map` 的 `connect-src` 警告属于调试源码映射请求，不以放宽 CSP 解决该按钮问题。
- 按用户补充，Right「清理」入口始终可点；等待就绪、任务忙、无可用目标时在弹窗说明原因，而不是禁用入口。打开/关闭受限状态提示不发送取消构建或实际清理；预览令牌、目标核对、Host busy/权限门禁不变。
- 此前后台/Host 流程与文件存在性门禁没有验证 Primary 的第一次真实渲染。新增离线 DOM 门禁执行实际生产脚本列表、真实 Wing 元素和 Host `ready/init` 消息，分别检查无工作区/有工作区、工具栏与 Run 激活；VSIX 验证执行同一检查，缺少注册时必须失败。DOM 检查不代替真实 VS Code 的 CSP/视觉验收。
- 0.9.3 从固定 `worktrees/kt-auto-code-working` 生成带真实 dirty/stable 来源标记的 Registry 补丁包；用户现已确认本地安装测试通过，并反馈自行发布到插件市场。AI 仅做本地归档，不重复上传、推送或覆盖 0.9.2/0.9.3 已验收制品。此包在源码提交前构建，不能把它的原始来源回执改写成 clean commit 构建；未来重新打包须按正常发布门禁重新验收。

实现边界：Registry `code-core@0.6.6` 暂无规则标题动作 slot，Auto 的共享小型布局适配器只补 slot 和标题截断，复用 Wing 的折叠、文本框和清理行为。真实 Registry DOM 有回归；后续 Wing 提供公开 slot 时可去掉此适配，不修改已安装依赖或借本次修复重发 Wing。

长目录增量（2026-09-11）：仅修布局，不改变无目录提示或清理逻辑。旧包在 840px iframe 中，680px 弹窗的隐式 Grid 列被长标题撑到约 1033px，导致 Header 和规则按钮被裁切。改为 `minmax(0, 1fr)` 并限制内部最小宽度，标题/目标路径截断且保留完整提示，Header 动作在窄窗口内换行；文本框宽度扣除 Block 内边距。独立 Chromium 使用包内脚本在 840/640/420/360px 下核对全部按钮边界、标题截断与正文无水平溢出；用户已确认本地安装测试通过，Windows 专项仍保留待测，不以 DOM 单测冒充几何验证。
