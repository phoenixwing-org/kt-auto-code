# 编译工具：Windows 导出脚本首行错误

状态：current；待定位，未修复确认

Owner：KT Auto Code maintainers

适用版本：0.9.2 后续开发；用户 Windows 导出文件的实际来源版本待核对

最后核验：2026-09-10

## 已知现象与边界

用户反馈：今天在 Windows 上运行 `Invoke-AutoBuild.local.ps1` 时，第一行报错，脚本不能运行。目前没有对应原始文件、完整红色错误文本、PowerShell 版本或执行命令。

仅登记问题，不根据“第一行”推定是编码、BOM、版本声明或路径问题，也不把当前生成器检查写成修复。macOS 环境尚未取得这份 Windows 文件，未复现 Windows 执行失败。此项与 YAML 清理 UI、Codegen Combo 注释/配色及 Windows clang-format 分开跟踪。

## 当前源码核对

- [构建启动脚本生成器](../../src/tools/codeAssistant/autoBuildLauncher.ts)当前生成首行为 `#Requires -Version 5.1`；不是已拿到用户文件后的逐字核验。
- [Host 导出入口](../../src/tools/codeAssistant/autoBuildViewController.ts)的 `exportLauncher` 与“脚本”窗口导出 PS1 两条路径，当前均将 `\uFEFF` 前缀与内容一起按 `utf8` 写入，即源码意图为 UTF-8 BOM。版本归档 JSON 的写入路径是另一种产物，不混为 PS1。
- [检出脚本生成器](../../src/tools/codeAssistant/autoBuildCheckoutScript.ts)同样以 `#Requires -Version 5.1` 开头，但用户本次报告的是 `Invoke-AutoBuild.local.ps1`，不能用另一个脚本的表现替代复现。
- 上述事实只描述当前源码；不证明用户运行的文件来自这些入口、不证明传输/保存后字节一致，也不证明 Windows 可以执行。

## 待取得的诊断材料

不要求用户现在补答；后续定位时再收集最小必要材料，保留原件，不先格式化或重新保存覆盖它。

1. 出错的原始 `.ps1` 文件或保持原始字节的附件；至少核对文件开头字节、前几行、换行及内容哈希。分享前检查其中的本机路径、私有仓库地址和其他敏感值。
2. 完整红色错误文本，包括行/列、错误标识与调用位置；仅“第一行”不足以区分解析、版本检查或调用方式错误。

4. 导出入口、插件/候选包或源码标识、导出时间，以及是否经编辑器另存、复制或下载。
