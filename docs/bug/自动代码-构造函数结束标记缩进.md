状态：0.9.2 本地候选已修复并完成本机回归；未执行 Windows clang-format

发现版本：KT Auto Code 0.9.1 本地内测；原冻结来源见[内测收尾](../0.9.1-内测收尾.md)。修复采用独立生成规则 `1.0.1`，不回改 0.9.1 冻结源码或制品。

最后核验：2026-09-10

## 当前实际快照

用户的自动替换结果位于
`PNXBomAnalysisWsp/PNXBomAnalysisInterfaces/PNXBomAnalysisItf.m/src/PNXBomAnalysisParam.cpp`。
来源工程为 `<PhoenixRoot>/PNXCaaStudy/`（文档中省略用户主目录）。
只读点检确认：

- 生成的构造函数初始化项使用 4 空格缩进。

  被写在第 1 列。

因此错位在自动替换后、Windows clang-format 前已经存在。备忘与后续修复均没有修改或格式化该用户文件，也没有判定 Windows 格式化后的确切二次变化。

## 用户期望

结束标记应跟随生成区之后的第一条语义行，不能始终顶格：

1. 若结束标记后还有构造函数初始化项，两条标记与前后初始化项对齐（当前样式为 4 空格）。
2. 若结束标记后没有初始化项，只剩构造函数体的 `{`，两条标记与 `{` 对齐。

最小输入与期望文本放在
[`tests/fixtures/codegen-format-boundary/`](../../tests/fixtures/codegen-format-boundary/)：

- `constructor-with-tail.input.cpp` → `constructor-with-tail.expected.cpp`
- `constructor-brace-only.input.cpp` → `constructor-brace-only.expected.cpp`

夹具使用通用 `Sample` 类和最少字段，不复制完整公司源码。有后续初始化项的 input 保留本次顶格反例；brace-only input 是用于防止“一律采用初始化项缩进”的构造反例，不是本次用户文件的实际快照。Wing `packages/kt-codegen/tests/constructor-boundary.test.ts` 已将两组情形接入真实 Analyze → renderer 的完整输出回归，并验证区域外内容不变及重复生成稳定。Auto 原始最小夹具保留不重写；本机格式化复验将真实 renderer 输出的结束边界与这两份 expected 比较后再送入 clang-format。

## 修复与范围

2026-09-10 用户明确开启此项，解除之前“仅记录、不修”的限制。根因是 `cpp-parameter-family.ts` 有意保留旧 VB `Trim()` 行为，硬编码两条结束标记顶格，不是 Windows 格式化器把正确缩进删除。

规则 `1.0.1` 在同一路径、同一指纹的只读源码快照中，从 END 替换范围之后寻找第一条非空、非纯注释语义行，保留其空格或 tab 前缀；只有 `{` 时自然与 `{` 对齐。忽略空行、单行和块注释；无后续语义行则保留原 END 缩进。只改 `PARAM CONSTRUCTOR` 结束边界，不动用户尾部初始化项、函数体或其他 block，不改 Marker/Analyze/Apply 安全算法。

Wing 与 Auto 的规则常量、缓存样例同步为 `1.0.1`。旧 `1.0.0` 计划即使源文件、JSON、索引未改变也必须重新预检；旧 runtime 不得伪装新规则。详见[版本约定](../codegen-plan/Codegen生成规则版本.md)。
