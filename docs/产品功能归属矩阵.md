# KT Auto Code 产品功能归属矩阵

状态：current

Owner：KT Auto Code maintainers

适用版本：0.8.x

最后核验：2026-09-04

本文由 KT Auto Code 维护，记录基础插件、Phoenix Wing 与 Phoenix Desk Tools 的能力归属。自 2026-09-04 起，**Codegen、Code 工具与工作区自动化以 KT Auto Code 为唯一产品开发真源**；Desk Tools 不再为了功能对齐维护第二套用户入口。KT Auto CAD 在[自己的产品功能归属矩阵](https://gitee.com/PhoenixWing321/kt-auto-cad/blob/master/docs/产品功能归属矩阵.md)中维护 CAD 能力。

Wing 已实际导出的能力只认 [Wing 共享能力目录](https://gitee.com/phoenixwing/phoenix-wing/blob/develop/docs/共享能力目录.md)中的 `capabilityId`、export 和源码相对路径。跨库盘点过程与阶段决策归档在本机 Phoenix AI Workspaces 的 `wing-projects/work/三库功能归属与迁移协调-2026-07-22.md`；该内部工作记录不是发布包依赖。

## 维护规则

- 两端出现相同 `featureId`，先判定是否为重复产品能力。Auto 已覆盖的 Codegen、Code 工具或工作区自动化不得继续做双端功能对齐，Desk 对应入口进入冻结或退役评审。
- `共享完成` 只用于本仓库已经消费 Wing 正式 export 的能力。Wing 已提供但本仓库仍用私有实现时标为 `部分共享`。
- VS Code Commands、Settings、QuickPick、Problems、Output、SCM、编辑器定位和 `workspaceState` 是 Host 能力，不因为 Desk 有对应页面就迁入 Wing。
- Desk 只有在 Auto 明确不足、且能力确实依赖独立桌面宿主时才可保留或新增；例外必须写明缺口、宿主理由、owner、复核日期和退役条件。
- UI-neutral 的字符串、路径、计划、冲突、IR、校验和 fixture 继续优先放入 Wing；产品流程、权限、文件事务和宿主 UI 不得为了“共用”下沉到 Wing。
- Python 不作为恢复或重写主路径；只有当前 TypeScript/Wing 行为无法解释的具体回归，才定点对照旧函数或 fixture，修复仍落在当前架构。
- 治理标记：`R1` 为已确认重复、满足门禁后从 Desk 退役；`R2` 为冻结新增并限期证明桌面宿主必要性；`K` 为宿主或产品专有、继续保留；`—` 为 Auto 单端能力。

### Auto 覆盖与验收判定

- Codegen、成员排序、UUID 和 Ignore 已有持续自动门禁、真实 Extension Host 基线及既往发布使用记录，可进入 Desk 依赖/数据迁移审计；这表示允许准备退役，不表示跳过 Desk 回滚窗口直接删除。
- 搜索替换/项目改名已随 `0.8.1` 发布并完成基础手工验证，但详细 Windows 代表路径尚无额外回执；在该证据补齐前只冻结 Desk 新功能，不执行最终删除。
- Code Index 在 Auto 没有等价持久页，也没有桌面宿主必要性证据，保持 `R2`。它既不能被当前矩阵直接删除，也不能据此继续扩建其它重复工具。

## Desk 退役门禁与顺序

### 已完成的盘点动作

- [x] 对齐 Auto 命令、核心能力与 Desk 可见页面/route，识别五组 `R1` 重复入口和一组 `R2` 灰区。
- [x] 固定 Auto 是 Codegen、Code 工具与工作区自动化的唯一产品开发真源；停止“两个产品功能数相等”的目标。
- [x] 固定 Wing 只承载 UI-neutral 纯能力，Python 只用于无法解释的定点回归对照。
- [x] 把 Git、CAA、CAD/BOM、Desk 自测台与同名但不同领域的 CAD 文件改名排除出误删范围。

### 后续执行顺序

1. **冻结**：Desk 的五组 `R1` 页面不再新增产品功能；紧急修复只允许安全、数据兼容或删除准备。
2. **取证**：每组建立 Auto ↔ Wing golden fixture、Auto 真实 Host 回执和 Desk 当前数据/配置迁移清单。Auto 已发布不自动等于 Desk 可立即删除。
3. **先解耦再删**：先移除 Desk 导航/入口并保留一个兼容窗口，再删除 Vue 页面、API route、Host service 与仅服务该入口的测试；共享项目文件和 Wing pure core 不删。
4. **建议批次**：先 Codegen；再成员排序与 UUID；最后处理与 Code Index/Workset 耦合更深的 Ignore 与 Code 改名。每批独立提交、独立回滚。
5. **裁定 Code Index**：记录真实大型查询消费者、性能证据和桌面宿主理由。无法证明时退役用户页；能够证明时写例外 ADR、owner、复核日期及退出条件。
6. **完成定义**：Desk 不再暴露已退役入口、不保留孤儿 route/service；Auto、Wing 和 Desk 相关门禁通过，用户迁移说明可执行，项目数据可继续读取。

## 变更流程

1. 在本表找到 `featureId`，先判定 Auto 真源、Wing pure core、宿主 adapter 和 Desk 退役状态。
2. Codegen、Code 工具或工作区自动化的新产品能力默认只进入 Auto；不得以 Desk 现有页面为理由同步开发第二份。
3. Desk 例外必须先记录 Auto 缺口、桌面宿主必要性、owner、复核日期和退役条件；缺任一项不得新增。
4. 如果 Wing 已有能力，必须引用共享能力目录中的 `capabilityId` 和 export；不得复制算法，也不得把宿主事务下沉到 Wing。
5. `R1` 删除前冻结 fixture、Auto Host 回执、数据迁移和回滚点；按“入口 → 页面/route → 私有 service/test”分批退役。
6. 本仓库继续锁 Registry 精确版本，本地联调只用既有 resolver；Python 仅用于具体回归对照。
