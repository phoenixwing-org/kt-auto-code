# 工程配置与隐藏状态存储规则

状态：current

Owner：KT Auto Code maintainers

适用版本：0.6.x

最后核验：2026-07-21

## 1. 目的

本规则回答同一个问题：某个值应当写入当前工程、VS Code 用户设置，还是扩展隐藏状态。

判断标准不是“代码写起来方便”，而是该值是否属于工程属性、是否需要随工程迁移，以及是否包含本机路径、端口或个人偏好。新增 `ktAutoCode.*` 配置必须先完成分类，再选择 VS Code scope 与存储 API。

## 2. 三类状态边界

| 类别 | 含义 | 存储 | 示例 |
| --- | --- | --- | --- |
| 工程属性 | 决定当前工程如何分析、构建或运行；复制工程后应继续生效 | 当前 Workspace Folder 的 `.vscode/settings.json`，resource scope + `ConfigurationTarget.WorkspaceFolder` | 编码目标、CAA/MK 关联工程 |
| 本机默认/集成 | 依赖当前电脑安装位置、个人默认值、用户服务或端口；不应提交给团队，但用户应能查看和删除 | VS Code User Settings，machine scope | Git 审查人、Desk Tools executable、服务 endpoint、CAA 默认版本 |
| 隐藏 UI/会话状态 | 不改变工程语义；删除后只损失界面便利或短期记录 | `workspaceState`、`globalState` 或 Webview state | 折叠、筛选、游标、最近目录、临时草稿 |

复杂、可审查的团队业务配置可以使用版本化 `.phoenix/*.json`，例如 workset、搜索替换档案或未来经批准的显式 Run Target schema。它们仍是可见工程配置，不得与隐藏状态混为一类。

## 3. 0.6.0 已落地工程属性

Run Primary 的工程属性使用 VS Code 标准点号键：

```json
{
  "ktAutoCode.run.caaRelatedProjects": [
    "../PNXCaaStudy",
    "../PNXSharedWsp"
  ]
}
```

- `ktAutoCode.run.caaRelatedProjects`：提供给 MK/`mkGetPreq -p` 的关联工程目录；它不等于当前工程 cwd。
- Primary 修改关联工程时直接更新当前 Workspace Folder 设置；界面 tooltip 显示完整解析路径。
- 旧关联目录 `workspaceState` key 仅作一轮兼容读取；用户下一次明确修改后删除该工程的旧记录，不在扩展激活时静默改写项目文件。

`ktAutoCode.run.caaVersion` 不属于上述工程属性。它是 machine-scoped 的插件默认版本，写在 VS Code 用户 Settings：

```json
{
  "ktAutoCode.run.caaVersion": "21"
}
```

同一份代码可能依次编译 19/20/21 等多个版本。Primary 中每个 CAA 工程的“当前版本”只是本工作区运行选择，保存在 `workspaceState` 并优先于插件默认值；它不写入 Git。若未来需要团队锁定多版本矩阵，必须定义显式 target/profile 列表，而不是把一个可变的 `caaVersion` 冒充完整工程能力。

同一 Workspace Folder 发现多个 CAA 子工程时，关联目录写入 `ktAutoCode.run.caaProjects`，以子工程相对路径为 key；该对象仍只承载工程级关联路径，不承载当前版本选择。

现有 `ktAutoCode.encodingFix.defaultTarget/headerTarget/sourceTarget/markdownTarget` 已经属于同一工程属性类别。

## 4. 关联目录相对化与运行时解析

### 4.1 写入规则

设当前 CAA project root 为 `projectRoot`，用户选择的关联目录为 `selectedRoot`：

1. 两者先执行平台路径规范化并去重；当前工程自身不能作为自己的关联工程。
2. 使用 `path.relative(projectRoot, selectedRoot)` 生成相对路径。
3. 可相对表达时统一保存为 `/` 分隔的相对路径；允许 `../SiblingProject`，使整个父目录迁移到另一台机器后仍可解析。
4. Windows 跨盘等无法相对表达的目录才保存规范化绝对路径。该项标记为本机绑定，选择时必须经过工作区外二次确认。
5. 不把运行时解析出的绝对路径回写到设置。

### 4.2 运行前规则

每次执行前重新读取设置，逐项解析：

```text
absolute entry  → normalize(entry)
relative entry  → resolve(projectRoot, entry)
```

解析后必须重新完成：

- 绝对路径与目录存在性检查；
- 规范化去重与“不能等于当前工程”检查；
- 危险控制符/换行/shell 元字符拒绝；
- 工作区内外边界判定；工作区外目录再次进入显式预检；
- 以结构化参数传给 runner，不把目录文本直接拼成 shell command。

工程移动、父目录整体复制或换机后，解析始终以当前真实 `projectRoot` 为基准，不使用旧进程 cwd、扩展安装目录或上一次运行留下的绝对路径。

## 5. Desk Tools 统一规则

Desk Tools 已统一到 machine-scoped `ktAutoCode.deskTools.*`：

- `discoveryMode`
- `serviceEndpoint`
- `executable`
- `executableArgs`
- `nativeProviderManifest`

这些值进入 VS Code 用户 Settings，不进入 `.vscode/settings.json`。旧 `ktAutoCode.caa.externalEditor.*` 与 Auto CAD provider key 只兼容读取/迁移用户显式值；默认值不迁移，新 key 始终优先。

原因是 executable、manifest 与服务端口属于本机安装事实。把它们写进工程会泄露个人绝对路径，并让其他开发者打开工程后得到错误配置。

## 6. 隐藏状态允许范围

`workspaceState` 只允许保存当前工作区的界面便利状态，例如：

- Block/分组折叠；
- 本地筛选与布局比例；
- 工作区内最近目录的相对路径；
- 最近运行展示记录；
- 可安全丢弃的游标或短期 session 标识。

`globalState` 只允许保存无需由用户审查的跨工作区界面便利状态，例如用户主动选择过的工作区外最近目录。Git 默认审查人/候选与固定的外部仓库都必须可在设置中删除，因此分别写入 machine-scoped `ktAutoCode.git.reviewers` 和 `ktAutoCode.git.repositories`，不再长期保存在隐藏状态。不得把 token、环境值、源码内容或团队工程规则写入其中。

以下内容禁止只存在隐藏状态：关联工程、编码目标、团队固定的 target/profile、可共享运行参数，以及任何删除缓存后会改变工程固有构建/分析规则的值。当前 CAA 版本选择可以是隐藏状态，因为它只是从多个可运行版本中选择本次目标；机器默认版本另存 User Settings。

## 7. 读取与迁移优先级

工程属性的推荐优先级：

```text
当前 Workspace Folder 显式设置
> 经批准的版本化工程配置
> 一轮兼容读取的旧值
> 当前进程/系统环境
> 产品建议值
```

迁移遵守以下原则：

- 不在扩展激活时无提示修改 `.vscode/settings.json`；
- 用户在 Primary/Settings 中明确修改时，写新位置并清除同一工程对应的旧隐藏值；
- 机器级旧值只能迁入 User Settings，不能迁入工程；
- 相对路径迁移前必须知道可靠的 project root；无法证明时保留旧读取并要求用户重新选择；
- 至少保留一个版本的兼容读取和迁移测试，删除旧 key 另立版本决策。

### 分阶段计划

1. **0.6.0 收口**：完成 Run 关联工程属性、相对路径 round-trip、旧状态兼容、CAA 默认/当前选择分层和 VSIX/Extension Host 验证。
2. **既有 key 审计**：为所有 `contributes.configuration.properties` 生成 scope 清单，逐项标注工程、机器、用户 UI 或废弃；检查所有 `ConfigurationTarget` 调用与 schema 一致。
3. **显式迁移**：只对确认属于工程属性的旧 key设计兼容读取、用户触发写入、回滚与点检；一个领域一个迁移，不做无关批量改写。
4. **旧 key 清理**：至少跨一个兼容版本后，根据使用证据删除 legacy state/setting；发布说明列出迁移路径。
5. **持续门禁**：增加测试，拒绝 durable project setting 写 `workspaceState`、machine setting 写 Workspace Folder，以及工程路径无理由保存绝对值。

## 9. 验收清单

- 用户 Settings 的 `ktAutoCode.run.caaVersion` 作为本机默认；Primary 切换当前版本后只更新本工作区选择，不修改 `.vscode/settings.json`，扩展重载后仍保持选择。
- 选择同一父目录中的关联工程后，只保存相对路径；把整个父目录复制到新位置后预检解析到新绝对路径。
- 运行前日志只显示脱敏后的工作区路径，不打印个人根目录或全部环境值。
- 删除旧 `workspaceState` 不改变已写入工程设置的实际运行参数。
- 选择 Windows 跨盘目录时明确显示其本机绑定风险；另一台机器路径不存在时 fail closed。
- Desk Tools 本机路径与端口只出现在 User Settings/自动注册中，Git diff 不出现这些值。
- Git 默认审查人只出现在机器级 `ktAutoCode.git.reviewers`；清空该设置后不再从已迁移的隐藏状态恢复。
- Git“我的仓库”只出现在机器级 `ktAutoCode.git.repositories`；清空后不再列出外部仓库。工作区内目录缓存不保存机器绝对路径，commit 内容不写入任何 Settings/state。
- 扫描 `workspaceState.update()` 与 `globalState.update()`，没有 durable 工程属性新增。
