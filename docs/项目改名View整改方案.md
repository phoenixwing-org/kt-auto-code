# “项目改名”View 整改方案

状态：current（0.8.1 已实现；人工 Windows 矩阵待完成）

Owner：KT Auto Code maintainers

适用版本：0.8.x 后续候选

最后核验：2026-09-05

> 本文已作为 `0.8.1` 的职责迁移、布局与写盘前 Diff 实施依据。当前行为真源仍是[搜索替换](./搜索替换.md)；第二阶段结构化规则和正则能力不在本候选内。文中“目录齿轮”是当时外壳记录，已由 2026-09-05 的[当前 UI 规则](./前端开发规则.md)取代。

## 1. 整改目标

本轮不重做项目改名引擎，目标是把已经存在但分散在 Primary **搜索替换**中的复杂能力迁入独立 Editor View，并改善宽屏信息密度：

1. 对外名称统一为 **项目改名**；Primary 入口显示在当前工具 Header 的标题与关闭按钮之间。
2. Primary 保留一次性的精确搜索替换和一组显式“常用变形”；复杂前缀、档案、CAA/自定义规则和长任务都进入独立 View。
3. 规则档案、源/目标前缀、常用规则、CAA 规则和自定义规则在同一可折叠 Block 内完成。
4. 名称输入和规则输入严格上下对齐。
5. 命中结果默认单行多列，结果区内部滚动，最右侧 **打开**列固定。
6. 写盘前以 VS Code 原生 Diff Editor 展示冻结原文与计划结果；写盘后继续使用原生源代码管理和 Git diff 验收，不在 Webview 内复制差异渲染器。
7. 保持现有只读分析、冻结计划、冲突/漂移门禁、显式确认、完成复扫和单任务绑定语义。

## 2. 产品职责冻结

| 能力 | Primary：搜索替换 | Editor View：项目改名 |
| --- | --- | --- |
| 工作目录选择 | 保留 | 创建任务时绑定；任务中不可随意切换 |
| 单组 `搜索 → 替换` | 保留 | 作为项目原名/目标名输入 |
| 文本、文件名、文件夹名范围 | 保留 | 固定同时分析三类，逐项报告风险 |
| ASCII 文件目标默认编码 | 保留 | 第一阶段继续使用已验证默认值；后续若开放必须显式显示 |
| 规则档案 | 移出 | 迁入“改名方案”Block |
| 源前缀、目标前缀 | 移出 | 迁入“改名方案”Block |
| 自定义、常用、CAA 关联规则 | 移出 | 迁入“改名方案”Block，复用现有 Picker |
| 常用名称形态派生 | 可选“大驼峰 / 小写 / 全大写 / 空格 / 短横线 / 下划线”，提交前显示映射摘要 | Display、kebab、snake、camel、Pascal、UPPER_SNAKE 显式列出并逐条启停 |
| 最近改名记录 | 用户级最近 50 组成对记录 | 共用用户级记录；另按分析目录保留最近 20 个完整项目方案 |
| 智能短写法候选 | 不提供 | 分析后提示，默认不加入；加入后默认不启用 |
| 根目录改名 | 不提供 TODO/写盘入口 | 仅非当前工作区根目录满足门禁时受控执行 |
| 长任务取消、分页、风险分类 | 不提供 | 保留 |
| 写盘前内容差异 | 不提供 | **预览差异…**和文本结果行 **对比**打开原生 Diff Editor |
| 执行后 Git 验收 | 结果提示即可 | 保留 **Git 对比**，打开 VS Code 原生 SCM |

Primary 外层仍严格保持 `Toolbar Strip → 目录 → 当前工具` 三段结构。本整改只修改“搜索替换”工具内部内容，不增加第四段、不改变固定目录行，也不改变当前工具的关闭语义；Header 与设置入口采用当前 UI 规则。

## 3. 命名与入口

- Primary Header 上下文按钮：**项目改名**
- Editor Tab、View header：**项目改名**
- 命令面板：**KT Auto Code：项目改名**
- 第一块：**改名方案**
- 第二块：**总览**
- 第三块：**命中与风险**
- 命令 ID、View type 等稳定内部标识继续保留 `projectRenameAnalysis`，避免仅因文案调整破坏调用方。

入口位于 Primary **搜索替换**的当前工具 Header。点击后使用当前目录创建任务，并带入已填写的 Source、Target 和启用的常用变形规则；这些内容只形成草稿，不自动分析。已有 View 时再次点击只聚焦，不用新目录或表单覆盖旧任务。需要处理另一目录时，先关闭当前 View，再从 Primary 创建新任务。

## 4. 固定 Header

Header 参考“头文件引用修正”的规则：固定在 View 顶部，背景、边框、按钮高度和间距使用 VS Code/Wing 已有 token，不随结果表滚走。

建议顺序：

```text
项目改名  /完整/绑定/目录      [选择目录…] [分析] [取消] [预览差异…] [执行改名] [Git 对比] [结束任务]
```

- **选择目录…**：仅任务没有任何目录来源时显示；绑定后隐藏。
- **分析**：始终只读；已有报告时文案可变为“重新分析”。
- **取消**：只在扫描中显示，不把取消解释为关闭任务。
- **预览差异…**：分析完成且存在文本变更时启用；不写磁盘，打开本报告冻结内容的原生 Diff Editor。
- **执行改名**：只执行当前冻结报告；规则或名称变化后立即禁用。
- **Git 对比**：只有本任务确实成功写盘后启用，用于查看磁盘上的真实 Git 改动。
- **结束任务**：只有“目标达到”或“本次冻结计划全部完成”之一成立时启用。

目录不是可编辑输入框。完整路径显示在 tooltip；提示中明确“当前任务已绑定目录，如需更换请关闭 View 后重新创建”。

## 5. “改名方案”Block

该 Block 本身可折叠，替代 Primary 中“展开/收起关联规则”的局部开关。折叠只隐藏内容，不清空草稿、档案、规则或报告。

当前第一阶段固定处理文本、文件名和文件夹名，默认编码为 UTF-8；该固定范围以低强调摘要显示在 Block Header。它不继承 Primary 临时取消的范围勾选或 GBK 选择，避免界面没有控件时仍暗中改变执行范围。

内容顺序固定为：

1. Block Header 中的最近输入/项目方案下拉、删除所选、清空、规则数、固定范围摘要、**全不选 / 全选**与 **派生**。
2. 原项目名、目标项目名。
3. 源前缀、目标前缀。
4. 默认折叠的项目档案区；其 Header 提供紧凑的 **+ 规则 / 常用 / CAA** 入口，展开后显示档案下拉、档案名称与 **保存**。
5. 六种派生规则和显式关联规则。
6. 分析后出现的相关短写法候选。

### 5.1 规则档案

- 继续使用项目内 `.phoenix/search-replace.json`，不新建第二种档案格式。
- 下拉只载入草稿，不自动分析、不自动写盘。
- **保存规则**只在档案名、原名和目标名完整时启用；同名按既有档案 ID 更新。
- 已损坏的 JSON 拒绝覆盖并显示错误；文件不存在只显示空档案列表。
- 从旧 Primary 档案载入时，保留母规则、前缀和关联规则；旧 `preserveCase` 字段只为兼容解析保留，不再驱动隐式扩展。
- 单个 View 最多接受 32 条规则，其中六条为标准形态；旧档案超出上限时明确阻止载入并要求精简，不静默截断、覆盖或丢失。

### 5.2 “同时匹配全大写”整改

旧 `0.8.0` Primary 虽显示“同时匹配全大写”，但 `workspaceRename.rulesForOptions()` 固定调用不扩展大小写的规则解析，勾选值不会改变命中结果。这是无效控件，不能继续向用户暗示有效。

整改决策：

- 从 Primary 删除该复选框。
- 不把它迁入“项目改名”View。
- View 中保留可见、可编辑、可启停的 `UPPER_SNAKE` 规则。
- Display、camel、Pascal 等形态也各自显式列出；不再用一个含糊开关猜测所有混合大小写。
- Header 的 **全不选 / 全选**一次控制当前全部有效规则；固定六种形态右侧不显示无效删除按钮，自定义规则才显示可点击的 **×**。
- 档案中的旧字段继续可读，保存新档案时固定为 `false`，避免旧配置解析失败。

### 5.3 关联规则 Picker

复用现有 `ktc-associated-rule-picker` Web Component 和 Host 候选算法：

- **+ 自定义规则**：打开同一 Picker，并始终提供 Source/Target 空白输入。
- **常用规则**：展示空格写法和前缀规则候选。
- **CAA 规则**：展示完整名称及末词段 I/E 候选。
- Picker 只显示和回传选择；候选生成、去重、档案保存、分析和写盘仍由 Host 负责。
- 同一 Source 不自动覆盖既有规则；自动候选必须在规则列表中可见。
- 分析得到的 `open-issue`、稳定 URL、协议或领域前缀候选仍默认关闭，不能因“智能匹配”直接进入写盘计划。

### 5.4 最近记录与恢复

- 最近输入采用成对的 `Source → Target` 记录，避免两个独立历史列表错配；用户级最多 50 组，按最近使用倒序，同一对精确去重。
- Primary 和“项目改名”View 共用这 50 组记录；只有成功完成搜索/分析的完整 Source/Target 才进入历史。
- “项目改名”另按绑定的分析目录保留最近 20 个完整方案，包括原名、目标名、源/目标前缀和当前多变体规则；选择后只恢复草稿，必须重新分析。
- 自动历史只写 VS Code 本机状态，不自动创建或修改项目文件，不污染 Git。
- **保存规则**仍是唯一把可共享档案写入项目 `.phoenix/search-replace.json` 的显式动作；自动历史和项目档案不能混为一谈。
- 最近记录支持删除当前项；清空全部本机历史必须二次确认，并明确说明项目共享规则档案不受影响。
- 最近记录、删除、清空与派生收进“改名方案”Header；三种规则入口收进默认折叠的“项目档案”Header，并缩短为 **+ 规则 / 常用 / CAA**。两个 Header 内的完整含义由 tooltip 和无障碍名称保留，内容区不再为快捷操作单独占一整行。

## 6. 上下对齐与宽屏布局

原项目名/目标项目名、源前缀/目标前缀以及每条规则共用同一套六列栅格：

```text
[启用] [形态/来源] [Source 输入] [→] [Target 输入] [删除]
                    ↑                    ↑
                 原项目名             目标项目名
                 源前缀               目标前缀
```

宽屏建议列定义：

```css
24px minmax(96px, 140px) minmax(160px, 1fr) 20px minmax(160px, 1fr) 28px
```

名称和前缀行在第一、二、四、六列保留空位，使上方输入框边界与规则 Source/Target 输入严格对齐。不要让上方输入占满左右各 50%，下方输入却因“启用/形态”突然缩进。

在窄宽度下：

- 名称和前缀退化为两列，必要时再退化为单列。
- 规则保留启用和形态；Target 可落到第二行。
- 不压缩到遮挡复选框、删除按钮或输入值。
- 响应式变化不得改变规则顺序、启用状态或报告身份。

## 7. 命中结果：单行多列与固定操作列

宽屏默认一条结果只占一行：

```text
风险 | 分类 | 来源（文件名 · 相对路径） | 目标 / 位置预览 | 命中 | 操作
```

行为要求：

- 默认行高约 32～36px，单元格不主动换行。
- “来源”使用一个连续可伸缩标签：`文件名 · 相对路径`；整列省略，不为文件名和路径预留两套固定宽度。
- “目标 / 位置预览”对文本显示行号摘要和 `Source → Target ×N`；对文件/目录显示计划目标。
- 所有被省略内容必须在 `title`/`aria-label` 中提供完整值。
- 表格放在结果 Block 内部横向滚动；页面本身不因宽表形成常规横向滚动。
- 表头固定在结果区顶部。
- 最右 **操作**列使用 sticky 固定在右侧，横向滚动时 **打开**始终可操作；文本内容行同时提供 **对比**，文件名和目录名行只提供 **打开**。该列有独立背景和左边界，避免覆盖内容后无法辨认。
- 分页仍由 Host 全量报告提供，每次最多 200 行；压缩行高不改变 20,000 项安全上限。

## 8. 写盘前差异、打开文件与写盘后 Git 对比

### 8.1 写盘前差异是本轮核心能力

Git 只能比较磁盘或索引中真实存在的变化，不能承担尚未落盘的计划预览。写盘前差异采用 VS Code 原生 Diff Editor，但两侧由项目改名 Host 提供只读虚拟文档：

- 左侧是本报告冻结的原始文本。
- 右侧是按当前已启用精确规则计算出的计划文本。
- Host 通过受控的 `TextDocumentContentProvider` 提供内容，并调用 `vscode.diff`；Webview 不渲染 diff、不持有完整文件正文。
- 虚拟 URI 只携带报告 ID、文件身份和左右侧标记，不把正文、绝对路径或任意命令塞入 URI。
- 点击 **预览差异…**时可先选择一个发生文本变化的文件；点击文本结果行 **对比**时直接打开该文件的差异。
- **打开**仍定位真实文件和命中位置，和 **对比**是两个独立动作。

差异必须绑定冻结报告。打开前 Host 重新读取实际文件并验证内容指纹；文件已漂移时不生成新的临时计划，而是提示“请重新分析”。规则、名称、前缀或启用状态变化后，旧差异入口和 **执行改名**同时失效。

第一阶段可以在用户请求某个文件时懒生成右侧计划文本，避免把大型仓库全部正文长期复制到 Webview 或内存；但生成必须使用报告中的规则、编码和已验证原文，不能读取当前表单重新推导另一份结果。

文件名和目录名没有可供文本 Diff Editor 展示的正文。它们继续在结果表和总览中显示明确的 `源路径 → 目标路径`，路径冲突和大小写-only 临时路径仍由冻结计划检查。不得为了“统一 diff”先在磁盘上制造临时 rename。

写盘前差异不依赖 Git，因此外部非 Git 目录也能预览；这不改变非 Git 目录缺少写盘后恢复能力的警告。

### 8.2 写盘后

- **Git 对比**继续调用 VS Code 原生源代码管理入口，让用户在 Git 扩展中逐文件打开真实磁盘 diff。
- 不在 Webview 中读取 `.git` 对象、渲染 diff 或重新实现暂存/撤销。
- 非 Git 目录执行前已经明确提示无法依赖 Git 恢复；此时按钮不得暗示存在 Git 对比。
- 若 Git 扩展不可用，显示明确提示并保留普通“打开”能力。
- 自动打开 SCM 不等于自动暂存、提交、恢复或丢弃更改。

写盘前 **预览差异**与写盘后 **Git 对比**不能合并为同一含糊按钮：前者比较冻结计划且不改磁盘，后者只检查实际完成的工作区变化。

## 9. 状态与安全边界

- 一个 View 只拥有一个目录、一个规则草稿和一个冻结报告。
- 编辑名称、前缀、规则值或启用状态后，旧报告立即变脏，**执行改名**禁用。
- 写盘前差异只读取冻结报告；不能把 Diff Editor 中的右侧虚拟文档编辑结果反向写入计划。
- 载入或保存档案会更新当前草稿；若草稿与报告不同，必须清空或作废报告。
- 规则、路径和报告 ID 从 Webview 进入 Host 时仍做长度、枚举、数量和控制字符校验。
- 智能候选、协议短名和 `open-issue` 类契约默认不修改。
- 保持 symlink、二进制、大文件、Ignore、点目录、编码、Git dirty、冲突、漂移、分页和结果上限门禁。
- 根目录改名继续只允许同一父目录下单层 rename；当前工作区根目录或包含工作区根的父目录只提示、不执行。

## 10. 实施切口

文档确认后按以下顺序恢复代码工作，禁止一次性混入第二阶段正则：

1. 先用 characterization test 锁定 Primary 只剩简单搜索替换、按钮展开的显式常用变形 Block、最近记录和 Header **项目改名**入口。
2. 迁移档案、前缀和 Picker 消息到项目改名 Host/View；验证旧档案兼容。
3. 为精确文本计划建立只读虚拟文档 Provider；冻结报告校验通过后用原生 `vscode.diff` 打开写盘前差异。
4. 修正统一命名和固定 Header；区分 **预览差异…**与成功写盘后的 **Git 对比**。
5. 实施共享栅格上下对齐。
6. 改造结果表为单行多列、内部横向滚动、固定操作列；文本行保留 **对比 / 打开**。
7. 更新当前行为文档，删除 Primary 旧交互描述和无效全大写说明。
8. 完成 typecheck、定向测试、全量 CI、本地 Wing `0.7.2` 集成门禁和真实 VS Code 手工验收。
