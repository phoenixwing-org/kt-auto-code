# KT Auto Code 0.8.2 编译工具发布归档

状态：Windows 发布候选。

平台边界：Windows 是 PowerShell 5.1、MSVC 与 CAA 的实际构建和发布验证平台，CAA 编译仅支持 Windows。macOS/Linux 保留完整 View 入口，可对本机 POSIX 路径进行配置编辑、目录/Git 探测、预检和 PS1 生成，以 Extension Development Host 完成盲开发；非 Windows 运行入口会提示平台限制，但不会被隐藏。载入 Windows/UNC 配置时不触碰本机文件系统，Root 不直接同步，导出时改由用户选择本机位置。

## 发布内容

- 代码辅助增加编译工具 View，使用原生 `<details>/<summary>` 内容块。
- 使用 schema 2 项目表统一管理仓库与构建目录，支持多选目录、当前目录探测、相对路径保存和逐行探测、运行、移除。
- 显示仓库分支、Commit、Origin 和工作区状态；Root、3rdParty 及每个项目可独立决定是否更新和目标分支。
- 自动识别 Git、CMake、CAA、`linkCAA.ps1` 与 `linkOut`，并预选适用操作。
- 仓库更新与 Export 内部并行；支持 CMake → CAA 分阶段执行，或 CMake 与 CAA 全并行执行。
- 项目脚本从自身目录无参数运行；单项失败不阻断其他任务，最终统一汇总。
- 插件固化 `scripts/auto-build/Invoke-AutoBuild.ps1`，可显式同步到 Root，也可导出工作目录下的 `Invoke-AutoBuild.local.ps1` 脱离 UI 执行。
- Run 增加 build、objects、`*.obj` 快捷清理；编译 View 增加 Root 前缀头文件、DLL、LIB 清理，均跳过 `.git`。
- PowerShell 子进程和导出脚本兼容 Windows PowerShell 5.1 与 UTF-8 输出。
- Windows 盘符、UNC 与 POSIX 路径使用与宿主系统无关的路径语义；macOS/Linux 开发检查或保存配置时不会再把 `E:/...` 错写到当前仓库目录下。
- Root、3rdParty、工作目录和独立 PowerShell 脚本统一拒绝不完/相对路径与错误文件类型；Windows 执行拒绝 POSIX 目标。清理在任何 Git/CMake 副作用前拒绝文件系统根、UNC 共享根，并扫描路径链和待删除树；遇到 junction、符号链接或其他 reparse point 即安全停止。
- 构建与仓库 Job 均要求“终态已完成 + 恰好一个显式结果”；异常终止、结果丢失或重复都按失败返回。

## 发布验证

- 项目表、JSON 保存读取、独立分支更新、脚本同步、日志项目名、顺序/并行编译以及导出 PS1 已完成 Windows 手工测试。
- 导出脚本实测完成 3 个 Export 与 3 个 CMake，退出码均为 0。
