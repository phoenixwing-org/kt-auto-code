# KT Auto Code 0.8.3 开发计划

状态：current

Owner：KT Auto Code maintainers

最后核验：2026-09-05

## 基线

- `v0.8.3` 是本机下一发布目标；`0.8.2` 保留，本分支不抢做、不覆盖。
- `0.8.2` 正在实现批量编译，并修改代码辅助及其 Tree；本计划不跟踪、不复刻、不要求对齐该版本的中间状态。
- `0.8.2` 发布并进入 `develop` 后再整体合入，届时统一处理冲突、运行全量门禁并把版本号升级到 `0.8.3`。
- 新功能继续以 Auto Code 为唯一实现端；Wing 只优先承载 UI-neutral 纯算法，不同步扩建 Desk 重复页面。
- 试行目标线规则：每轮以仓库主目录当前检出的版本号分支为目标发布线；`develop` 只作开发/测试基线提示。提交、合并、打包和发布前必须重新核对实际分支、版本号、工作区状态与用户当次发布意图。
- 后续进行中开发 worktree 统一放在共享 Phoenix 根目录的 `worktrees/` 下，不新建隐藏 `.worktrees`。

## 简单开发列表

1. [ ] **以后整体合入 0.8.2**：等其发布并进入 `develop` 后一次性同步，核对批量编译、代码辅助 Tree、命令、设置、状态迁移、manifest、lockfile 和文档；现在不处理，也不零散复制提交。
2. [x] **升级架构门禁**：`verify-import-boundaries.mjs` 已使用 TypeScript AST 解析 import/export/dynamic import、调用与声明，并沿相对 import graph 检查 pure core；View 继续禁止直接文件写入。项目改名结构化 scanner 也已纳入 pure graph，当前门禁覆盖 188 个源码文件、26 个 pure graph 和 20 个 View root。
3. [ ] **项目改名第二阶段 A**：聚焦与输入词段相关的批量只读发现，包括大小写、连接符和 Web / CAA / C++ 通用前缀；受限纯算法及 Web/CAA 两个实仓只读烟测已完成，View/独立“探测”入口仍待评审。另行设计写盘后的“遗漏探测”；普通单文件正则继续使用 VS Code，不在这里复制，未评审完成前不开放动态写盘。
4. [ ] **Codegen 未闭合诊断**：在 Wing 提供结构化 `blockKey/classId/boundary` 后，增加“未闭合”展示、定位和显式复制 END，不自动修改源码。

[ ] **0.8.3 质量收口**：写盘前 Diff 的 UTF-8 BOM/GBK 字节不落盘、立即取消与迟到结果隔离、跨平台非法路径组件预检、280/360/560/760px 响应式几何、Node 22 `release:check`、真实 Extension Host 基础烟测、Controller/Analyzer 取消与暂存 VSIX 安装/版本枚举已完成；已增加必须显式提供版本与完整 commit OID 的 `pnpm release:preflight`，以及核对 Registry 打包来源、同一 VSIX SHA 和既有 verifier 证据后才写入本地 JSON 的 `pnpm release:receipt`。二者均不嵌入无参 CI，不改版本或执行远端发布。仍需完成项目改名深浅色/高对比人工观感、真实取消按钮点击、Windows 长路径和最终已安装 VSIX 激活点检，最后在合入正式 0.8.2 后更新版本、CHANGELOG 状态并生成最终回执。

## 本版本暂不做

- 不恢复已暂停的 Workset 删除、多目录范围和 ShellBlock 等价提炼。
- `0.8.2` 整体合入前不修改批量编译、代码辅助、内部 Tree 及其共享 Shell 接线；当前只选择与这些文件隔离的开发项。
- 不开放裸正则写盘，不做结构化文件名/目录名动态改名。
- 不主动升级 Wing，不修改或复制 Desk Tools 的产品实现。
- Desk 退役由 Desk 仓执行，不属于 0.8.3 功能开发；Auto 只保留能力矩阵，只有发现共同 fixture 或契约缺口时才另立小任务。
