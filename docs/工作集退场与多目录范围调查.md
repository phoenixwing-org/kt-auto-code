# 工作集退场与多目录范围调查

状态：current（仅“隐藏并停用工作集”已确认；多目录方案暂缓）

Owner：KT Auto Code maintainers

适用版本：0.6.x

最后核验：2026-08-08

## 1. 结论

停止扩展“工作集”产品概念，并从日常界面隐藏、禁用相关写入。多数项目已经存在 `.phoenix/worksets.json`，但没有形成真实、稳定的使用习惯；本轮不再尝试解释或扩展它。

不直接删除 `.phoenix/worksets.json` 和解析代码：已有文件原样保留，不自动打开、读取到新界面、迁移、覆盖或删除。旧工作集的 include/exclude glob 和精确文件清单不能安全、无损地自动转换为目录集合。

“多目录工作范围”只作为后续候选，不进入本轮实现。当前继续使用一个明确工作目录；等出现真实的多目录任务后，再以独立计划验证是否值得增加。

## 2. 当前实现调查

当前工作集 schema 包含：

```text
命名工作集
├─ roots[]：一个或多个相对根目录
├─ include[]：包含 glob，也会累积精确文件路径
└─ exclude[]：排除 glob
```

当前仓库自己的 `.phoenix/worksets.json` 已在默认工作集中累积大量文档、脚本、源码和 fixture 的精确路径。这类结果回收虽然技术上可用，但会让工程配置持续膨胀，用户也难以从界面判断最终范围。

消费者审计：

| 消费者 | 当前用途 | 多目录能否替代 | 迁移要点 |
| --- | --- | --- | --- |
| 头文件 ASCII | workset 展开为精确文件集后扫描 | 可以 | 对每个目录扫描头文件并合并去重 |
| 文件编码 | workset 展开为精确文件集后扫描/转码 | 可以 | 对每个目录执行同一编码策略 |
| C++ 成员排序 | 全工作区候选再与 workset 文件集求交 | 可以 | 改为按目录收集候选，保留快照与确认 |
| UUID 替换 | 全工作区候选再与 workset 文件集求交 | 可以 | 按目录扫描并用 canonical path 去重 |
| CAA UI | 全工作区 `.CATDlg` 再与 workset 求交 | 可以 | 按目录收集 `.CATDlg` |
| Codegen | scope ID 参与候选索引缓存 | 可以，但需改缓存身份 | 用规范化目录列表 fingerprint 替代 workset ID |
| 搜索替换 | 已不消费 workset，只保留“加入工作集”旧命令 | 已经由目录替代 | 删除结果回收入口与命令 |
| “加入工作集” | 将扫描结果写为精确 include 路径 | 不保留 | 不新增“加入目录集”；结果不是范围配置 |

`workspaceFileScopeId` 目前仍穿过 `ToolRunContext` 和部分工具兼容管线，但 Host 固定传入 `workspace`，不会读取现有 `.phoenix/worksets.json`。这部分属于后续可删除的类型/解析兼容层，不是继续保留工作集 UI 的理由。

## 3. 多目录候选（暂缓）

- 用户直接看到和理解实际根目录，不需要学习 `roots/include/exclude` 三层规则。
- 文件类型由各工具负责，排除规则由统一 Ignore 负责，范围职责不再重叠。
- 多根 VS Code 工作区、同级 Git 仓库和外部目录可以使用同一个选择模型。
- 当前选择保存在工作区 UI 状态，不会把一次性扫描结果持续写入项目配置。
- 目录列表可以稳定显示、删除、拖动或重新选择，最终执行范围容易确认。

上述优势只是方向判断，不代表当前需求已确定。多目录也不是工作集改名：如果以后实施，不提供命名集合、include glob、exclude glob、精确文件回收和“加入工作集”。如果未来出现确切的长期团队范围需求，应重新设计显式 profile schema，而不是恢复旧工作集。

## 4. 多目录候选模型（不在本期实现）

```ts
interface KtcWorkingDirectorySelectionV1 {
  roots: Array<{
    path: string;
    kind: "workspace-relative" | "absolute";
  }>;
  pluginIgnoreEnabled: boolean;
}
```

以下交互只用于未来讨论，本期不得据此增加界面：

- 默认选择当前 Workspace Folder；多根工作区下默认使用当前活动文件所属根，否则使用首根。
- 文件夹按钮允许一次选择一个或多个目录，随后可继续追加。
- 下拉/选择器列出多根工作区、一级子目录、优先标识的 Git 子目录和最近外部目录。
- 已选择多个目录时，第二个 Block 以紧凑标签显示；每项可移除，“清空”恢复默认当前目录。
- 目录可以位于工作区内部或外部；内部优先保存相对路径，外部保存本机绝对路径。
- 执行前 canonicalize；同一路径只保留一次，父目录已覆盖子目录时去除冗余子目录。
- 不允许选择文件；精确文件处理继续由工具结果列表的 checkbox 负责，不进入范围模型。

状态归属：

- 当前目录集合与“插件内置 / Git / 自定义 Ignore”三个开关放 `workspaceState`。
- 最近外部目录放 `globalState`。
- 不写 `.vscode/settings.json`，不产生新的 `.phoenix/*.json`。

## 5. 当前单目录 Ignore 组合

当前唯一选择根计算过滤规则：

1. “插件 Ignore”默认开启：应用 Phoenix Auto 内置生成物/缓存目录。
2. “Git Ignore”默认开启：应用最近仓库根 `.gitignore`（Phoenix Wing 支持的规则子集）。
3. “自定义 Ignore”开启：再叠加该选择根对应的 `.phoenix/.ignore`；默认关闭且空内容不建文件。
4. 工具文件类型和 symlink 等安全边界最后求交。

本期不递归发现“非 Git 聚合父目录”下面的多个仓库。用户从目录下拉切换到一个具体 Git 子目录后，再使用该仓库的 Ignore。

## 6. 分阶段退场

### 当前阶段：隐藏与冻结

- 移除 View Title 的“工作集”入口、各工具“加入工作集”和范围下拉中的工作集选项。
- 不再创建新的 `.phoenix/worksets.json`，不再写入精确文件路径。
- 保留用户文件和解析器；移除命令贡献与日常入口，旧 Webview 消息只做无读写的兼容忽略。
- 冻结 Wing workset schema；Auto 不增加新字段或新消费者。
- 保留当前单工作目录模型，不因为停用工作集立即增加多目录选择。

### 后续候选：消费者迁移

- 等产品范围明确后，再决定 `ToolRunContext.workspaceFileScopeId` 是直接删除并统一为单目录，还是替换为多目录上下文。
- 在此决定前，不新增目录列表、目录标签、拖动目录或目录集合 fingerprint。

### 后续候选：删除兼容层

- 确认源码、命令、测试、文档和真实工作区不再消费 workset。
- 删除 `worksets.ts`、工作集消息、状态、命令贡献和专属测试。
- 删除 Auto 对 Wing workset parser 的直接消费；不要求 Wing 同步删除公共 API。
- 对仓库内已有 `.phoenix/worksets.json` 单独决定删除或历史归档，不由插件自动操作用户文件。

## 7. 风险与边界

- 多目录可能重复包含同一文件，必须以 canonical URI 去重后再扫描和计数。
- 跨目录写盘仍需逐文件快照验证；不能因为根列表已验证就跳过写盘前检查。
- 外部目录不得读取当前工作区的项目 Ignore 或项目配置。
- 旧 workset 的精确文件规则不会自动转换；这是有意的产品简化，不应伪装为无损迁移。
- 多目录数量需要合理上限和摘要显示，避免把 UI 重新做成另一种复杂工作集。

## 8. 本期验收

- 日常界面不再出现“工作集”“加入工作集”或 `.phoenix/worksets.json` 编辑入口。
- 用户继续选择一个明确的内部或外部工作目录；界面不出现尚未确认的多目录操作。
- 默认使用插件内置与当前仓库 Git Ignore；三个来源开关彼此独立，自定义开关只控制当前扫描根 `.phoenix/.ignore`。
- 尚未接入公共工作目录的工具不得因隐藏工作集而悄悄改变或扩大扫描范围；迁移需另行点检。
- 用户已有 `.phoenix/worksets.json` 在整个迁移期间不被自动删除、覆盖或改写。
