# v0.9.0 Primary 迁移需求归档

状态：current

Owner：KT Auto Code maintainers

适用版本：0.9.0

最后核验：2026-09-08

本文记录 2026-09-08 本轮连续 UI 讨论形成的明确要求、实施状态和保留边界。它用于防止对话中的按钮、布局和安全语义在后续迭代中丢失；锁定的三段 Primary 外壳仍以 `AGENTS.md` 和《前端开发规则》为准。

## 通用迁移原则

- [x] 第一优先是 Preview 复现 Primary 效果，用户确认后再迁入正式插件。
- [x] 有 Right View 的工具同时制作 Primary 和 Right 效果；统计摘要与主要目录选择优先放 Primary，完整表格、长结果和复杂编辑留 Right。
- [x] Primary 内部采用与编译工具一致的满宽相邻分隔，不额外制造卡片左右 gap。
- [x] 局部按钮操作不得重建整个任务真源或清空其他行状态；只有明确的全量新轮次可以重置完整结果。
- [x] 未明确要求删除的正式功能不得因效果图未画出而删除；缺失项必须登记。
- [x] “代码辅助”本轮不再调整。

## 项目改名

- [x] 分析目录放 Primary 第一行，正文省略“分析目录”前缀，以 `目录名 @ 父路径` 显示，完整路径放 tooltip / aria。
- [x] 操作按钮区位于目录后、总览前；短文案采用“查看 / 取消 / 对比 / 改根目录…”。Right Header 不重复 Git 对比。
- [x] 总览统计移到 Primary 并位于项目档案前；Right 删除重复的“分析完成”提示。
- [x] 项目档案/方案管理移到 Primary；方案列表、共享档案和档案名称保持真实 Controller 能力。
- [x] 改名方案 Right 使用表格布局：启用、类型、原来、目标、操作五列；项目名和前缀是前两行，Display/kebab-case/PascalCase 等派生规则继续按行显示。
- [x] `+规则 / 常用 / CAA` 属于改名方案 Block，放入该 Block Header；不是第二个“最近方案”下拉。
- [x] 原有本机方案删除与清空能力未删除，改由 `PnwCombo` 菜单内每行 `×` 和底部“全部清空”承载；共享档案不可在此删除。
- [x] Git 工作区有未提交或未跟踪改动时只警告并要求确认，不再直接阻止写盘。
- [x] 气泡、警告和失败信息同时进入原生 Output 日志；写盘前差异冻结不一致仍保持安全拒绝，不伪装成成功。
- [x] 本轮修改说明、明确删除项和保留但未映射项由《项目改名 View 整改方案》和本归档共同记录。

## 搜索替换

- [x] Preview 以正式功能为基线融合，而不是用任一旧稿覆盖另一侧。
- [x] 最近改名选择保留；外部 `×` /“清空”取消，改用 `PnwCombo` 内每行 `×` 和底部“全部清空”。
- [x] “项目改名”保留在当前辅助按钮区，使用 Primary 蓝色按钮、明确焦点边框和加粗文字突出，不改锁定外壳 Header 插槽。
- [x] 常用变形、范围、编码和 Ignore 入口继续保留；未明确删除的原有按钮和功能继续列入点检。

## 自动代码

- [x] 原来难辨认的一排图标动作改为 2–3 字文本按钮（打开、导入、应用、刷新/取消、扫描）。
- [x] 自动代码图标统一为 Element Plus Operation 形态；媒体图标、Preview、Current Tool 和 Open Items 使用同一轮廓。

## 编译工具与清理

- [x] Primary 顺序为当前配置、执行、维护、工程环境；Right 只适配已迁入 Primary 的重复入口，不大改既有功能面板。
- [x] Right 顶部旧 JSON 工具条、自动 clean 和 Root 编排脚本行已清理；配置、脚本管理和任务业务仍保留在 Controller。
- [x] “Root 编排脚本”改名为“脚本”，眉毛为“ROOT/tools 与 ROOT/sample 同步”。点击直接新建或覆盖，不再询问覆盖。
- [x] 同步文件固定为 `Invoke-AutoBuild.ps1`、`Functions-Cleanup.ps1` 到 `ROOT/tools`，以及 `cleanup.ps1`、`cleanup.yaml` 到 `ROOT/sample`；Output 每个文件一行，只写“新建 <路径>”或“替换 <路径>”。
- [x] `scripts/auto-build/cleanup.ps1` 已移到 `scripts/sample/cleanup.ps1`；Functions 与 Invoke 继续留在 auto-build。
- [x] 后续确认已把“清理仓库”和“手动清理 Root”收敛到执行区的统一 **清理** 对话框；Git 强制恢复、CMake 与 YAML 规则仍是不同类型，入口合并但语义不混用。
- [x] 手动清理 Root 默认文本固定为：

  ```yaml
  delete:
    directories:
      - objects
      - build
    files:
      - '*.obj'
      - '*.exp'
      - '*.pdb'
      - 'test_*.exe'
  ```

- [x] 不再默认写入 `Kt* / KTC* / PNX*`。
- [x] 插件通过 Wing TypeScript 能力预览、冻结、复验和执行清理，不通过 PS1 代执行；PS1 和 sample 继续作为可复制脚本与语义样例保留。
- [x] TypeScript 与 Functions-Cleanup.ps1 对齐为三类直属规则：`unlinkDirectories`、`delete.directories`、`delete.files`。目录链接只删链接，目录名精确匹配并可删除树，文件 glob 不递归。
- [x] 执行前冻结 Root、每个顶层候选及完整目录树的身份；先验证全部快照，再按深度删除。文件系统根、路径规则、递归 glob、越界、类型变化和确认后新增/替换内容均拒绝。
- [x] 规则文本缓存到当前 AutoBuild schema-v2 JSON 的 `rootCleanupYaml`；旧 JSON 缺少字段时使用本版默认值，保存后显式写回。
- [x] Preview 只模拟，不删除真实文件；正式操作仍为精确预览、模态确认、按冻结快照删除，结果进入原生 Output。
- [ ] 下一个版本把可复用的结构化规则解析、快照和清理能力提炼到 Phoenix Wing；本版先在插件 TS 内稳定接口和安全测试。
