# 工作区验收记录

## 1. 验收方法

使用 `runWorkspaceRename()` 对同级真实项目运行 `apply: false` 预览，覆盖文件夹、文件名和文本三个阶段。每个仓库在预览前后都计算 `git status --porcelain=v1 -z` 的 SHA-256 指纹，确认插件核心没有改变工作树状态。

本轮只验证扫描、规则竞争、编码识别和预览结果，不执行写盘，不修改或恢复目标仓库原有改动。

## 4. 一次性工作区写盘验收

新增 `src/core/searchReplaceAcceptance.test.ts`，每次在系统临时目录创建独立工作区，完成如下真实写盘链路：

1. 创建并写入 `.phoenix/search-replace.json`，再从工作区档案重新加载规则。
2. 使用同一规则快照先预览，再按“文本 → 文件名 → 文件夹”顺序写盘。
3. 验证工作区内目录和文件名正确更名，但留空工作目录所代表的工作区根目录 `KTCAutoCodeWorkspace` 保持不变。
4. 验证 UTF-8 BOM 和 GBK 文件修改后编码不变，BOM、CRLF 和未命中字节保持原样。
5. 验证通用规则与 CAA 末词段 I/E 规则在同一次执行中竞争正确。

该验收使用真实文件系统写入，不修改任何用户工程；测试结束后删除一次性目录。
