## 阶段与优先级

### P0-A：同一内存草稿与项目表

本节及 P0-B/P1 的已勾项表示 **Preview 源码与定向自动化通过**；浏览器只按末段实际点检记录签署，不表示正式 Host 或全部人工场景通过。

- [x] 从完整 ready fixture 初始化可编辑草稿；原始 fixture 不变，Primary 统计、Right 配置/项目表与导入共用同一 session。
- [x] 用稳定项目 ID 与语义 action 处理启用、分支、路径、组合操作、添加/移除和排序；四个项目工具按钮使用语义 ID，不按文字或 DOM 行号推断目标。
- [x] 样例目录选择/扫描去重、单行模拟更新/运行产生状态变化；空项目、无效路径、非 Git、dirty、取消和迟到回包有模型/DOM 回归。不使用真实目录选择器或 Git。
- [x] 改目录、配置、项目或执行选项使旧探测/预检/执行请求失效；运行时锁定冲突操作，受影响依赖链重建，其他行已完成结果保留。

### P0-B：导入从占位变成闭环

依赖 P0-A 的草稿身份与 revision；仅导入清单到草稿，不访问 Git。

- [x] 载入内存样例或粘贴 JSON → 校验 → 动态新增/更新/忽略汇总 → 问题项展开 → 确认合入；取消不落表，重复导入无重复，旧草稿计划不能覆盖新编辑。
- [x] BUILD_MANIFEST schema v1 与 AutoBuild schema 2 分开选择、明确解析；后者要求路径一致、唯一的 repositorySnapshot Origin 及有效构建选项，不猜测任意 JSON，也不声称完整正式 AutoBuild 文件导入兼容。
- [x] Origin 主机名规范化、去掉尾部 `.git` 去重但保留仓库路径大小写；root/thirdParty 按角色与来源匹配，项目保留 branch、原 commit 字符串与 buildKinds。缺 Origin/dirty 快照明确忽略，导入 Commit 标为“清单快照（模拟）”，不冒充当前探测。
- [x] 新增项目显示建议目标 `工作目录/<name>` 并允许确认前修改；重复目标或越出工作目录拒绝，不根据本机目录存在与否静默绑定。只比较样例路径。
- [x] 校验字段类型、schema、角色、buildKinds、Origin、Commit 和输入上限；拒绝凭据/查询参数、`file://` 等非 Git 来源以及路径越界。使用文本节点显示不可信内容，不执行命令或写文件。

现有 [autoBuildManifest](../../src/tools/codeAssistant/autoBuildManifest.ts)同时含 Node 路径依赖，解析器也不是完整的不可信导入校验。若复用，应先明确 Host-neutral 的纯数据边界；不能把整模块直接引入浏览器，不能复制第二套正式导入算法。

### P0-C：多 cleanup.yaml 与清理窗口

本阶段可与 BUILD_MANIFEST 导入并行，但 YAML 文件来源、界面当前规则与编译草稿必须分清身份。以下以最终原生编辑器决定为准，早期内置多标签/独立文件草稿、清理规则导入及自建另存对话框方案不再实施或验收。

- [ ] 仅从当前编译工作目录向下自动列出多个名为 `cleanup.yaml` 的文件，不带入 ROOT、3rdParty 或配置项目的其他根；每个文件独占一行，显示文件/目录与自己的“清理”按钮，不合成一个隐含全局目标。来源列表只留数量及简短不完整状态，深度/限额/跳过明细进入日志区。
- [ ] 用户点击该行“清理”即开始该文件的清理流程，**不增加确认对话框**。自动发现只列出文件，绝不自动运行清理。
- [ ] 每条规则的根固定为 **该 YAML 所在目录**，只匹配该根的直属项，不使用全局 ROOT_DIR、当前激活项目或上次选择目录作为 fallback；发现子目录中的 YAML 不意味着允许从父根递归清理。
- [ ] 顶部“在 VS Code 中编辑”将界面当前规则交给未保存的 YAML 原生文档，用户自行保存；不自建导入、打开选择器或另存对话框。已有来源行内“打开”则指向该原文件，不把文件内容导入清理窗。Preview 只反馈对应的模拟原生编辑器请求，不伪造真实文档已打开。
- [ ] 文件来源以规范化完整路径标识，同名文件不能混淆。规则错误定位到对应来源，上下文改变使旧计划失效，清理结果归属发起行而非后来打开的文件；原生编辑器负责文件 dirty 与保存，正式执行前的已保存文件/未保存编辑冲突须独立复验。
- [ ] 四个可折叠 Block 按目标、规则、配置 YAML 列表、预览结果排列；对话框级编辑/探测/取消/预览/清理全在 Header 右侧，不再有 footer；来源行保留各自打开/清理，不增加内置文件标签行。方式为一行 radio，使用 VS Code 主题 token。
- [ ] 原生未保存文档内容来自界面当前规则，不能误用上次打开文件；其保存/取消完全交由用户和 VS Code，插件不自动写盘或静默覆盖文件。来源行清理只使用已保存 YAML，保存后来源版本变化使旧计划失效；不能把原生未保存草稿当成已保存配置执行。
- [ ] 原型真实计算匹配/结果状态但只使用内存文件树；不调用文件删除、Git 或 shell。非法 YAML、失效文件、空命中、失败、重复点击、取消、关闭/切换后的迟到结果均有可验证反馈。

“无确认”针对上述明确的逐 YAML 清理入口，不推定所有 Git 强制恢复动作都已取消既有高风险门禁。正式执行仍须在该入口内部完成解析、身份冻结、即时复验与并发/路径安全检查；没有弹窗不等于跳过这些检查。路径越界、盘根/共享根、符号链接/junction 穿越、命中树变化必须拒绝；选择了直属目录也不得通过其中的链接扩大范围。

Phoenix 缓存若被显式规则覆盖，应使用现行 `.phoenix/cache` 路径，并展示实际根与命中项；不据此默认删除所有项目缓存、用户级缓存或 clangd 的 `.cache/clangd`。清理方式不得把 YAML 内容当作任意命令执行。
