# 批量工程脚本设计

> 维护边界：本文与对应脚本已迁入 KT Auto Code。源码真源为 `scripts/auto-build/` 与 `scripts/sample/`；`ROOT_DIR/tools`、`ROOT_DIR/sample` 只是由 Auto Code 显式同步产生的运行副本，不再反向维护。

## 1. 目标

`tools/` 中的批量脚本用于从一个集合根目录发现多个 Git 仓或工程工作区，并按任务需要顺序调用或并行启动各工程自己的入口脚本。公共脚本只负责编排，不复制各工程内部的构建、导出逻辑。

脚本分为两类：

- CMake/通用入口发现：根据 `rebuild.ps1`、`export.ps1` 或 `export.bat` 判断是否可执行。
- CAA 联合构建：根据 CAA 目录结构发现工作区，聚合 Framework 并统一 `win_b64`，再选择聚合顺序编译或多窗口并行编译。

## 2. 脚本职责

| 脚本 | 搜索范围 | 入口或标记 | 行为 |
| --- | --- | --- | --- |
| `rebuildAll.ps1` | 一级子目录 | `rebuild.ps1` | 在当前窗口逐个调用；批量入口不创建窗口，单仓 `rebuild.ps1` 自己打开 Debug/Release 窗口 |
| `exportAll.ps1` | 默认 1–3 级 | 优先 `export.ps1`，其次 `export.bat` | 在当前窗口逐个导出；同时适用于 CMake 仓和 CAA 工程 |
| `linkFramework.ps1` | 当前目录或默认 1–3 级 | CAA Framework 结构 | 将各仓 Framework 链接到版本聚合工作区，并补充缺少的 `mk.ps1`、`run.ps1` |
| `linkWinb64.ps1` | 当前目录或默认 1–3 级 | CAA 工作区结构 | 将各工作区的 `win_b64` 链到聚合工作区的 `win_b64` |
| `linkCAA.ps1` | 当前目录或默认 1–3 级 | CAA 工作区结构 | 总入口：先执行 `linkFramework.ps1`，再执行 `linkWinb64.ps1` |
| `cmakeAll.ps1` | 默认 0–3 级 | 最浅层 `CMakeLists.txt` | 为每个独立 CMake 项目打开窗口；窗口内串行执行 Debug、Release |
| `caaAll.ps1` | 默认 1–3 级 | CAA 结构及 `mk.ps1` | 先执行 `linkCAA.ps1`，再为每个 workspace 打开独立窗口 |
| `mkAll.ps1` | 默认 1–3 级 | CMake 与 CAA 两套独立规则 | 混合总入口；默认启动两组，也可通过 `-Type` 仅运行一组 |
| `invokeAll.ps1` | 由调用者指定 | 指定的 `.ps1`/`.bat` | `rebuildAll`、`exportAll` 使用的内部顺序执行器 |

## 3. 推荐目录

版本聚合目录使用 `CAAB<版本>MkWsp`，不包含客户、用户或产品前缀。例如 B20：

```text
E:\out\
├─ CAAB20MkWsp\
│  ├─ FrameworkA -> RepositoryA\WorkspaceA\FrameworkA
│  ├─ FrameworkB -> RepositoryB\WorkspaceB\FrameworkB
│  ├─ win_b64\                 # 多仓联合输出目录
│  ├─ mk.ps1                   # 不存在时从 sample 复制
│  └─ run.ps1                  # 不存在时从 sample 复制
├─ RepositoryA\
│  └─ WorkspaceA\win_b64  -> E:\out\CAAB20MkWsp\win_b64
├─ RepositoryB\
│  └─ WorkspaceB\win_b64  -> E:\out\CAAB20MkWsp\win_b64
├─ linkCAA.ps1                 # sample 中的一行入口
├─ mkAll.ps1
├─ exportAll.ps1
└─ rebuildAll.ps1
```

`-Version 19`、`-Version 20`、`-Version 28` 会分别使用 `CAAB19MkWsp`、`CAAB20MkWsp`、`CAAB28MkWsp`。也可以用 `-TargetDirectory` 指定完全不同的聚合工作区根目录。

## 4. 搜索方法

### 4.1 通用入口搜索

`exportAll.ps1` 从集合根目录向下进行广度优先搜索，默认最大深度为 3：

1. 当前目录存在 `export.ps1` 时选择它。
2. 不存在 PowerShell 入口但存在 `export.bat` 时选择批处理入口。
3. 一旦某个目录命中入口，不再扫描它的子目录，避免根导出脚本与内部导出脚本重复执行。
4. `rebuildAll.ps1` 使用相同机制，但固定只搜索一级目录及 `rebuild.ps1`。

### 4.2 CAA 工作区搜索

`linkCAA.ps1`、`caaAll.ps1` 和 `mkAll.ps1` 不依赖仓库前缀或 `project.ps1`。CAA 结构按以下优先级识别：

1. Framework 级主要标记为 `IdentityCard/IdentityCard.h`。命中后，将 Framework 的父目录作为候选 CAA workspace。
2. Module 级主要标记为 `Imakefile.mk`。命中后，从 Module 回溯到 Framework，再将 Framework 的父目录作为候选 workspace。
3. Framework 和 Module 名称没有固定后缀，不使用 `*Frm`、`*Interfaces`、`*Tlb`、`*.edu` 等名称判断工程类型。
4. `CATIAV5Level.lvl` 可能在未编译时不存在，只作为可展示的附加信息，不参与 workspace 身份判定。

发现函数先检查传入的搜索根本身：如果它已经是 CAA workspace，就只返回该 workspace，不再把其直接 Framework 当作“子工程”继续扫描。仅当搜索根不是 workspace 时，才覆盖下方 1–3 级目录。识别 `IdentityCard/IdentityCard.h` 和 `Imakefile.mk` 时会检查 Framework、Module 的结构层级；所有命中结果最终都归一到 workspace，不把 Framework 或 Module 误当成 workspace。`mkAll.ps1` 还要求最终 workspace 存在 `mk.ps1`；缺少时只提示并跳过。

公共 `Get-CAAWorkspaceDirectories` 通过 `Test-CAAWorkspaceDirectory` 集中识别 `IdentityCard/IdentityCard.h`、Framework 根部 `IdentityCard.h` 和 Module 级 `Imakefile.mk`。目录名和 `CATIAV5Level.lvl` 均不参与身份判定。`linkCAA.ps1`、CAA 专用启动器和 `mkAll.ps1` 必须共用该函数。

### 4.3 默认忽略目录

搜索不会进入以下目录或重解析点：

```text
.git  .hg  .svn  .vs  .vscode
.clone  .worktrees  _clear  CAAB*MkWsp
build  cmake-build-*  CMakeFiles  win_b64
tools  sample  samples  node_modules  ImportedInterfaces
```

通过 `-IgnoreDirectory` 可追加名称或相对路径通配符，例如：

```powershell
.\mkAll.ps1 -Version 20 -IgnoreDirectory @('Legacy*', 'RepositoryC\Examples*')
```

## 5. CAA 版本与链接

版本解析顺序为：显式 `-Version`、环境变量 `CAA_MK_VERSION`、默认版本。`caaAll.ps1` 会把最终版本写入子进程环境，使只有一行转发内容的工作区 `mk.ps1` 也能获得版本。

`linkCAA.ps1` 是总入口，内部执行两种方向不同的链接：

- Framework：`CAAB<Version>MkWsp\Framework -> 各仓真实 Framework`；
- 运行输出：`各仓工作区\win_b64 -> CAAB<Version>MkWsp\win_b64`。

单工程根使用同步得到的 `sample/linkOut.ps1`。它不再只调用 `linkWinb64.ps1`，而是把当前目录交给 `linkCAA.ps1`，默认将当前 workspace 的 Framework 与 `win_b64` 一并接到上级 `CAAB20MkWsp`（或 `-Version` / `CAA_MK_VERSION` 指定的版本工作区）。

Framework 通过 `IdentityCard.h` 或其直接 Module 中的 `Imakefile.mk` 识别，不限制目录名称。同名 Framework 来自不同位置时，在修改目录前报冲突并退出。

默认参数：

- 搜索根：调用入口所在目录；
- 链接名：`win_b64`；
- 聚合工作区：`<搜索根>\CAAB<Version>MkWsp`；
- 共享输出：`<聚合工作区>\win_b64`；
- 最大搜索深度：3。

已有 Junction 指向正确位置时保持不变；指向其他位置时只替换 Junction。已有普通目录默认不会删除，脚本返回失败。只有显式使用 `-ReplaceDirectory` 才允许删除普通目录并建立 Junction，因此使用前必须确认其中内容可丢弃。

## 6. 典型调用

先检查发现结果，不修改目录、不启动构建：

```powershell
.\linkCAA.ps1 -Version 20 -ListOnly
.\mkAll.ps1 -Version 20 -ListOnly
.\exportAll.ps1 -ListOnly
.\rebuildAll.ps1 -ListOnly
```

建立 B20 联合输出链接：

```powershell
.\linkCAA.ps1 -Version 20
```

指定实际目标目录：

```powershell
.\linkCAA.ps1 -Version 20 -TargetDirectory 'E:\shared\CAA-B20'
```

聚合后在单一工作区中顺序编译全部 Framework：

```powershell
Set-Location .\CAAB20MkWsp
.\mk.ps1 -Version 20
```

同时启动 CMake 与 CAA 两组工程：

```powershell
.\mkAll.ps1 -Version 20
```

只启动一类工程：

```powershell
.\mkAll.ps1 -Type CMake -BuildType Debug,Release
.\mkAll.ps1 -Type CAA -Version 20
```

CMake 项目之间并行，每个项目窗口内部按 Debug、Release 串行。CAA 并行窗口会把 `CAAB20MkWsp` 作为 `mkGetPreq` 的附加工作区，因此各仓仍在自己的目录编译，但可以解析其他仓聚合后的 Framework。

已提前完成链接时跳过链接阶段：

```powershell
.\caaAll.ps1 -Version 20 -SkipLink
```

批量导出与 CMake 重建：

```powershell
.\exportAll.ps1
.\rebuildAll.ps1
```

## 7. 执行与退出规则

- `exportAll.ps1` 在当前窗口逐个执行导出入口。
- `rebuildAll.ps1` 逐个调用各仓入口；入口内部创建的 Debug/Release 窗口属于单仓行为，保持不变。
- `mkAll.ps1` 是混合调度入口；CMake 与 CAA 使用独立发现结果，同一个仓库允许同时出现在两组中。
- `All` 模式中的空分组显示为 `[SKIP]`，不计入已启动或已验证的分组数量。
- `cmakeAll.ps1` 为每个 CMake 项目打开一个可见窗口；项目之间并行，每个窗口内先执行已有的 `export.ps1`，再串行执行 Debug、Release。导出失败会记录并在末尾报告，不会阻止该项目继续编译。
- `caaAll.ps1` 为每个 CAA workspace 打开一个可见窗口；所有 workspace 并行运行。
- `CAAB<Version>MkWsp\mk.ps1` 是另一种模式：在聚合工作区中由 mkmk 顺序处理全部已链接 Framework。
- 单个入口失败后记录错误并继续其他入口，最终返回非零退出码。
- CAA 链接阶段失败时不启动 CAA 编译，但不取消已经启动或仍可启动的 CMake 组。
- `-ListOnly` 仅列出候选项，是正式执行前的推荐点检方式。
