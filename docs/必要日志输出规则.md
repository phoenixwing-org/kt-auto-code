# 必要日志输出规则

状态：current

Owner：KT Auto Code maintainers

适用版本：KT Auto Code 0.7.4+

最后核验：2026-08-27

## 1. 目标

KT Auto Code 的 Output 用于留下用户可行动、可复查的操作证据，不作为默认开启的调试追踪。普通使用时应优先让用户看到“做了什么、是否成功、失败后怎么办”，避免自动扫描、内部 ID、运行 ID、matcher 实现细节淹没真正结果。

统一格式：

```text
[模块][阶段][等级] 内容
```

等级固定为大写 `INFO`、`OK`、`WARN`、`ERROR`：

- `INFO`：用户主动触发的重要操作开始、取消或安全边界；
- `OK`：操作成功和必要的数量/对象摘要；
- `WARN`：操作可继续，但存在需要人工检查或部分跳过的项目；
- `ERROR`：操作已停止、失败或产生必须处理的结果，并给出下一步。

## 2. 默认输出与默认静默

默认输出：

1. 写盘、历史改写、构建运行等重要操作的开始与结果；
2. 路径/环境推导的成功结果或可行动失败；
3. 同名冲突、部分跳过、matcher 降级等会改变结果含义的警告；
4. 无法仅靠页面短状态长期保留的安全决策；
5. 失败原因及用户可执行的下一步。
6. Webview → Host 信号无法路由的开发错误，包括工具不存在、动作未声明或容器误收叶子动作；统一输出 `[Primary][信号][ERROR]`，并在当前 Block 显示错误。任何未知信号不得静默返回。

默认静默：

- 自动发现的文件数、仓库数、内部 target/run/session ID；
- 每次 Primary 重绘、普通选中、折叠和状态同步；
- 已在页面中清楚展示、且不影响后续判断的重复信息；
- matcher 内部实现、命令参数和环境键明细。

显式“试运行”“复制诊断”或开发模式可以输出更详细信息，但必须带明确阶段，例如 `[Run][试运行][INFO] execute=false`，不得让用户误以为命令已真正执行。

## 3. Output、Terminal 与 Problems 分工

- **Output**：生命周期、推导、安全预检、成功摘要和可行动错误；
- **Terminal**：工具原始 stdout/stderr、交互输入和完整命令输出；
- **Problems**：能够解析出文件、行号、严重级别的结构化诊断。

一个文件诊断可以同时由 Terminal 原样显示并进入 Problems；Output 不复制整段编译文本。任务非零退出但 Problems 为空时，Output 提示用户查看 Terminal 和 matcher 保真状态。

CAA/MSVC 约定：小写 `fatal error` / `error` 进入 Problems 的错误级别；厂商输出的大写 `ERROR` / `WARNING` 统一按 warning 捕获。没有文件和行号的 `ERROR` 只保留在 Terminal，不伪造成 Problems 项。

## 4. 并发与隐私

- 日志必须带模块和阶段；多仓库/多项目操作再带脱敏后的仓库或项目名称，避免并发输出互相混淆。
- CAA MK 使用共享 `cpp` Problems owner，当前版本一次只允许一个 CAA MK 运行，防止多个任务互相覆盖诊断集合；普通不同类型任务仍可并行。
- 不输出 token、password、cookie、带凭据 URL 或 secret 环境变量值。
- 用户目录和工作区外绝对路径仅在定位问题确有必要时显示；发布文档与 fixture 一律使用占位符。

## 5. 模块示例

```text
[代码辅助][头文件引用修正][目录推导][OK] ROOT_DIR + SDK_PREFIX（demo） -> <ROOT_DIR>/demo/core/include
[代码辅助][头文件引用修正][预览][WARN] 同名冲突：Demo.h -> PkgA/Demo.h | PkgB/Demo.h
[代码辅助][入口][INFO] 已打开：编码修正；目录 demo。
[编码修正][转换][INFO] 用户已取消，未写入文件。
[Git][合并预检][OK] 通过：分支 develop，区间 3 个 commit；只改本地分支，不自动 push。
[Git][简报][OK] 已复制：仓库 demo；commit 4b4622d。
[Git][时间重置][OK] abcdef012345 -> 123456789abc；重建 3 个 commit；备份 refs/kt-auto-code/backup/develop-time；未 push。
[Run][预检][ERROR] RADE intel_a 的厂商脚本缺失：<RADE_ROOT>/intel_a/...
[成员排序][写入][OK] 已写入 5 个文件；可在结果行按需查看 Git 差异。
```

## 6. 变更点检

新增或修改用户操作时至少检查：

1. 成功、失败和取消是否分别有准确等级；
2. 错误是否包含对象、原因和下一步，而不是只写 `failed`；
3. 自动刷新是否产生无意义重复行；
4. 页面气泡、Output、Terminal、Problems 是否各司其职；
5. 并发任务是否能从模块/项目标签区分；
6. 测试是否覆盖新增格式和关键 matcher 行为。
7. Webview 发送的 `toolId` 是否是实际执行叶子而非外层容器；不存在的工具或动作是否有 Output 错误和回归测试。
