# KT Auto Code 0.8.0 发布准备

状态：release-candidate（本地基本手工测试通过；供 Windows 用户继续点检，尚未完成详细人工矩阵）

Owner：KT Auto Code maintainers

适用版本：KT Auto Code 0.8.0；Phoenix Wing root 0.7.2 / scoped 0.6.4、0.6.3

最后核验：2026-09-01

## 版本边界

大型项目改名是新增用户可见工具，按仓库版本规则从尚未公开发布的 `0.7.4` 本地补丁候选升级为 `0.8.0` 次版本候选。`0.7.4` 的代码辅助修复一并进入 `0.8.0`，不单独上传 Marketplace、打 tag 或形成两套待发布制品。

Phoenix Wing Registry 根包最新为 `0.7.2`，但 Auto 不直接依赖根聚合包。正式 manifest 与 lockfile继续精确消费 Registry 已发布的 `@phoenix-wing/code-core`、`git-core`、`git-node`、`kt-codegen` `0.6.4`，以及 `run-core`、`run-node` `0.6.3`；不得把 scoped 包伪写成不存在的 `0.7.2`，也不得写入本地路径、`link:`、`file:`、workspace override 或本地 Wing 回退。

## 本轮内容

- 保留 `0.7.4` 已完成的代码辅助叶子动作、内部功能 Block、关闭清理与未知信号日志修复。
- 在 Primary **搜索替换**内提供 **大型项目改名分析…** 入口；一个 Editor View 对应一个固定目录任务，重复点击只聚焦，关闭后才可为另一目录创建任务。
- 使用与“头文件引用修正”一致的固定 command header，展示只读目录上下文和 **分析 / 取消 / 执行改名 / 结束任务**；内部三块使用可独立折叠的紧凑 Block。
- 派生六种大小写/连接符精确规则，并提示真实出现的相关短写法；智能候选默认关闭，必须人工加入、启用并重新分析。
- 写盘复用既有编码、Ignore、冲突预检和文件事务能力；冻结报告后再次预检漂移、检查 Git 状态、明确确认，成功后自动复扫。
- 非当前工作区根目录可在同一父目录内改名；当前工作区根目录只提示。只有达到目标或冻结计划全部完成时才允许结束任务。
- 结构化名称模式与正则替换只完成可行性归档；`0.8.0` 不开放裸正则写盘。

## Phoenix Wing 0.7.2 适配

- `npm view phoenix-wing version` 与并列仓库根 manifest 均确认 root `0.7.2`。
- 六个 Auto scoped 依赖的 Registry 最新版本与现有精确映射一致：四个 `0.6.4`、两个 `0.6.3`，因此本轮不制造无效依赖升级。
- 本地开发使用 sibling `phoenix-wing@0.7.2` 构建六个包；esbuild metafile 必须证明全部输入来自并列仓库且 consumer `node_modules` 命中为 0。
- 正式 VSIX 仍使用 committed lockfile 与 Registry 精确版本，不把本地 Wing 构建产物当作发布来源。

## Windows 用户测试重点

1. 在干净 Git 克隆中打开 **搜索替换 → 大型项目改名分析…**，确认 header、目录 tooltip、折叠 Block 和单任务聚焦行为。
2. 使用包含大小写、空格、`-`、`_` 的项目名检查六种派生规则；确认 `open-issue` 一类候选默认关闭。
3. 分别验证 UTF-8、UTF-8 BOM、GBK 文本及 `.github`、`.vscode` 等点目录；二进制、大文件与 symlink 不应写入。
4. 在写盘确认前制造 Git 脏状态、目标路径冲突和分析后文件漂移，确认执行被阻止；清理后再完成一次真实写盘和 Git diff 审查。
5. 当前工作区根目录只能看到改名提示；选择不包含当前工作区的外部克隆时，验证同父目录根文件夹改名与目标已存在阻断。
6. 成功写盘复扫后确认“目标已达到”或“冻结计划全部完成”会启用 **结束任务**；关闭后才能为另一目录创建新任务。
