# 固定与排序菜单控件

状态：current

Owner：KT Auto Code maintainers

适用版本：0.6.x

最后核验：2026-08-09

## 1. 定位

“固定与排序菜单”是挂在“工具栏” Block Header 唯一 `…` 下的独立弹出控件，用于统一管理 Code、CAD 及后续模块的工具入口。

它不是第四个主 Block，也不改变“工具栏 → 目录 → 当前工具”三个主 Block 的数量、顺序和职责。工具栏折叠后的 Header 行及 `…` 保持当前已确认效果。

工具栏 Header 的固定职责为：

- “显示密度”始终在 Header，切换“图标与文字 / 仅图标”；工具栏已折叠时，点击它必须先自动展开，再执行切换，让结果立即可见。
- 唯一 `…` 始终在 Header；折叠状态下仍可打开菜单，弹层不得挂在被隐藏的 Ribbon 内容节点内。
- 打开 `…` 后焦点必须直接进入菜单首个可操作项；不得从 Primary 原位置继续 Tab 到整页末尾才进入弹层。
- Code/CAD 不常驻 Header，而是在 `…` 的树形分组中使用 checkbox 控制显示。
- 插件级搜索、诊断和设置不进入该 Header；它们仍属于整个 View 或具体工具。

## 3. 交互规则

### 3.1 分组

- 工具按贡献声明中的 `moduleId` 分组，当前先显示 Code 与 CAD。
- 分组使用“折叠箭头 + 模块 checkbox + 标题”的树形行，不用颜色单独表达展开状态。
- 折叠箭头只控制菜单内工具列表；模块 checkbox 只控制该模块是否显示在 Ribbon，两项操作不得绑定。
- 至少保留一个可见模块；最后一个可见模块的 checkbox 不允许关闭。
- 分组折叠只影响本次菜单会话，不写工程配置，也不改变工具固定状态。
- 新模块沿用同一模型，不为每个模块增加独立 `…`。

### 3.2 固定

- 已固定：钉子常显，`aria-pressed="true"`，提示“取消固定到工具栏”。
- 未固定：钉子默认隐藏；整行 hover 或 `focus-within` 时显示，提示“固定到工具栏”。
- 隐藏仅是视觉收敛，键盘到达该行后必须能看到并操作钉子。
- 固定操作只改变 `pinnedToolIds`，不得顺带打开、关闭或执行工具。

### 3.3 排序

- 整行是拖动来源，用户不必抓取一个很小的图标。
- 只允许同模块排序；跨模块拖放必须被拒绝。
- 放置位置使用目标行上半区/下半区判断 `before` 或 `after`，并显示插入提示。
- 上移、下移是拖动的键盘等价入口，不得只提供鼠标拖动。
- 排序更新稳定的 `toolOrder`；取消固定不丢失该工具在模块内的相对位置。

## 4. 控件边界

建议控件名为 `KtcRibbonCustomizationMenu`，注册为 `ktc-ribbon-customization-menu` Web Component。控件只接收可序列化 ViewModel，并发出语义事件：

```ts
interface KtcRibbonCustomizationMenuModel {
  tools: Array<{
    id: string;
    title: string;
    shortTitle?: string;
    moduleId?: string;
    moduleTitle?: string;
  }>;
  pinnedToolIds: string[];
  visibleModuleIds: string[];
}

type KtcRibbonCustomizationAction =
  | { kind: "open"; toolId: string }
  | { kind: "togglePin"; toolId: string }
  | { kind: "toggleModule"; moduleId: string }
  | {
      kind: "move";
      sourceId: string;
      targetId: string;
      placement: "before" | "after";
    };
```

控件内部负责：

- Code/CAD 树形分组和会话内折叠状态；
- 钉子、hover/focus、拖放目标和上移/下移按钮；
- 菜单行的键盘焦点、ARIA 和高对比度样式；
- 把用户操作转换为语义事件。

控件不得负责：

- 调用 `acquireVsCodeApi()` 或直接发送 Host 消息；
- 保存 `globalState`、`workspaceState` 或工程设置；
- 决定工具属于 Code 还是 CAD；
- 打开工具、执行命令或修改工作目录。

父级 Webview 负责把弹层挂到 Webview 顶层、锚定 Header `…` 并约束在可视区内，再把控件事件转发给 Extension Host。Host 校验工具 ID、模块边界和排序合法性，规范化后保存 `pinnedToolIds` 与 `toolOrder`，再广播新快照。

## 5. 复用规则

- 后续出现同类“固定 + 排序”场景时复用控件和事件契约，不复制 DOM/CSS 到业务页面。
- 调用方可替换标题和数据，但不得绕过同模块排序、键盘等价入口及持久化边界。
- 复用控件不等于新增主 Block；三 Block 外层契约仍以[前端开发规则](./前端开发规则.md#11-锁定的三-block-外层契约)为准。

## 6. 自动验证

- 控件可幂等注册，源码不包含 Host API、工作区或存储调用。
- ViewModel 可生成折叠分组、工具行和正确的固定状态。
- 模块显示、打开、固定、取消固定、拖动、上移、下移均只发一次对应语义事件。
- 未固定钉子具有 hover 与 `focus-within` 可见规则；已固定钉子常显。
- 同模块移动成功，跨模块移动由 Host 拒绝且布局不变。
- 菜单在窄侧栏内夹紧并内部滚动；深色、浅色和高对比度主题均有边框、焦点和拖动提示。

## 7. 非目标

- 不支持把工具拖到另一个模块。
- 不改变三个主 Block 的外层结构。
- 不增加另一套 Ribbon 布局存储。
- 不引入第三方拖拽库或新的 Webview。
