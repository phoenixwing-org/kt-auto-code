# UI 开发规则

> 适用范围：KT Auto Code 的 VS Code / Cursor 插件界面。
> 本文是当前 UI 的权威规则；功能计划只记录目标和进度，不重复维护交互规范。
> 当前以“单 View 四段 Shell + 固定尺寸 Ribbon + 单显示、多打开的工具 Block”为目标基线。实施顺序与联动计划见 [0.9.0 Primary 与 Editor 联动及统一工具运行时计划](./0.9.0-Primary与Editor联动讨论稿.md)。旧的多 View、两区或三段 Shell、Toolbar-first、无 Header Tool Surface、可折叠 Current Tool、独立结果 TreeView 和编辑区 Workbench 方案仅作历史参考，不再构成现行要求。

## 1. 当前界面架构

插件只贡献一个主侧栏 Webview；以下区域在同一页面内自然排列：

```text
KT Auto Code                             [目录显隐] [忽略] [设置]
├─ Directory：固定一行，表达共享目录；可由 Header 显示或隐藏
├─ Toolbar Strip：`箭头 + Ribbon + …` 共用一层；无独立标题行
├─ Current Tool：固定展开，Header 为 `Tool 图标 + 标题 + ×`；Body 独立滚动
└─ Open Items：固定在底部，表达已打开逻辑工具与 MRU
```

Toolbar Strip 的两态示意；中间始终是同一份入口 DOM：

```text
展开  ⌄ │CODE│ [代码辅助] [Git] [Run] [替换] [自动代码] │CAD│       […]
             图标 + 现有短标题；空间不足时自然换到后续行

紧凑  › [图标] [图标] [图标] [图标] [图标]  ⇆                   […]
             单行仅图标，中间轨道可横向滚动；完整名称由 Tooltip / aria-label 提供
```

术语统一：

| 术语 | 定义 |
| --- | --- |
| 原生 View Header | VS Code 提供的 View 标题操作区；固定动作依次为目录显隐、Ignore、Settings |
| Ribbon | Toolbar Strip 中唯一一份工具入口 DOM，不承载任务结果 |
| Directory | Shell 管理的第一个一级区域；固定单行共享工作目录，无折叠箭头、无 Body |
| Current Tool | 第三个一级区域；固定展开，Header 管理身份与关闭，Body 是唯一日常纵向滚动边界 |
| Open Items | 第四个一级区域；固定在 Primary 底部，投影打开项、活动项和 MRU |
| 逻辑工具 | 某工具在 MRU 打开栈中的状态；可以当前显示，也可以后台隐藏 |
| 结果分组 | Current Tool Body 内的待写盘、已写盘、无变更等列表分组，不是独立 Block |

- Ribbon 只负责打开、切换模块和表达打开状态，不直接扫描、预览或写盘。
- 四个区域全宽连续相接，不用卡片外边距、内部拖动分隔条或人工高度。Directory 与 Current Tool 使用 VS Code 分区基线；Toolbar Strip 是不显示独立标题行的例外。
- Toolbar Strip 的箭头只切换“展开图标与文字 / 紧凑仅图标”，不折叠 Current Tool 或 Directory。Current Tool 没有折叠状态，内容始终展开。
- 页面本身不作为日常纵向滚动边界；Current Tool 填充剩余高度，只有其 Body 独立滚动。Directory、Toolbar、Current Tool Header 和 Open Items 保持固定。
- 同一时刻只显示一个 Current Tool 内容，但允许多个工具处于逻辑打开状态；Open Items 使用同一打开项和 MRU 状态源，不维护副本。
- Current Tool Body 上部放操作界面，下部放本次会话缓存结果；不得再创建第二个结果 View。
- 文件预览、文本编辑、Diff 和 Git 变更继续使用 VS Code 原生编辑器与 SCM。
- Ribbon、菜单、命令和 Editor 传入的直接叶子 `toolId` 必须进入同一套激活、状态、MRU 与关闭运行时，入口来源只影响焦点和诊断。
- 原生 View Header 固定依次提供目录显隐、Ignore、Settings。目录显隐只控制 Directory 且不重置目录选择；Ignore 与 Settings 打开同级逻辑工具并复用 Current Tool，不新增一级区域或 Right 标签。

### 1.1 锁定的四段外层契约

下列项是 Primary 侧栏的稳定外层契约：

1. 原生 View Header 的固定动作顺序为目录显隐 → Ignore → Settings。搜索预览、目录齿轮和 Webview 内部 Ignore 快捷方式都不属于 Header；未来新增动作必须单独评审并同步契约与测试。
2. 一个 Webview View 恰好有四个全宽一级区域，顺序固定为 Directory → Toolbar Strip → Current Tool → Open Items。Ignore 与 Settings 通过 Current Tool 显示，不能创建第五个正式一级区域。
3. Directory 是无折叠箭头、无 Body 的单行；只承担目录上下文、下拉与右侧实际文件夹选择。左侧没有装饰性文件夹，行内没有目录齿轮。Header 的目录动作只切换该区域显隐；隐藏后对应布局轨收为零且保留当前选择。
4. Toolbar Strip 只有展开与紧凑两态：展开保留图标、短标题和自然多行换行；紧凑把同一组入口收成单行小图标。左侧 16px 箭头不产生完全隐藏状态，也不改变目录或 Current Tool 展开状态。
5. Ribbon 定制只有一个 `…`，固定在 Toolbar Strip 右侧；箭头位于左侧，中间只渲染一份 Ribbon DOM。紧凑态所有不可见工具仍能从 `…` 到达。
6. Current Tool 固定展开，Header 左侧依次是当前 Tool 图标和标题，右侧是明确的 `×`，不得显示 disclosure 或保留折叠占位。`×` 只关闭当前逻辑工具并按 MRU 恢复，不关闭 Editor、不 dispose/cancel/stop 任务，也不清空草稿或结果。
7. Open Items 固定在 Primary 底部且不随 Current Tool Body 滚动。其激活、关闭、关闭其他项和溢出操作只发送稳定 item ID 的语义事件；打开项、活动项和 MRU 由 Host 统一维护。
8. 四段使用连续分区；Directory、Toolbar 与 Open Items 使用固定或自然高度，Current Tool 填充剩余高度，只有其 Body 纵向滚动。页面和其他三个区域都不得成为日常纵向滚动边界。
9. Ribbon、菜单、命令、Editor 等入口若指向同一个直接叶子 `toolId`，必须复用同一激活运行时；不得因入口层级复制工具实例、MRU、草稿或关闭逻辑。
10. `KtcPrimaryShell` 只固定四个 named slot 的顺序与 Current Tool 弹性轨；各区域由独立 Host-neutral Web Components 投影。组件只接收可序列化 ViewModel 或 slot、只发稳定 ID 的语义事件，不拥有 VS Code API、业务 Controller、MRU、路由、持久化或跨 Surface 生命周期。

四段 Shell 的目标视觉基线同时锁定：

- 四段全宽相接，不使用卡片圆角、左右外边距或一级区域间空白；用连续分隔线表达层级。
- Toolbar Strip 不显示“工具栏”文字：16px SVG 箭头位于左侧，Ribbon 占中间剩余宽度，唯一 `…` 固定右侧。展开态保留 Ribbon 图标、短标题、活动高亮和多行换行；紧凑态使用单行仅图标按钮，超出可见宽度的工具仍能从 `…` 到达。
- 紧凑态不显示 `CODE`、`CAD` 等文字分组标签；模块边界由工具按钮的可访问名称、分组 `aria-label` 和唯一 `…` 内的模块分组保留。任何缺少图标的可选模块工具都必须生成可见的文字首字符回退，不得出现空白按钮。
- 原生 View 标题固定为 `KT Auto Code`，右侧依次为目录显隐、Ignore、Settings，不再放搜索预览或目录齿轮。Directory 保留目录下拉和右侧实际文件夹选择；Toolbar Strip 不显示密度按钮；Current Tool Header 固定为 Tool 图标、标题和 `×`。
- Open Items 使用单行紧凑项和本区域自己的 `…`；项目过多时允许区域内部横向滚动，但不得推动 Primary 页面横向滚动。
- Hover、focus、高对比度边框和操作入口继续使用 VS Code 主题变量，不写死颜色。

该契约锁定“外层结构和行为语义”，不锁死每个工具内容的演进：

- 允许优化各区的标题文案、图标、按钮排布、间距、响应式布局、无障碍和高对比度效果；目录的无箭头、单行、下拉和右侧文件夹按钮是固定行为。
- 允许增删、重组或改进 Current Tool Body 内部功能，前提是不把职责偷渡到原生 Header、Toolbar、Directory 或 Open Items，不改变 Toolbar 两态、Current Tool 固定展开、唯一滚动和关闭语义。
- Toolbar 不依赖可见标题表达职责，必须用区域 `aria-label`、箭头 Tooltip 和工具按钮名称保留“工具入口”语义；目录与 Current Tool Header 标题继续明确。
- 正式组件接入见[ShellBlock 控件提炼 TODO](./ShellBlock控件提炼TODO.md)；组件化不得与无关功能修改合并，也不得作为改变已确认效果的理由。

如果用户或新计划要求改变一级区域数量、顺序、Header 动作、目录固定行为、折叠/滚动边界、唯一 `…` 或 `×` 语义，执行者必须在编码前：

1. 明确提示“该请求会改变已锁定的四段 Primary Shell 契约”。
2. 列出被改变的具体规则、原因、迁移影响和需回归的交互。
3. 等待用户明确确认后，才能同时修改规则、实现和测试；不得把该变更夹带在普通功能、样式清理或重构中。

### 1.2 Codegen 数据编辑 View 例外

Codegen 的17列参数表属于结构化文档编辑，不属于扫描结果，因此允许在编辑区打开专用 Webview View：

- 左侧仍只复用一个 Current Tool Block，负责 JSON 列表、打开、CSV 导入、刷新、活动文档摘要和 Prefix/Middle/Namespace/Append 属性。
- 一份 JSON 对应一个右侧编辑 View；重复打开同一 JSON 时复用原 View。
- 当前编辑区的 Codegen 标签激活时，必须把活动 JSON、打开状态和未保存状态同步回左侧 Current Tool Block。
- View 组合文档级工具栏和独立 `KtCodegenTable`；属性由活动文档 Current Tool Block 编辑，表格组件不负责文件选择、写盘和生成动作。
- 表格内部可以逐格编辑，但跨 Webview/Host 边界只发送首次 dirty 通知，并在保存或生命周期同步点交换整份草稿，禁止每个单元格都与 Host 往返。

## 2. 分层和运行时边界

### Extension Host

- 负责文件系统、扫描、转换、工作集解析、确认框、配置、缓存和 VS Code 命令。
- `ToolUiState` 及工具会话是任务状态和结果的权威来源。
- 状态更新发送给唯一 Shell View；View 重建后必须能重放 Host 快照。
- 捕获工具入口的未处理异常，并把状态从 `running` 收敛到 `error`，不得无限转圈。

### Webview

- 只负责展示、收集输入、筛选、勾选和发送语义化消息。
- 不直接读写工作区、环境变量或 VS Code 配置。
- 不实现成员排序、UUID、编码、搜索替换等领域算法。
- 只保存界面局部状态，例如表单草稿、展开、筛选和当前选择。

### 共享核心

- 可跨产品复用的纯算法放根目录 `src/` 或 `phoenix-wing/code-core`。
- VS Code API、Git 命令、Webview、QuickPick 和工作区生命周期不得进入 Wing。

### Host-neutral Web Components

- Primary 正式外壳复用 `KtcPrimaryShell`、`KtcDirectoryBar`、`KtcToolbarStrip`、`KtcToolNavigator`、`KtcCurrentToolRegion` 和 `KtcOpenItemsBar`；Right 复用 `KtcRightViewShell`。不得在 Preview 与正式 Host 中分别维护外观相似但事件不同的外壳 DOM。`KtcSystemOutputBlock` 只在 Preview 中模仿 VS Code Output，用于显示原型按钮反馈；它不是正式插件能力，不进入正式 Webview、构建 bundle 或 VSIX。正式日志沿用现有原生 `OutputChannel("KT Auto Code")`。
- `KtcRightViewShell` 默认在工具名旁独立显示当前目录上下文，格式为 `末级目录名 @ 父路径`；完整路径必须保留在该上下文的 `title` / `aria-label`，长内容保持单行省略，Header actions 不得被路径挤出可操作区域。工具 `title` 仍只来自 Catalog，不得把路径拼入 Catalog、Panel / Tab 名或工具标题。消费者只传已有、真实的关联目录；没有目录时明确显示“未关联目录”，不得从文案、DOM 或相邻工具猜路径。只有产品明确要求关闭时才传 `hideContext: true`。
- Right Shell 接收重复的等值规范化模型时不得重建 Shadow Header，以免无关业务快照打断 actions 焦点或滚动。路径格式化必须在浏览器中同时支持 POSIX、Windows 盘符和 UNC，不得为此把 Node 路径 API 引入 Host-neutral 组件。
- `KtcPrimaryShell` 是零业务状态的四槽布局，只固定 `directory → toolbar → current → open-items` 顺序、零区域间距和 Current Tool 弹性轨。它不代理子组件事件，不复制子组件行为，也不拥有边框之外的业务呈现。
- 各组件只接收可序列化 ViewModel 或明确 slot，只发出带稳定 ID 的语义事件。Host / Store 负责状态真源、MRU、路由、持久化、Controller 和 Surface 生命周期，组件等待新快照回投影。
- 组件不得导入 `vscode`，不得读写文件、Git、进程、工作区配置或浏览器存储，也不得通过标题、DOM 位置、Shadow DOM 实例或任意 HTML 推断业务动作。
- Primary 与 Right 若属于同一逻辑工具，必须由同一 Controller 和实例身份投影不可变快照；两侧不能直接读取对方 DOM，也不能把另一侧是否仍挂载作为业务前提。
- 内置 `KtTool` 的 `title`、`shortTitle` 和 `description` 必须在中央 `src/tools/toolRegistrationCatalog.json` 中按 `toolId` 唯一解析；外部可选模块则保留其扩展版本管理下、已通过校验的 `package.json#ktAutoCodeModule` 注册文案。Primary、Right、Open Items、Navigator、Ribbon 与 Block 适配器不得覆盖、复制或拼接显示文案，也不得显示 Group、Module 或插件名前缀；完整归属信息只放 tooltip / `aria-label`。迁移期 snapshot 中的旧标题字段只能被忽略，不能作为 fallback。

## 3. Ribbon 规则

### 3.1 入口行为

- 点击 Ribbon 只打开或切换模块，不自动执行扫描、预览、替换或修复。
- Group Ribbon 只控制下级 Navigator 显隐；它不拥有 Current Tool、Right View 或 Open Item。组内已有打开叶子时可激活 MRU 叶子；否则保持现有 Current/Welcome，禁止默认打开第一个孩子。
- 激活组外 Tool 时收起该组二级 Navigator，包括再次点击当前独立 Tool；组内 Tool 不自动收起。只改变导航显隐，不关闭已打开 Tool 或 Right 任务；父按钮展开态、高亮与二级区必须同步。
- 重复点击当前入口不得关闭或隐藏 Current Tool；Current Tool 内容始终展开。主动关闭由 Header 的明确 `×` 执行；下述三种任务型 Right 关闭时另按已确认的联动规则移除对应工具。
- 展开 Ribbon 随入口换行自然增高；紧凑 Ribbon 保持单行，仅自身中间轨道可横向滚动，不得让页面产生横向滚动。工具内容只能出现在第三段 Current Tool。
- “图标与文字”和“仅图标”行为一致，仅显示方式不同；左侧箭头直接切换两态，不增加完全隐藏的第三态，也不另设密度按钮。
- Ribbon、`…` 菜单、命令面板和 Editor 只能发送注册过的直接叶子 `toolId`；四种来源必须调用同一个激活运行时。聚合目录 ID 不得代替叶子执行，`source` 只用于焦点保持和诊断。

### 3.2 置顶、更多与排序

具体控件边界、交互细节和简短人工点检见[固定与排序菜单控件](./固定与排序菜单控件.md)。后续同类入口必须复用该控件契约，不得在业务页面复制一套固定与排序 DOM。

- 已置顶入口常驻 Ribbon，未置顶入口进入所属模块的 `…` 菜单。
- Code 模块首次启动默认固定顺序为“代码辅助 → Git → Run → 替换 → 自动代码”；只用于没有持久化布局的新用户，不覆盖已有用户的置顶和排序。`…` 菜单提供“重置 Code 默认顺序”，只重置 Code 的顺序与固定项，保留 CAD 和其他模块的用户偏好。
- 代码辅助的 Primary 内部叶子必须复用统一的 Current Tool 外壳：Tool 图标、标题、`×`、操作区和关闭清理语义一致。关闭叶子只更新逻辑工具/MRU，不关闭 Editor 或后台任务；只打开独立 Editor 的入口仍通过相同叶子激活通道投影必要摘要，不创建第二套 Primary 运行时。
- Webview 动作必须发送真实叶子 `toolId`，不得把扫描、预检或写入动作发送给聚合容器。Host 找不到工具或动作不在声明契约中时，必须写入 `[Primary][信号][ERROR]` 并回传可见错误状态，禁止静默吞掉信号。
- 界面只保留一个 `…`，固定在 Toolbar Strip 最右；菜单内按模块分组，不得在 Code/CAD 尾部各放一个。
- 原生 View Header 常驻目录显隐、Ignore、Settings，顺序固定。目录动作只切换 Directory；后两者打开两个同级逻辑工具并复用 Current Tool。Toolbar Strip 左侧箭头切换展开/紧凑，中间始终是同一份 Ribbon，右侧唯一 `…` 在两态都可用；弹层必须挂在 Webview 顶层，不能被中间轨道裁切。
- Code/CAD 显示开关只存在于 `…` 的树形分组 checkbox 中；分组箭头只折叠菜单列表，checkbox 只控制模块显示。
- `…` 菜单必须以 Header 按钮为锚点并夹在 Webview 可见区内；窄宽时允许菜单内部滚动，不允许裁切文字和固定操作。
- 当前打开但未置顶的工具允许临时显示；临时显示不改变置顶集合。
- 已置顶入口支持在 Ribbon 中同模块拖动排序；`…` 可对模块内全部工具整行拖动，并提供键盘可用的上移和下移，使未置顶工具以后固定时也保留所选位置。
- 置顶集合与顺序属于本机 UI 偏好，由 Extension Host `globalState` 保存；不得写入工程设置。
- Current Tool Block Body 内的功能都以满宽紧凑方式嵌入；不保留外层卡片式左右空隙，但每一行、表格或输入控件必须保留自身必要内边距，避免内容贴边或相互重叠。
- 模块标签和入口按内容宽度连续排列，模块切换不强制另起一行。

### 3.3 三种状态

| 状态 | 表现 | 含义 |
| --- | --- | --- |
| 当前显示 | 强活动高亮、活动边框 | 当前逻辑工具；Current Tool Body 始终展开 |
| 已打开但隐藏 | 次级强调色、底部强调线 | 有逻辑工具，可切回 |
| 未打开 | 普通背景和前景 | 当前没有逻辑工具 |

- 不得只靠颜色传达状态；tooltip 和 `aria-label` 必须写明“当前显示”或“已打开，当前隐藏”。
- 已打开按钮的 tooltip 应显示当前打开总数。
- 切换模块不得清除其他模块的工具状态或结果缓存。

### 3.4 单显示、多打开与关闭顺序

- 打开顺序使用 MRU（最近使用优先）记录，最近使用项位于栈顶。
- 点击已打开的后台模块时，将其移到 MRU 栈顶并显示。
- 关闭当前 Current Tool 时，只移除当前逻辑工具，随后显示 MRU 中最近使用的剩余工具。
- 关闭最后一个逻辑工具后在 Current Tool 位置显示欢迎内容；Directory、Toolbar Strip 与 Open Items 区域仍保留。
- 关闭逻辑工具不等于清空工具结果，也不关闭 Editor 或取消任务；重新打开时允许重放 Host 缓存。
- 2026-09-09 确认：项目改名、编译工具、头文件引用修正的最后一个 Right 关闭时，同时关闭对应 Primary 和 Open Item，沿用 MRU/欢迎回退，不触发扫描、构建或其他工具业务，也不抢焦点。同工具仍有其他 Right 时保留 Primary。自动代码除外，其 Editor 按 JSON 文档管理；不改变关闭 Primary 不关闭 Right 的反向规则。
- VS Code 重启后的打开栈默认不持久化；如以后持久化，必须按工作区保存并处理已删除模块。

示例：依次打开 `头文件 → 搜索替换 → 编码`，关闭编码后显示搜索替换，再关闭后显示头文件。

### 3.5 Ribbon 高度

- Ribbon 内容必须紧贴按钮行，不设置额外最小高度或占位空白。
- VS Code 没有锁定 Webview View 高度的公开 API，因此 Directory、Toolbar Strip、Current Tool 和 Open Items 必须位于同一个 Webview View 内。
- 四段之间不渲染可拖动分隔条；展开态 Toolbar 高度只由入口数量、侧栏宽度和自然换行决定，紧凑态固定为一行图标轨道。
- 用户仍可调整整个侧栏和 View Container；不得用脚本循环测量或强制修改原生布局。

## 4. Current Tool Block 布局

当前逻辑工具只允许有一个 Current Tool Block 投影，按下列顺序组织：

1. Shell 管理的紧凑 Header：左侧包含当前 Tool 图标和标题，右侧包含明确的 `×`；没有折叠箭头或折叠占位，关闭必须可键盘到达。
2. 工作区摘要：只保留必要路径或工作区名称，尽量一行。
3. 扫描/搜索范围：文件工具复用 Shell 级单工作目录；不得恢复工作集下拉。
4. 主操作：预览、扫描、修复、替换、应用等高频按钮放在操作区第一行。
5. 模块选项：输入框、checkbox、策略、过滤和高级规则。
6. 运行状态：明确说明动作、范围、数量、成功、无结果或错误。
7. 结果列表：紧跟状态，不跳到第二个 View。
8. 说明文字和低频入口：放在操作区尾部，避免把主按钮推到首屏外。

布局约束：

- Current Tool Block 使用侧栏全部可用宽度，不设置页面式 `max-width`。
- Header 与摘要应紧凑，通常控制在 2～3 行内。
- 不重复显示原生 View Header 已经包含的插件标题。
- 不在 Current Tool Block 内再套一个视觉上等价的“大卡片 Block”。
- 主操作不得因说明文字、其他模块或长结果而需要先滚动才能看到。
- 复杂选项可以渐进展开，但基础操作和当前范围始终可见。

### 4.1 Toolbar 下级导航控件

Tool Navigator 是 Toolbar 中当前 Ribbon Group 的下展内容，不是新的一级区域、Current Tool Body、第二个 Tool Header 或业务 Action 面板。首个实现由代码辅助验证，后续 Code/CAD 消费者必须复用同一模型与交互：

```text
Ribbon 行
└── 左缩进约 20px 的紧凑下级网格   [icon 短名称] […] [Aa]
```

- 导航节点非此即彼：`group` 只拥有子节点，`tool` 只引用稳定 `toolId`；扫描、写入、启动等 Action 不进入导航树。
- 正式 Shell 使用无可见标题的紧凑网格，不提供“大纲 / 网格”双模式。网格列数由 Tool Navigator 自身宽度决定，侧栏变化不得切换到另一套状态机。
- `Aa` 只切换短名称显示，不激活工具，不改变 Current Tool、MRU、任务、Editor、草稿或权限；完整名称始终保留在 tooltip 和无障碍名称中。
- 隐藏名称时图标保持可辨识尺寸；当前 Group 没有下级 Tool 时，整个下级导航、边框和 `Aa` 都必须消失，不保留空行。
- 下级导航相对 Ribbon 内容左缩进，以“上边开放、左右与底边包围”的样式表达它属于当前 Group；Ribbon 与下级网格之间不使用通长横线。
- Tool Navigator Web Component 不依赖 `vscode`、存储、文件系统或业务 Controller；只接收可序列化模型并发送结构化的选择与标签显示 intent。
- 所有 Tool 叶子必须保留相同的选中状态、禁用原因和可访问名称。图标缺失时要有稳定回退，不允许空按钮。
- 展现偏好由 Host 持久化；能力树本身来自版本化配置，不得被用户状态复制或改写。

## 5. 工作目录、Ignore 与工作集退场

- 日常文件工具使用 Toolbar Strip 上方统一的 Directory，不得各自重复目录下拉或在运行后临时弹 QuickPick。Directory 始终是一行且不是可折叠 Block；它只可由原生 Header 的目录动作整体显示或隐藏。
- 工作目录默认当前 Workspace Folder；下拉提供多根工作区、一级子目录与最近目录，右侧唯一文件夹按钮允许切换到一个外部目录。左侧不渲染仅用于对齐的装饰文件夹，只用内边距对齐 `目录` 文案。
- 本期保持单工作目录；多目录是否有必要尚未明确，不得先增加目录列表、标签或集合配置。
- Ignore 只显示“插件内置 / Git / 自定义”三个独立来源，默认启用前两项；`.phoenix/.ignore` 只代表默认关闭的自定义来源。不得宣称已覆盖嵌套规则或完整 Git Ignore 语义。
- 目录与过滤的结果为“工作目录候选 - 当前启用的三个来源”；工具自身文件类型规则在该结果上继续求交集。symlink、不可读目录、二进制和大文件是安全边界，不伪装成 Ignore 来源。
- 原生 View Header 依次放固定目录显隐、Ignore、Settings。目录显隐只控制 Directory 且保留选择；Ignore 打开“忽略设置”逻辑工具，Settings 打开“设置”逻辑工具；二者都投影到 Current Tool。搜索替换可在自身内容内显示同一来源的紧凑折叠区。Directory 只保留目录上下文、下拉和实际目录选择。
- 工作集退出日常扫描主流程，不放入目录或新增一级区域，也不与目录/Ignore 继续组合。兼容读取在完成消费者审计前保留，但不得新增消费者。
- `.phoenix/` 是普通源文件扫描的硬排除目录；显式读取工作集配置不算源文件扫描。

## 6. 操作、运行状态与缓存

### 6.1 运行入口

- Primary 和 Right 的业务按钮默认以文字为主；仅用户明确要求时使用纯图标或“图标＋文字”。图标辨识度低，Primary 空间有限，文字更直接。理由见[插件开发指导](插件开发指导.md)；不改变已约定的外层导航及通用关闭/折叠控件。
- 用户点击 Current Tool Block Body 内主按钮后才进入 `running`。
- `running` 时禁用会产生重复任务的按钮，并显示正在执行的动作和有效范围。
- 光标或按钮转圈不能成为唯一反馈。
- 只有 `running` 状态可以使用进度/繁忙光标；因输入不完整而禁用的按钮使用普通禁用光标，并在按钮附近说明缺少的条件。
- 禁用按钮必须提供可操作原因的 tooltip 和可访问文案；由于原生 `disabled` 元素可能不触发悬停，tooltip 应挂在外层容器，按钮使用 `aria-describedby` 或等价语义关联原因。
- 单 View 容器的原生 View 名称与容器标题都使用 `KT Auto Code`，避免 VS Code 合成为 `KT Auto Code: 工具栏`；第二段 Toolbar Strip 用 `aria-label="工具栏"` 表达职责，不再显示一行“工具栏”标题文字。
- 不得把多个连续 QuickPick/InputBox 当作常规配置界面；多字段配置必须留在 Current Tool Block 或对应复杂 Editor。
- 扫描策略、转换方式、过滤、搜索条件等常规参数必须在 Current Tool Block Body 中直接选择，不得在点击主按钮后再弹 QuickPick。
- QuickPick 仅用于明确的一次性低频选择，且不得形成无法判断进度的长链；工作集已停用，不能再作为示例或新入口。
- 写盘、还原、清除系统值等高风险动作保留模态确认；文件/目录选择保留系统选择器。
- 普通成功、无结果和可恢复错误只更新 Current Tool Block 状态，不再同时弹出重复通知。

### 6.2 终止状态

每次任务必须结束为以下之一：

- `done`：成功，有结果或明确无结果。
- `idle`：用户主动取消且没有错误。
- `error`：输入、工作目录、文件系统或算法执行失败，并显示可操作原因。

所有异常路径都必须结束 `running`，恢复按钮状态。

### 6.3 结果缓存

- 新扫描完成后替换该模块的会话缓存。
- 运行期间保留旧结果，避免列表闪空；状态明确写“正在重新扫描”。
- 应用写盘后只更新缓存行的状态、选择和诊断，不自动重新扫描或重新生成预览。
- 用户取消勾选后，应用其余文件不得恢复已取消的选择。
- 从后台逻辑工具切回 Current Tool Block 时重放同一缓存，不重新执行任务。
- “关闭候选”只从当前缓存隐藏/取消该行，不删除文件，也不触发重扫。

## 7. 结果列表规则

结果列表参考 VS Code Search 与 Source Control，而不是桌面表格：

- 文件名在前，目录在后，二者属于同一弹性行。
- 文件名尽量完整显示，不先压缩；目录使用剩余宽度并从尾部省略。
- 右侧依次放悬停操作和短状态，操作不得挤掉文件名。
- 常见分组包括：待写盘、已写盘、变更文件、无变更文件、错误或已阻止。
- 支持批量操作时，组和行使用统一 checkbox；组 checkbox 正确表达全选、部分选择和禁用。
- 默认只显示有改动的文件；“显示无变更文件”作为显式筛选。
- 行点击的默认行为是打开文件；Diff、应用、Git Diff、还原和取消使用独立图标按钮。
- 行内按钮默认可在悬停/聚焦时出现，但键盘用户必须能够访问。
- 没有结果时显示明确空状态，例如“没有匹配结果”或“未发现需修正文件”，不得只留下空白。

### 命中高亮

- 搜索替换结果的文件名仅高亮匹配片段，不整行染色。
- 打开文件后，编辑器命中使用统一的问题高亮及 VS Code 概览尺警告标记。
- 头文件 ASCII 在纯 ASCII 模式下按连续的非 ASCII 文本整段高亮，不得把字节列号直接当作混合中英文的编辑器字符列。
- 问题位置使用黄色半透明底色与警告色边框，同时保留概览尺标记，确保浅色和深色主题都醒目。
- 编码结果打开文件只定位文件，不生成字符问题高亮；若同一编辑器残留其他模块的装饰，必须先清除。
- 切换到无关编辑器后清除上一文件的装饰。

## 8. 预览、写盘、Diff 与还原

- 预览默认只更新结果缓存，不自动逐文件弹出 Diff。
- 用户点击某一行的“预览差异”后，才打开该文件的只读预览 Diff。
- 预览不得创建难以管理的 untitled 文件；使用只读内容提供器或 VS Code 支持的资源 URI。
- 批量应用前必须确认；写盘前比较预览快照，阻止覆盖外部修改。
- 应用后不得自动逐个打开 Diff，只更新行状态为“已写盘”。
- 已写盘行提供按需 Git Diff，调用 VS Code SCM/Git，不自行实现 Git 差异界面。
- 还原仅允许撤销本次会话写入；还原前再次核对文件内容，阻止覆盖用户后续修改。

## 9. 按钮和图标

- 主按钮使用文字，低频行内操作优先使用 VS Code 常见图标语义。
- 打开、预览 Diff、应用、Git Diff、还原、取消等图标在各模块保持一致。
- 优先使用 codicon 或现有统一 SVG，不为同一语义重复创建图标。
- 不支持的图标动作应隐藏或禁用，不得留下无图标的空白按钮。
- 每个图标按钮必须有 tooltip、`aria-label`、键盘焦点和足够点击区域。
- `×` 在结果行表示取消当前候选；Current Tool Header 的 `×` 表示关闭当前逻辑工具，两者不可混用。后者不得隐式关闭 Editor 或 cancel/stop 任务。

## 10. 配置界面边界

- 多字段、需要反复调整的功能配置放 Current Tool Block 或对应复杂 Editor。
- VS Code Settings 只保留真正的插件偏好，例如默认行为、外部编辑器和显示模式。
- 操作系统环境变量不伪装成 VS Code Settings；使用“工程环境”Current Tool Block 展示、刷新和修改。
- 系统级设置、外部编辑器和 Git 等宿主能力优先调用原生界面。
- 高级界面只能有一个权威入口；不得在 Current Tool Block、旧 Webview 和 QuickPick 中维护三份相同配置。

## 11. 状态和消息协议

- Webview 与 Extension Host 的消息类型集中定义在 `tools/types.ts`。
- 跨边界数据必须可结构化克隆，不传函数、URI 类实例、DOM 节点或不可序列化对象。
- Host 合并更新工具状态；局部状态更新不得意外清空旧结果。
- 一次性 UI 请求（例如临时规则选择器）不进入可重放的持久工具状态。
- 新增消息必须包含明确 `type` 和必要的 `toolId`，Provider 负责兜底异常。

## 12. 样式、主题与可访问性

- 使用 VS Code CSS variables，不硬编码只适合浅色或深色主题的前景/背景。
- 验证深色、浅色和高对比度主题；状态不能只靠红/绿/蓝区分。
- 侧栏窄宽度不得产生页面级横向滚动。
- 文本输入、select、checkbox 和按钮使用原生 HTML 控件即可，不为基础控件引入 Element Plus。
- 当前 Webview 使用轻量 TypeScript/HTML；未来引入 Vue 或组件库必须单独证明复杂度和体积收益，且不得改变本文的 Host/View 边界。
- 文件路径、状态和按钮在 300～500px 常见侧栏宽度下均应可用。

### 12.1 界面文案

- 动作词统一：未运行用“扫描/预览”，计划修改用“待写盘”，成功修改用“已写盘”，撤销本次修改用“已还原”。
- 结果已在当前 Current Tool Block 时，不再写“扫描并打开结果”或“请到底部结果 View 查看”。
- 范围统一显示解析后的单工作目录；工作区外目录明确写“外部工作目录”。
- 转码目标在界面简写为 `UTF-8`，默认含义为 UTF-8 无 BOM。
- GBK 转码统一写 `GBK → UTF-8`；只有文件实际带 BOM 或操作专门讨论 BOM 时才写 `UTF-8 BOM`。
- 错误文案说明原因和下一步，不只写“失败”或“请重试”。

## 13. Webview 安全和资源

- 使用严格 CSP；脚本通过随机 nonce 授权，不允许远程脚本或宽泛 `unsafe-eval`。
- 图片和资源通过 `webview.asWebviewUri()` 或 CSP 允许的安全数据源加载。
- 不把用户文本拼入 `innerHTML`；必须使用 `textContent`，必要的模板文本要进行转义。
- Extension Host 校验消息类型、工具 ID 和工作目录；Webview 输入不能被当作可信路径。
- 生产 VSIX 不包含 source map、测试文件、示例源码或未使用资源。

## 14. UI 变更验收

每次改变 Header、Directory、Toolbar、Current Tool、Open Items 或结果行时至少检查：

- [ ] 点击 Ribbon 只打开/切换，不自动运行。
- [ ] 当前、后台已打开、未打开三态清晰，tooltip 与 `aria-label` 完整。
- [ ] Webview 恰好按 Directory → Toolbar Strip → Current Tool → Open Items 排列四个一级区域，没有旧两区/三段嵌套或额外正式一级 Block。
- [ ] 原生标题只显示 `KT Auto Code`；Header 动作依次为目录显隐、Ignore、Settings，搜索放大镜、目录齿轮和 Webview 内部 Ignore 图标均不存在。
- [ ] Directory 固定单行、没有折叠箭头或 Body；左侧无装饰文件夹，目录值占剩余宽度，右侧唯一文件夹按钮负责实际选择；Header 隐藏/恢复不改变选择或留下空白轨。
- [ ] Toolbar Strip 箭头只切换展开/紧凑且不产生完全隐藏态；中间只有一份 Ribbon，右侧只有一个 `…`，紧凑态隐藏入口都可从 `…` 到达。
- [ ] 有下级 Tool 的 Ribbon Group 显示无标题紧凑网格；无下级时整个下展区消失；`Aa` 只切名称且不改变激活状态。
- [ ] 页面不整体纵向滚动；长内容只在 Current Tool Body 内滚动，Directory、Toolbar、Current Tool Header 和 Open Items 固定；切换工具后恢复各自的内部滚动位置。
- [ ] Current Tool Header 左侧 Tool 图标和标题、右侧独立 `×` 均清晰可达；没有折叠按钮或占位；`×` 按 MRU 恢复上一个，Editor 与任务不受影响。
- [ ] Open Items 固定在底部，激活/关闭/关闭其他项与 Current Tool、Right View、MRU 同源；横向溢出和本区域 `…` 均可键盘到达。
- [ ] 项目改名、编译工具、头文件引用修正关闭最后一个 Right 后，对应 Primary/Open Item 一起关闭；其他工具、存活 Right 和自动代码 JSON 不受影响；迟到消息不得复活已关闭项。

## 15. 规则维护

- 新增通用 UI 行为时，先更新本文，再更新实现和自动化点检。
- 四段 Primary Shell 契约是特殊锁定规则；除非用户在看到冲突提示后明确批准，不得降级、删除或用新计划默认覆盖。
- `0.x` 功能计划只链接本文并记录偏差，不复制整套规则。
- Phoenix Webview Preview 是长期保留的设计沙箱和行为金样本。新的外壳、大区域、宿主交互或视觉基线变更必须先在 Preview 实现，通过浏览器注释取得用户确认后，再有意识地同步到正式 Host、本文和回归测试。
- **风险分流试行规则**：不机械地把每个像素改动实现两遍。外壳结构、大区域、不确定交互和仍有争议的视觉方向继续先走 Preview；已确认共享组件内的孤立小尺寸调整可以直接修改同一个 Host-neutral 组件，使 Preview 与 Host 同时消费；尚有争议的小效果只在 Preview adapter 中覆盖组件 token，并保持正式 fallback 不变，确认后再把同一值提升为正式默认或 adapter 值。试验不得复制组件 DOM、业务逻辑或事件协议；如出现两套维护、token 漂移或“确认后仍需重写”，应停止试行并回顾流程。
- Preview 允许在研究阶段超越正式契约，但必须在跟踪文档记录差异；Preview 通过不等于 Extension Host、真实生命周期或发布门禁通过。
- 正式 UI 每达到一个可独立展示且已通过自动门禁的阶段成果，启动一次可见的 VS Code Extension Host 交给用户查看真实效果；不能只以后台 smoke 或浏览器 Preview 代替阶段展示。展示本身不是默认验收，VS Code 特有差异要回写跟踪文档。
- 其他临时试验若与本文冲突，必须在试点文档中写明范围和退出条件。
- 已废弃方案应标记为历史，不与当前规则并列陈述。
