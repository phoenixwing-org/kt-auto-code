# UI 开发规则

> 适用范围：KT Auto Code 的 VS Code / Cursor 插件界面。
> 本文是当前 UI 的权威规则；功能计划只记录目标和进度，不重复维护交互规范。
> 2026-09-06 起以“单 View Shell + 可显隐目录 + 工具区域内无 Header Tool Surface”为目标基线。实施顺序与联动计划见 [0.9.0 Primary 与 Editor 联动及统一工具运行时计划](./0.9.0-Primary与Editor联动讨论稿.md)。旧的多 View、并列区域 Shell、独立 Sub Tool Header、独立结果 TreeView 和编辑区 Workbench 方案仅作历史参考。

## 1. Primary 目标界面架构

插件只贡献一个主侧栏 Webview。原生 View Header 和 Webview 内容按下列层级组织：

```text
KT Auto Code                            [目录显隐] [忽略] [设置]
├─ 目录 Row（默认显示，可由 Header 隐藏）：固定一行，表达共享目录
└─ Tool Area
   ├─ Toolbar Strip：`箭头 + Ribbon + …` 共用一层；无独立标题行
   └─ Tool Surface：无 Header；内容独立滚动，右上角悬浮 `×`
```

Webview 的一级区域只有“目录 Row”和“Tool Area”两个槽位。目录隐藏时只改变第一个槽位的可见性，不销毁所选目录或上下文；Toolbar Strip 与 Tool Surface 都是 Tool Area 的内部子级，不得重新解释成额外一级区域。

Toolbar Strip 的两态示意；中间始终是同一份入口 DOM：

```text
展开  ⌄ │CODE│ [代码辅助] [Git] [Run] [替换] [自动代码] │CAD│       […]
             图标 + 现有短标题；空间不足时自然换到后续行

紧凑  › [图标] [图标] [图标] [图标] [图标]  ⇆                   […]
             单行仅图标，中间轨道可横向滚动；完整名称由 Tooltip / aria-label 提供
```

术语统一：

| 术语 | 定义 |
| --- | --- |
| 原生 View Header | VS Code 提供的 View 标题操作区；当前固定核心动作是目录显隐、Ignore、Settings |
| 目录 Row | Shell 管理的单行共享工作目录；可隐藏但上下文不丢失 |
| Tool Area | Webview 第二个一级区域；依次容纳 Toolbar Strip 和一个 Tool Surface |
| Ribbon | Toolbar Strip 中唯一一份工具入口 DOM，不承载任务结果 |
| Tool Surface | Tool Area 内唯一可见的二级工具内容区；没有独立 Header 行 |
| 逻辑工具 | 某工具在 MRU 打开栈中的状态；可以当前显示，也可以后台隐藏 |
| 结果分组 | Tool Surface 内的待写盘、已写盘、无变更等列表分组，不是独立 Block |

- Ribbon 只负责打开、切换模块和表达打开状态，不直接扫描、预览或写盘。
- 目录 Row 与 Tool Area 全宽连续相接，不用卡片外边距、内部拖动分隔条或人工高度。Tool Surface 紧跟 Ribbon，不渲染标题 Header。
- Toolbar Strip 的箭头只切换“展开图标与文字 / 紧凑仅图标”，不隐藏 Tool Surface 或目录。重复点击当前 Ribbon Tool/Group 才切换 Tool Surface 的展开/收起；两个切换互不重置。
- 页面与 Tool Area 都不作为日常纵向滚动边界；只有 Tool Surface 内容填充剩余高度并独立滚动。
- 同一时刻只显示一个 Tool Surface，但允许多个工具处于逻辑打开状态。
- Tool Surface 上部放操作界面，下部放本次会话缓存结果；不得再创建第二个结果 View。
- 文件预览、文本编辑、Diff 和 Git 变更继续使用 VS Code 原生编辑器与 SCM。
- Ribbon、菜单、命令和 Editor 传入的直接叶子 `toolId` 必须进入同一套激活、状态、MRU 与关闭运行时，入口来源只影响焦点和诊断。
- 原生 View Header 固定依次提供“目录显隐、忽略、设置”。后二者打开同级逻辑工具并复用同一个 Tool Surface；目录动作只控制目录 Row 可见性。

### 1.1 锁定的两区外层契约

2026-09-06 用户已明确确认下列 Primary Shell 方案，并据此替换旧并列区域契约。此处记录的是目标与回归边界，不代表新布局已经完成人工 UI 点检：

1. 原生 View Header 的当前核心动作顺序固定为“目录显隐 → Ignore → Settings”。目录显示时用 `folder-opened` 和 Tooltip“隐藏目录”，隐藏时用 `folder` 和 Tooltip“显示目录”。首次使用默认显示；之后持久化用户的可见性偏好。隐藏只改变展示，所选目录与上下文必须保留。以后只允许少量、真正全局且高频的动作通过显式契约评审加入 Header；普通工具动作不得借此扩张 Header。
2. 一个 Webview View 只有两个一级区域，顺序固定为“可显隐的目录 Row → Tool Area”。目录 Row 显示时是无箭头、无 Body 的固定单行；隐藏时不由 Toolbar 或 Tool Surface 补位出额外一级区域。
3. Tool Area 内部只按“Toolbar Strip → 一个无 Header Tool Surface”排列。两者是 Tool Area 内部层级，不是两个新的一级 Section。Ignore 与 Settings 也通过同一个 Tool Surface 运行时显示。
4. Toolbar Strip 只有展开与紧凑两态：展开保留图标、短标题和自然多行换行；紧凑把同一组入口收成单行小图标。左侧箭头不产生完全隐藏状态，也不改变目录可见性或 Tool Surface 展开状态。
5. Ribbon 定制只有一个 `…`，固定在 Toolbar Strip 右侧；箭头位于左侧，中间只渲染一份 Ribbon DOM。不恢复 Code/CAD 多个 `…`，不把 Ribbon `…` 移入原生 View Header。
6. 当前 Ribbon Tool/Group 再次点击只收起或展开 Tool Surface；它不关闭逻辑工具、不改变 MRU，也不关闭 Editor、不 dispose、cancel/stop 任务或清空草稿与结果。切换其他工具，以及从菜单、命令、原生 Header 或 Editor 激活工具时，必须重新显示 Surface。
7. Tool Surface 右上角保留一个不占独立行、可键盘到达且带 Tooltip/`aria-label` 的悬浮 `×`。它只关闭当前逻辑工具并按 MRU 恢复上一个，不关闭 Editor、不 dispose、cancel/stop 任务，也不清空草稿或结果。
8. 目录 Row 与 Tool Area 使用连续分区；只有 Tool Surface 内容填充剩余高度并纵向滚动。页面、Tool Area 和 Toolbar 都不得成为日常滚动边界。
9. Ribbon、菜单、命令、Editor 等入口若指向同一个直接叶子 `toolId`，必须复用同一激活运行时；不得因入口层级复制工具实例、MRU、草稿或关闭逻辑。

两区 Shell 的目标视觉基线同时锁定：

- 目录 Row 与 Tool Area 全宽相接，不使用卡片圆角、左右外边距或一级区域间空白；用连续分隔线表达层级。Tool Surface 直接位于 Toolbar 之后，用弱分隔表达从属关系，不再增加二级 Header 行。
- Toolbar Strip 不显示“工具栏”文字：16px SVG 箭头位于左侧，Ribbon 占中间剩余宽度，唯一 `…` 固定右侧。展开态保留 Ribbon 图标、短标题、活动高亮和多行换行；紧凑态使用单行仅图标按钮，超出可见宽度的工具仍能从 `…` 到达。
- Ribbon 当前的展开/紧凑效果已获用户观感确认，是基本固定的交互基线。后续可以研究把更多二级菜单入口迁入统一工具模型，但不得借迁移重写这套两态行为、复制 Ribbon DOM 或重新增加独立标题行。
- 紧凑态不显示 `CODE`、`CAD` 等文字分组标签；模块边界由工具按钮的可访问名称、分组 `aria-label` 和唯一 `…` 内的模块分组保留。任何缺少图标的可选模块工具都必须生成可见的文字首字符回退，不得出现空白按钮。
- 原生 View 标题固定为 `KT Auto Code`，右侧当前依次为目录显隐、Ignore、Settings，不再放搜索预览。三项是已批准的最小核心集；未来新增常用全局图标必须少而明确，并同步修改契约与回归测试。Webview 内目录 Row 保留目录下拉和实际目录选择动作，不增加装饰性左文件夹、目录齿轮或内部 Ignore；Toolbar Strip 不显示密度按钮；Tool Surface 不显示 Header，逻辑关闭使用右上悬浮 `×`。
- Hover、focus、高对比度边框和折叠后的操作入口继续使用 VS Code 主题变量，不写死颜色。
- 新层级已获方案确认，但深色、浅色、高对比度、窄宽和真实 Extension Development Host 观感仍须按验收清单完成，不得提前写“人工测试通过”。

该契约锁定“外层结构和行为语义”，不锁死每个工具内容的演进：

- 允许优化各区的标题文案、图标、按钮排布、间距、响应式布局、无障碍和高对比度效果；目录 Row 当前的位置、单行结构、目录文字、下拉、右侧选择动作、显隐持久化及隐藏不丢上下文是已确认并基本固定的 UI/行为基线。
- 允许增删、重组或改进 Tool Area 内部功能，前提是不把职责偷渡到原生 Header 或目录 Row，不改变 Toolbar 两态、当前 Ribbon 项控制 Surface 显隐、唯一滚动和悬浮关闭语义。
- Toolbar 不依赖可见标题表达职责，必须用区域 `aria-label`、箭头 Tooltip 和工具按钮名称保留“工具入口”语义；目录 Row 标题继续明确，Tool Surface 用动态 `aria-label` 保留当前工具语义而不恢复可见标题行。
- 后续等价组件化见[ShellBlock 控件提炼 TODO](./ShellBlock控件提炼TODO.md)；组件化不得与功能修改合并，也不得作为改变当前效果的理由。

如果用户或新计划要求改变一级区域数量、顺序、Header 动作、目录持久化、Tool Area 嵌套、折叠/滚动边界、唯一 `…` 或 `×` 语义，执行者必须在编码前：

1. 明确提示“该请求会改变已锁定的两区 Primary Shell 契约”。
2. 列出被改变的具体规则、原因、迁移影响和需回归的交互。
3. 等待用户明确确认后，才能同时修改规则、实现和测试；不得把该变更夹带在普通功能、样式清理或重构中。

### 1.2 Codegen 数据编辑 View 例外

Codegen 的17列参数表属于结构化文档编辑，不属于扫描结果，因此允许在编辑区打开专用 Webview View：

- 左侧仍只复用一个 Tool Surface，负责 JSON 列表、打开、CSV 导入、刷新、活动文档摘要和 Prefix/Middle/Namespace/Append 属性。
- 一份 JSON 对应一个右侧编辑 View；重复打开同一 JSON 时复用原 View。
- 当前编辑区的 Codegen 标签激活时，必须把活动 JSON、打开状态和未保存状态同步回左侧 Tool Surface。
- View 组合文档级工具栏和独立 `KtCodegenTable`；属性由活动文档 Tool Surface 编辑，表格组件不负责文件选择、写盘和生成动作。
- 表格内部可以逐格编辑，但跨 Webview/Host 边界只发送首次 dirty 通知，并在保存或生命周期同步点交换整份草稿，禁止每个单元格都与 Host 往返。

## 2. 分层和运行时边界

### Extension Host

- 负责文件系统、扫描、转换、工作集解析、确认框、配置、缓存和 VS Code 命令。
- `ToolUiState` 及工具会话是任务状态和结果的权威来源。
- 状态更新发送给唯一 Shell View；View 重建后必须能重放 Host 快照。
- 捕获工具入口的未处理异常，并把状态从 `running` 收敛到 `error`，不得无限转圈。

### Webview

- 只负责展示、收集输入、筛选、勾选和发送语义化消息。
- 不直接读写工作区、环境变量或 VS Code 配置。
- 不实现成员排序、UUID、编码、搜索替换等领域算法。
- 只保存界面局部状态，例如表单草稿、展开、筛选和当前选择。

### 共享核心

- 可跨产品复用的纯算法放根目录 `src/` 或 `phoenix-wing/code-core`。
- VS Code API、Git 命令、Webview、QuickPick 和工作区生命周期不得进入 Wing。

## 3. Ribbon 规则

### 3.1 入口行为

- 点击 Ribbon 只打开或切换模块，不自动执行扫描、预览、替换或修复。
- 重复点击当前 Ribbon Tool/Group 只切换 Tool Surface 的展开/收起，不得关闭逻辑工具；关闭只能通过 Surface 右上角明确的悬浮 `×` 执行。
- 展开 Ribbon 随入口换行自然增高；紧凑 Ribbon 保持单行，仅自身中间轨道可横向滚动，不得让页面产生横向滚动。工具内容只能出现在同一 Tool Area 下方的 Tool Surface。
- “图标与文字”和“仅图标”行为一致，仅显示方式不同；左侧箭头直接切换两态，不增加完全隐藏的第三态，也不另设密度按钮。
- Ribbon、`…` 菜单、命令面板和 Editor 只能发送注册过的直接叶子 `toolId`；四种来源必须调用同一个激活运行时。聚合目录 ID 不得代替叶子执行，`source` 只用于焦点保持和诊断。

### 3.2 置顶、更多与排序

具体控件边界、交互细节和简短人工点检见[固定与排序菜单控件](./固定与排序菜单控件.md)。后续同类入口必须复用该控件契约，不得在业务页面复制一套固定与排序 DOM。

- 已置顶入口常驻 Ribbon，未置顶入口进入所属模块的 `…` 菜单。
- Code 模块首次启动默认固定顺序为“代码辅助 → Git → Run → 替换 → 自动代码”；只用于没有持久化布局的新用户，不覆盖已有用户的置顶和排序。`…` 菜单提供“重置 Code 默认顺序”，只重置 Code 的顺序与固定项，保留 CAD 和其他模块的用户偏好。
- 代码辅助的 Primary 内部叶子必须使用统一的 Tool Surface：无专用 Header，显隐由当前 Ribbon Tool/Group 重复点击控制，悬浮 `×`、操作区和关闭清理语义一致。关闭叶子只更新逻辑工具/MRU，不关闭 Tool Area、Editor 或后台任务。只打开独立 Editor 的入口仍通过相同叶子激活通道投影必要摘要，不创建第二套 Primary 运行时。
- Webview 动作必须发送真实叶子 `toolId`，不得把扫描、预检或写入动作发送给聚合容器。Host 找不到工具或动作不在声明契约中时，必须写入 `[Primary][信号][ERROR]` 并回传可见错误状态，禁止静默吞掉信号。
- 界面只保留一个 `…`，固定在 Toolbar Strip 最右；菜单内按模块分组，不得在 Code/CAD 尾部各放一个。
- 原生 View Header 常驻“目录显隐、忽略范围、设置”，顺序固定。目录动作只显示/隐藏目录 Row；Ignore 与 Settings 打开两个同级逻辑工具。Toolbar Strip 左侧箭头切换展开/紧凑，中间始终是同一份 Ribbon，右侧唯一 `…` 在两态都可用；弹层必须挂在 Webview 顶层，不能被中间轨道裁切。
- Code/CAD 显示开关只存在于 `…` 的树形分组 checkbox 中；分组箭头只折叠菜单列表，checkbox 只控制模块显示。
- `…` 菜单必须以 Header 按钮为锚点并夹在 Webview 可见区内；窄宽时允许菜单内部滚动，不允许裁切文字和固定操作。
- 当前打开但未置顶的工具允许临时显示；临时显示不改变置顶集合。
- 已置顶入口支持在 Ribbon 中同模块拖动排序；`…` 可对模块内全部工具整行拖动，并提供键盘可用的上移和下移，使未置顶工具以后固定时也保留所选位置。
- 置顶集合与顺序属于本机 UI 偏好，由 Extension Host `globalState` 保存；不得写入工程设置。
- Tool Surface 内的功能都以满宽紧凑方式嵌入；不保留外层卡片式左右空隙，但每一行、表格或输入控件必须保留自身必要内边距，避免内容贴边或相互重叠。
- 模块标签和入口按内容宽度连续排列，模块切换不强制另起一行。

### 3.3 三种状态

| 状态 | 表现 | 含义 |
| --- | --- | --- |
| 当前显示 | 强活动高亮、活动边框；Tooltip 说明再次点击可收起 | 当前 Tool Surface 展开 |
| 当前收起 | 保持强活动高亮；Tooltip 说明再次点击可展开 | 逻辑工具仍为当前项，Surface 暂时隐藏 |
| 已打开但隐藏 | 次级强调色、底部强调线 | 有逻辑工具，可切回 |
| 未打开 | 普通背景和前景 | 当前没有逻辑工具 |

- 不得只靠颜色传达状态；tooltip 和 `aria-label` 必须写明“当前显示”或“已打开，当前隐藏”。
- 已打开按钮的 tooltip 应显示当前打开总数。
- 切换模块不得清除其他模块的工具状态或结果缓存。

### 3.4 单显示、多打开与关闭顺序

- 打开顺序使用 MRU（最近使用优先）记录，最近使用项位于栈顶。
- 点击已打开的后台模块时，将其移到 MRU 栈顶并显示。
- 关闭当前 Tool Surface 时，只移除当前逻辑工具，随后显示 MRU 中最近使用的剩余工具。
- 关闭最后一个逻辑工具后在 Tool Surface 位置显示欢迎内容；Toolbar Strip 保留，目录 Row 保持用户当前的显示或隐藏状态。
- 关闭逻辑工具不等于清空工具结果，也不关闭 Editor 或取消任务；重新打开时允许重放 Host 缓存。
- VS Code 重启后的打开栈默认不持久化；如以后持久化，必须按工作区保存并处理已删除模块。

示例：依次打开 `头文件 → 搜索替换 → 编码`，关闭编码后显示搜索替换，再关闭后显示头文件。

### 3.5 Ribbon 高度

- Ribbon 内容必须紧贴按钮行，不设置额外最小高度或占位空白。
- VS Code 没有锁定 Webview View 高度的公开 API，因此 Toolbar Strip 与 Tool Surface 必须位于同一个 Webview Tool Area 内。
- Toolbar Strip 和 Tool Surface 之间不渲染可拖动分隔条；展开态高度只由入口数量、侧栏宽度和自然换行决定，紧凑态固定为一行图标轨道。
- 用户仍可调整整个侧栏和 View Container；不得用脚本循环测量或强制修改原生布局。

## 4. Tool Surface 布局

当前逻辑工具只允许有一个 Tool Surface 投影，按下列顺序组织：

1. 右上悬浮关闭：`×` 不占独立行，必须可键盘到达，不遮挡首个主操作；原生 View Header 不重复提供关闭当前工具。
2. 工作区摘要：只保留必要路径或工作区名称，尽量一行。
3. 扫描/搜索范围：文件工具复用 Shell 级单工作目录；不得恢复工作集下拉。
4. 主操作：预览、扫描、修复、替换、应用等高频按钮放在操作区第一行。
5. 模块选项：输入框、checkbox、策略、过滤和高级规则。
6. 运行状态：明确说明动作、范围、数量、成功、无结果或错误。
7. 结果列表：紧跟状态，不跳到第二个 View。
8. 说明文字和低频入口：放在操作区尾部，避免把主按钮推到首屏外。

布局约束：

- Tool Surface 使用 Tool Area 的全部可用宽度，不设置页面式 `max-width`。
- 摘要应紧凑，通常控制在 1～2 行内；不得为了工具标题恢复整行 Header。
- 不重复显示原生 View Header 已经包含的插件标题。
- 不在 Tool Surface 内再套一个视觉上等价的“大卡片 Block”。
- 主操作不得因说明文字、其他模块或长结果而需要先滚动才能看到。
- 复杂选项可以渐进展开，但基础操作和当前范围始终可见。

### 4.1 Tool Navigator 内容控件

Tool Navigator 是 Tool Surface 内的功能导航，不是新的一级区域、Sub Tool Header 或业务 Action 面板。首个实现由代码辅助验证，后续 Code/CAD 消费者必须复用同一模型与交互：

```text
功能目录（数量）                               [大纲] [网格]
大纲：Group 单列折叠 → Tool 单列叶子
网格：Group 单列折叠 → Tool 按控件宽度排列为 1～多列
```

- 导航节点非此即彼：`group` 只拥有子节点，`tool` 只引用稳定 `toolId`；扫描、写入、启动等 Action 不进入导航树。
- `大纲 / 网格` 使用明确的可点击文字和 `aria-pressed`。切换只改变同一 ViewModel 的呈现，不激活或重复执行工具，不改变 MRU、任务、Editor、草稿和权限。
- 大纲始终保持单列与清晰阅读顺序。不得把层级 Tree 横向拆列；降低高度由网格模式负责。
- 网格根据 Tool Navigator 自身容器宽度响应列数，而不是根据整个窗口做媒体查询。拖动侧栏只能调整网格列数，不能自动覆盖用户选定的大纲/网格模式。
- Tool Navigator Web Component 不依赖 `vscode`、存储、文件系统或业务 Controller；只接收可序列化模型并发送结构化的选择、布局和折叠 intent。
- 控件标题行属于工具内容。它不得复制插件标题、当前 Tool Header 或逻辑关闭按钮；Tool Surface 右上悬浮 `×` 仍是唯一的逻辑关闭入口，并须预留不遮挡的空间。
- 大纲与网格必须渲染相同的 Tool 叶子集合、选中状态、禁用原因和可访问名称。图标缺失时要有稳定回退，不允许空按钮。
- 用户级布局和分组展开偏好由 Host 持久化；能力树本身来自版本化配置，不得被用户状态复制或改写。

## 5. 工作目录、Ignore 与工作集退场

- 日常文件工具使用 Webview 第一槽位统一的目录 Row，不得各自重复目录下拉或在运行后临时弹 QuickPick。目录 Row 显示时始终是一行；它不是可折叠 Block。
- 工作目录默认当前 Workspace Folder；下拉提供多根工作区、一级子目录与最近目录，行内实际目录选择按钮允许切换到一个外部目录。左侧不渲染仅用于对齐的装饰文件夹。
- 新用户/尚无偏好时目录 Row 默认显示。原生 Header 的首个动作负责显隐：显示态为 `folder-opened` / “隐藏目录”，隐藏态为 `folder` / “显示目录”。可见性偏好必须持久化；隐藏与再次显示不得更改所选目录、最近目录或下游工具正在使用的目录上下文。
- 本期保持单工作目录；多目录是否有必要尚未明确，不得先增加目录列表、标签或集合配置。
- Ignore 只显示“插件内置 / Git / 自定义”三个独立来源，默认启用前两项；`.phoenix/.ignore` 只代表默认关闭的自定义来源。不得宣称已覆盖嵌套规则或完整 Git Ignore 语义。
- 目录与过滤的结果为“工作目录候选 - 当前启用的三个来源”；工具自身文件类型规则在该结果上继续求交集。symlink、不可读目录、二进制和大文件是安全边界，不伪装成 Ignore 来源。
- 原生 View Header 依次放目录显隐、固定 Ignore、Settings。Ignore 打开“忽略设置”逻辑工具，Settings 打开“设置”逻辑工具；二者都投影到同一个 Tool Surface。搜索替换可在自身内容内显示同一来源的紧凑折叠区。目录 Row 只保留目录上下文、下拉和实际目录选择。
- 工作集退出日常扫描主流程，不放入目录 Row 或新增一级区域，也不与目录/Ignore 继续组合。兼容读取在完成消费者审计前保留，但不得新增消费者。
- `.phoenix/` 是普通源文件扫描的硬排除目录；显式读取工作集配置不算源文件扫描。

## 6. 操作、运行状态与缓存

### 6.1 运行入口

- 用户点击 Tool Surface 内主按钮后才进入 `running`。
- `running` 时禁用会产生重复任务的按钮，并显示正在执行的动作和有效范围。
- 光标或按钮转圈不能成为唯一反馈。
- 只有 `running` 状态可以使用进度/繁忙光标；因输入不完整而禁用的按钮使用普通禁用光标，并在按钮附近说明缺少的条件。
- 禁用按钮必须提供可操作原因的 tooltip 和可访问文案；由于原生 `disabled` 元素可能不触发悬停，tooltip 应挂在外层容器，按钮使用 `aria-describedby` 或等价语义关联原因。
- 单 View 容器的原生 View 名称与容器标题都使用 `KT Auto Code`，避免 VS Code 合成为 `KT Auto Code: 工具栏`；Tool Area 内的 Toolbar Strip 用 `aria-label="工具栏"` 表达职责，不再显示一行“工具栏”标题文字。
- 不得把多个连续 QuickPick/InputBox 当作常规配置界面；多字段配置必须留在 Tool Surface 或对应复杂 Editor。
- 扫描策略、转换方式、过滤、搜索条件等常规参数必须在 Tool Surface 中直接选择，不得在点击主按钮后再弹 QuickPick。
- QuickPick 仅用于明确的一次性低频选择，且不得形成无法判断进度的长链；工作集已停用，不能再作为示例或新入口。
- 写盘、还原、清除系统值等高风险动作保留模态确认；文件/目录选择保留系统选择器。
- 普通成功、无结果和可恢复错误只更新 Tool Surface 状态，不再同时弹出重复通知。

### 6.2 终止状态

每次任务必须结束为以下之一：

- `done`：成功，有结果或明确无结果。
- `idle`：用户主动取消且没有错误。
- `error`：输入、工作目录、文件系统或算法执行失败，并显示可操作原因。

所有异常路径都必须结束 `running`，恢复按钮状态。

### 6.3 结果缓存

- 新扫描完成后替换该模块的会话缓存。
- 运行期间保留旧结果，避免列表闪空；状态明确写“正在重新扫描”。
- 应用写盘后只更新缓存行的状态、选择和诊断，不自动重新扫描或重新生成预览。
- 用户取消勾选后，应用其余文件不得恢复已取消的选择。
- 从后台逻辑工具切回 Tool Surface 时重放同一缓存，不重新执行任务。
- “关闭候选”只从当前缓存隐藏/取消该行，不删除文件，也不触发重扫。

## 7. 结果列表规则

结果列表参考 VS Code Search 与 Source Control，而不是桌面表格：

- 文件名在前，目录在后，二者属于同一弹性行。
- 文件名尽量完整显示，不先压缩；目录使用剩余宽度并从尾部省略。
- 右侧依次放悬停操作和短状态，操作不得挤掉文件名。
- 常见分组包括：待写盘、已写盘、变更文件、无变更文件、错误或已阻止。
- 支持批量操作时，组和行使用统一 checkbox；组 checkbox 正确表达全选、部分选择和禁用。
- 默认只显示有改动的文件；“显示无变更文件”作为显式筛选。
- 行点击的默认行为是打开文件；Diff、应用、Git Diff、还原和取消使用独立图标按钮。
- 行内按钮默认可在悬停/聚焦时出现，但键盘用户必须能够访问。
- 没有结果时显示明确空状态，例如“没有匹配结果”或“未发现需修正文件”，不得只留下空白。

### 命中高亮

- 搜索替换结果的文件名仅高亮匹配片段，不整行染色。
- 打开文件后，编辑器命中使用统一的问题高亮及 VS Code 概览尺警告标记。
- 头文件 ASCII 在纯 ASCII 模式下按连续的非 ASCII 文本整段高亮，不得把字节列号直接当作混合中英文的编辑器字符列。
- 问题位置使用黄色半透明底色与警告色边框，同时保留概览尺标记，确保浅色和深色主题都醒目。
- 编码结果打开文件只定位文件，不生成字符问题高亮；若同一编辑器残留其他模块的装饰，必须先清除。
- 切换到无关编辑器后清除上一文件的装饰。

## 8. 预览、写盘、Diff 与还原

- 预览默认只更新结果缓存，不自动逐文件弹出 Diff。
- 用户点击某一行的“预览差异”后，才打开该文件的只读预览 Diff。
- 预览不得创建难以管理的 untitled 文件；使用只读内容提供器或 VS Code 支持的资源 URI。
- 批量应用前必须确认；写盘前比较预览快照，阻止覆盖外部修改。
- 应用后不得自动逐个打开 Diff，只更新行状态为“已写盘”。
- 已写盘行提供按需 Git Diff，调用 VS Code SCM/Git，不自行实现 Git 差异界面。
- 还原仅允许撤销本次会话写入；还原前再次核对文件内容，阻止覆盖用户后续修改。

## 9. 按钮和图标

- 主按钮使用文字，低频行内操作优先使用 VS Code 常见图标语义。
- 打开、预览 Diff、应用、Git Diff、还原、取消等图标在各模块保持一致。
- 优先使用 codicon 或现有统一 SVG，不为同一语义重复创建图标。
- 不支持的图标动作应隐藏或禁用，不得留下无图标的空白按钮。
- 每个图标按钮必须有 tooltip、`aria-label`、键盘焦点和足够点击区域。
- `×` 在结果行表示取消当前候选；Tool Surface 右上悬浮 `×` 表示关闭当前逻辑工具，两者不可混用。后者不得隐式关闭 Editor 或 cancel/stop 任务。

## 10. 配置界面边界

- 多字段、需要反复调整的功能配置放 Tool Surface 或对应复杂 Editor。
- VS Code Settings 只保留真正的插件偏好，例如默认行为、外部编辑器和显示模式。
- 操作系统环境变量不伪装成 VS Code Settings；使用“工程环境”Tool Surface 展示、刷新和修改。
- 系统级设置、外部编辑器和 Git 等宿主能力优先调用原生界面。
- 高级界面只能有一个权威入口；不得在 Tool Surface、旧 Webview 和 QuickPick 中维护三份相同配置。

## 11. 状态和消息协议

- Webview 与 Extension Host 的消息类型集中定义在 `tools/types.ts`。
- 跨边界数据必须可结构化克隆，不传函数、URI 类实例、DOM 节点或不可序列化对象。
- Host 合并更新工具状态；局部状态更新不得意外清空旧结果。
- 一次性 UI 请求（例如临时规则选择器）不进入可重放的持久工具状态。
- 新增消息必须包含明确 `type` 和必要的 `toolId`，Provider 负责兜底异常。

## 12. 样式、主题与可访问性

- 使用 VS Code CSS variables，不硬编码只适合浅色或深色主题的前景/背景。
- 验证深色、浅色和高对比度主题；状态不能只靠红/绿/蓝区分。
- 侧栏窄宽度不得产生页面级横向滚动。
- 文本输入、select、checkbox 和按钮使用原生 HTML 控件即可，不为基础控件引入 Element Plus。
- 当前 Webview 使用轻量 TypeScript/HTML；未来引入 Vue 或组件库必须单独证明复杂度和体积收益，且不得改变本文的 Host/View 边界。
- 文件路径、状态和按钮在 300～500px 常见侧栏宽度下均应可用。

### 12.1 界面文案

- 动作词统一：未运行用“扫描/预览”，计划修改用“待写盘”，成功修改用“已写盘”，撤销本次修改用“已还原”。
- 结果已在当前 Tool Surface 时，不再写“扫描并打开结果”或“请到底部结果 View 查看”。
- 范围统一显示解析后的单工作目录；工作区外目录明确写“外部工作目录”。
- 转码目标在界面简写为 `UTF-8`，默认含义为 UTF-8 无 BOM。
- GBK 转码统一写 `GBK → UTF-8`；只有文件实际带 BOM 或操作专门讨论 BOM 时才写 `UTF-8 BOM`。
- 错误文案说明原因和下一步，不只写“失败”或“请重试”。

## 13. Webview 安全和资源

- 使用严格 CSP；脚本通过随机 nonce 授权，不允许远程脚本或宽泛 `unsafe-eval`。
- 图片和资源通过 `webview.asWebviewUri()` 或 CSP 允许的安全数据源加载。
- 不把用户文本拼入 `innerHTML`；必须使用 `textContent`，必要的模板文本要进行转义。
- Extension Host 校验消息类型、工具 ID 和工作目录；Webview 输入不能被当作可信路径。
- 生产 VSIX 不包含 source map、测试文件、示例源码或未使用资源。

## 14. UI 变更验收

每次改变 Header、目录 Row、Toolbar、Tool Surface 或结果行时至少检查：

- [ ] 点击 Ribbon 只打开/切换，不自动运行。
- [ ] 当前、后台已打开、未打开三态清晰，tooltip 与 `aria-label` 完整。
- [ ] Webview 只有“可显隐目录 Row → Tool Area”两个一级区域；Tool Area 内严格按 Toolbar Strip、一个无 Header Tool Surface 排列，没有旧并列区或额外一级 Block。
- [ ] 原生标题只显示 `KT Auto Code`；Header 动作依次为目录显隐、Ignore、Settings，搜索放大镜、目录齿轮和 Webview 内部 Ignore 图标均不存在。
- [ ] 首次使用目录默认显示；Header 图标和 Tooltip 随显隐切换；重载后保持可见性偏好，隐藏/显示全程保留所选目录与工具上下文。
- [ ] Toolbar Strip 箭头只切换展开/紧凑且不产生完全隐藏态；重复点击当前 Ribbon Tool/Group 只切换 Tool Surface，不影响目录可见性、MRU 或任务状态；切换其他工具及菜单/命令/Header/Editor 激活会重新展开。
- [ ] 页面和 Tool Area 不整体纵向滚动；长内容只在 Tool Surface 内滚动，切换工具后恢复各自的内部滚动位置。
- [ ] Tool Surface 悬浮 `×` 可由键盘访问且不遮挡主操作；它按 MRU 恢复上一个，最后一个关闭后显示欢迎内容并保留 Toolbar，目录 Row 保持用户当前显隐状态，Editor 与任务不受影响。
- [ ] 同一直接叶子 `toolId` 从 Ribbon、菜单、命令、Editor 激活时复用同一状态、MRU、草稿恢复和关闭语义。
- [ ] 主按钮位于首屏上部，状态和结果位于同一个 Tool Surface。
- [ ] 连续运行不重复弹扫描范围，所有异常都能结束转圈。
- [ ] 工作目录、文件类型和 Ignore 的交集正确，非法范围不静默扩大。
- [ ] 运行中保留旧结果；应用后原地更新，不自动重扫或弹多个 Diff。
- [ ] 文件名优先完整显示，目录和状态按剩余宽度压缩。
- [ ] checkbox、行内按钮、空状态、键盘操作正常。
- [ ] 深色、浅色、高对比度及窄侧栏无明显问题。
- [ ] TypeScript、DOM 脚本解析、状态纯函数和相关领域测试通过。
- [ ] Extension Host 人工确认原生 View、编辑器、Git Diff 和关闭顺序。

## 15. 规则维护

- 新增通用 UI 行为时，先更新本文，再更新实现和自动化点检。
- 两区 Primary Shell 契约是特殊锁定规则；除非用户在看到冲突提示后明确批准，不得降级、删除或用新计划默认覆盖。
- `0.x` 功能计划只链接本文并记录偏差，不复制整套规则。
- 临时试验若与本文冲突，必须在试点文档中写明范围和退出条件。
- 已废弃方案应标记为历史，不与当前规则并列陈述。
