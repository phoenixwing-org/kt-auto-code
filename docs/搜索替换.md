# 工作区搜索替换

工作区搜索替换用于在当前 VS Code 工作区或用户选择的本地工作目录中搜索和执行三类精确修改，不限于源码文件：

- 文件夹名中的命中片段替换。
- 文件名中的命中片段替换。
- 文本内容替换。

## 使用方式

1. 打开 Activity Bar 的 **KT Auto Code**。
2. 选择 **搜索替换**，先选择目录，再填写搜索值和替换值。
3. 点击 **搜索**查看只读匹配结果；填写替换内容后，**替换**按钮才可执行写盘。

搜索、替换或前缀输入框中的 `Enter` 不触发操作。搜索和替换必须点击明确按钮；写盘前仍会弹出确认框，并明确显示实际工作目录。左侧箭头只收起第二行替换输入，不隐藏目录、范围选项或关联规则。

**工作目录**位于搜索行上方，默认使用当前 VS Code 工作区根目录。下拉优先列出多根工作区、一级 Git 子目录和其他一级子目录，再列出最近目录；右侧文件夹按钮可选择任意内部或外部目录：

- 工作区内部目录保存到 VS Code `workspaceState`，使用相对路径，只在当前工作区显示。
- 工作区外部目录保存到扩展 `globalState`，使用绝对路径，可跨工作区选择。
- 两组各最多保留 12 条；选择工作区根目录时输入框恢复为空，不生成冗余记录。

- 相对路径（如 `src/OldModule`）相对当前工作区解析；工作区内的非根目录本身会参与文件夹改名。
- 工作区外的绝对目录作为独立扫描根，可处理其内部的文件夹、文件名和文本，但不自动改名该根目录。
- 外部扫描根只读取它自己已有的 `.phoenix/.ignore`，不会把当前工作区尚未保存的 Ignore 草稿跨项目套用过去，也不会因预览自动创建外部配置。
- 未打开 VS Code 工作区时，仍可通过文件夹按钮选择绝对目录运行；相对路径不可用。
- 指向单个文件、目录不存在或工作区内路径经过符号链接时拒绝执行。

## 关联规则

点击 **展开关联规则**可增加多行搜索/替换，每行可启用、排序、删除或通过末尾按钮继续派生。**+ 自定义规则**、**常用规则**、**CAA 规则**和每行末尾按钮都打开同一个添加对话框：分析得到的候选规则按行列出并可多选，底部始终保留一行空白 Source / Target 供手工填写。

```text
CaaStudy → TomBuild
Caa Study → Tom Build
KTCCaaStudy → KTMTomBuild
```

源、目标前缀是普通文本，例如 `KTC → KTM`；任一前缀为空时，不生成前缀或 CAA 组合规则，仍可使用基础替换与空格规则。自动生成行被手工修改后转为自定义规则，之后重新生成不会覆盖它。已经存在的 Source 不再出现在候选中；确定添加时也会再次去重，不覆盖旧规则。

**CAA 规则**在同一对话框内展示两种目标方案：

- **完整名称 I/E**：`PNXITemplateFeature → PNXICurveDivision`，默认勾选。
- **仅替换末词段 I/E**：`KTCIAutoCode → KTCIAutoBuild`，作为可选候选展示。

同一 Source 的不同 Target 方案不能同时加入；按对话框顺序保留第一个选中项。逐行按钮使用相同算法，可选择空格、前缀、CAA I 或 CAA E 规则。真实依据与边界见 [PNXCaaStudy CAA 命名规则调查](./PNXCaaStudy-CAA命名规则调查.md)。

关联规则 Dialog 已由 `ktc-associated-rule-picker` Web Component 统一承载：Picker 只展示候选并回传勾选结果，候选派生、同 Source 竞争和追加去重仍由 Model/Extension Host 负责；组件不直接访问 VS Code API。Picker 状态是只发回请求来源 View 的一次性 transient，不写入 Host durable state，也不会在 Webview 重建或后续普通状态更新时重新弹出。责任边界、行为冻结和保留 Browser 回执见[关联规则选择器组件化 Baseline 点检](./关联规则选择器组件化Baseline点检表.md)。

## 工作区规则档案

关联规则区提供 **规则档案…** 下拉和 **保存规则**按钮：

- 下拉只把已保存档案填入当前草稿，不自动预览、替换或再次保存。
- 只有点击 **保存规则**并确认名称后，才写入当前工作区 `.phoenix/search-replace.json`。
- 档案包含母规则、源/目标前缀、关联规则、替换范围、工作目录和 Ignore 选项。
- 同名档案由用户明确选择更新或另存；取消不会写文件。
- 文件缺失时只显示空列表，不自动创建；现有 JSON 损坏时拒绝覆盖。
- 搜索词、替换词和关联规则不写入机器级状态；内部最近目录只进 `workspaceState`，外部最近目录只进 `globalState`，均不加入 VS Code Settings Sync。

`.phoenix/search-replace.json` 是可读的项目配置，是否提交 Git 由项目决定。临时输入仍保存在 Webview state，与共享档案分离。

规则默认**精确匹配大小写**。勾选“同时匹配全大写”后，每条显式规则另派生一条全大写规则；不猜测驼峰以外的任意混合大小写。最长匹配优先，同长度按界面顺序，替换结果不再级联进入后续规则。

## 安全策略

- 文件名和文件夹名在单个 basename 内替换所有命中片段，不直接替换完整路径字符串。
- 当用户同时勾选多个级别时，执行顺序固定为**文本 → 文件名 → 文件夹**，与旧版 Windows 工具一致；未勾选的级别跳过，不改变其余级别的相对顺序。
- 文本阶段先遍历当前路径下的文件。每个文件只读取一次，并对同一份原始字节应用全部启用的关联规则：最长匹配优先、同长度按规则顺序，替换结果不再进入下一条规则。
- 文件夹阶段最后递归收集并按最深层到最浅层改名；每完成一个阶段都重新收集当前工作目录条目。
- **工作目录留空时，当前 VS Code 工作区根目录永不改名**：扫描只收集其内部条目，不会使打开的工作区失效。
- 工作目录指向工作区内部的非根目录时，该目录本身属于扫描条目，可以被改名。
- 工作目录指向工作区外部时，该目录成为独立根目录，同样不自动改名；结果 View 使用该实际根目录打开文件。
- 当勾选“文件夹名”并运行搜索/替换时，若根目录名称命中任一启用规则，Primary 面板下方显示建议的新名称；插件不提供自动改名，用户自行在 VS Code 外部完成根目录改名后再重新打开工作区。
- 提示中的“创建 TODO”会在工作区根目录创建并打开 `KT-AUTO-CODE-TODO.md`，列出当前名、建议名和手动改名步骤；仅在用户点击时写入，已有同名文件不覆盖。
- 目标路径已存在或多个源映射到同一目标时，替换前预检返回 `blocked`，不弹写盘确认框，也不执行部分改名。
- 写盘后结果行指向新路径，可继续定位文件或文件夹。
- 支持大小写-only 改名，通过临时名称保证在大小写不敏感文件系统上可执行。
- 自动跳过符号链接、常见构建目录、二进制后缀和含 NUL 的文件。
- 默认读取 `.phoenix/.ignore`；“包含 Ignore 路径”只用于明确的人工操作。
- 搜索不写盘，写盘前插件再次显示 Modal 确认。

## 编码行为

文本替换先检测文件编码，再按该编码生成匹配字节并在原始 Buffer 上精确替换。只有**原文件为 ASCII 且目标文本含非 ASCII 字符**时，ASCII 无法表达用户希望使用 UTF-8 还是 GBK，才使用关联规则区域的“默认编码”下拉框；其他情况保持检测到的原编码。完整决策见[搜索替换编码规则](./搜索替换编码规则.md)。

| 文件编码 | 当前行为 |
| --- | --- |
| ASCII | ASCII 目标保持 ASCII；目标含非 ASCII 时使用界面选择的 UTF-8 或 GBK 默认编码 |
| UTF-8 / UTF-8 BOM | 支持任意 UTF-8 旧名和新名；保留 UTF-8 是否带 BOM、换行和其他字节 |
| GBK | 支持可按 GBK 表示的旧名和新名；保持 GBK、原始换行和其他字节不变 |
| UTF-16 / UTF-32 / unknown | 列为跳过，不写盘 |

GBK 限制是有意的安全边界：Node.js 没有内置 GBK 编码器，在未引入经过验证的转码依赖前，不对包含非 ASCII 新旧名的 GBK 文件写盘。

## 当前界面形态

搜索值、替换值、级别、工作目录、最近目录下拉和 Ignore 选项放在 Side Bar；结果组件直接展示只读匹配与执行结果。完整结果保留在 Host，Webview 每次只接收 300 行；点击“继续加载”时按报告版本请求下一页，避免旧分页混入新结果。
