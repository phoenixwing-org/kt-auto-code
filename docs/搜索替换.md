# 工作区搜索替换

工作区搜索替换用于在当前 VS Code 工作区或用户选择的本地工作目录中搜索和执行三类精确修改，不限于源码文件：

- 文件夹名中的命中片段替换。
- 文件名中的命中片段替换。
- 文本内容替换。

## 使用方式

1. 打开 Activity Bar 的 **KT Auto Code**。
2. 选择 **搜索替换**，先选择目录，再填写搜索值和替换值。
3. 点击 **搜索**查看只读匹配结果；填写替换内容后，**替换**按钮才可执行写盘。

搜索、替换或前缀输入框中的 `Enter` 不触发操作。搜索和替换必须点击明确按钮；写盘前仍会弹出确认框，并明确显示实际工作目录。左侧箭头只收起第二行替换输入，不隐藏目录、范围选项或关联规则。

**工作目录**位于搜索行上方，默认使用当前 VS Code 工作区根目录。下拉优先列出多根工作区、一级 Git 子目录和其他一级子目录，再列出最近目录；右侧文件夹按钮可选择任意内部或外部目录：

- 工作区内部目录保存到 VS Code `workspaceState`，使用相对路径，只在当前工作区显示。
- 工作区外部目录保存到扩展 `globalState`，使用绝对路径，可跨工作区选择。
- 两组各最多保留 12 条；选择工作区根目录时输入框恢复为空，不生成冗余记录。

- 相对路径（如 `src/OldModule`）相对当前工作区解析；工作区内的非根目录本身会参与文件夹改名。
- 工作区外的绝对目录作为独立扫描根，可处理其内部的文件夹、文件名和文本，但不自动改名该根目录。
- 外部扫描根只读取它自己已有的 `.phoenix/.ignore`，不会把当前工作区尚未保存的 Ignore 草稿跨项目套用过去，也不会因预览自动创建外部配置。
- 未打开 VS Code 工作区时，仍可通过文件夹按钮选择绝对目录运行；相对路径不可用。
- 指向单个文件、目录不存在或工作区内路径经过符号链接时拒绝执行。

## 大型项目改名分析

在 Primary 中打开 **搜索替换**，选好顶部工作目录后，点击关联规则旁的 **大型项目改名分析…**，即可为该目录创建独立 Editor View。命令面板中的 **KT Auto Code：大型项目改名分析** 是备用入口；从命令面板打开时默认使用当前工作区首个根目录。

一个大型项目改名 View 对应一个独立分析任务：

- View 顶部使用与“头文件引用修正”一致的固定 command header：左侧显示任务名和当前分析目录，右侧放置 **分析 / 取消 / 执行改名 / 结束任务** 等主要按钮。路径是带完整 tooltip 的任务上下文而不是可编辑输入框；只有创建任务时没有任何目录来源，header 才允许选择一次目录。
- 创建时固定 Primary 当前工作目录；之后切换 Primary 目录或再次点击入口，只会聚焦现有 View，不会覆盖它的目录、规则或报告。
- 若要为另一目录建立任务，请先关闭现有 View，在 Primary 选择新目录，再点击 **大型项目改名分析…**。
- 没有已打开工作区、也没有从 Primary 带入目录时，View 才允许在任务开始前选择一次目录。

View 内的 **名称与规则**、**总览**、**命中与风险** 使用与 **合并 commit 区间** 一致的可折叠 Block；三块可独立展开或收起，折叠只改变显示状态，不会清空当前任务、规则或分析结果。

该 View 面向 Web 等大型仓库完成“只读分析 → 冻结计划 → 受控写盘 → 重新扫描 → 结束门禁”的完整任务，不占用 Primary Side Bar。分析按钮始终只读；只有显式点击固定 header 中的 **执行改名** 并通过门禁与确认后才会写盘。

- 从原名和目标名派生 Display、kebab-case、snake_case、camelCase、PascalCase 与 UPPER_SNAKE 六种规则；每条规则可编辑和停用。
- 短前缀、缩写或协议标识不自动猜测，使用“添加显式规则”逐项填写，例如 `Pdh → Pnh`。
- 完成精确规则扫描后，View 会额外提示 `open-issue → issue`、`OpenIssue → Issue` 一类真实出现的相关短写法，并排除它们位于 `phoenix-open-issue` 完整命中内部的次数。候选默认不参与报告；点击“加入规则”也只会生成一条**未启用**的显式规则，仍需人工审查并主动勾选后重新分析。
- 同时分析文本内容、文件名和目录名；默认覆盖 `.github`、`.storybook`、`.vscode` 等 Web 点目录，同时跳过 `.git`、`node_modules`、构建输出、符号链接、二进制和超大文件。
- 结果展示目标预览、路径冲突，以及包契约、环境变量、构建配置、CI、源码和文档等风险分类；点击“打开”可定位到本次报告中的真实文件或目录。
- 若仓库根目录名本身命中规则，“总览”会显示 `phoenix-open-issue → phoenix-issue` 建议。只有分析目录不是当前 VS Code 工作区根目录、也不包含任何当前工作区根目录时，才显示 **重命名根目录…**；操作前再次显示源路径和目标路径并要求明确确认。
- 根目录改名只移动同一父目录下的这一层目录，不修改仓库内部内容，不跟随符号链接，也不覆盖已存在的目标。成功后 View 绑定新路径并清空旧报告，需重新分析；Primary 中保存的旧目录记录不会被静默改写。
- 扫描异步、可取消；Host 保留完整报告，View 首屏和后续分页每次最多接收 200 行。单次分析最多收集 20,000 个结果项，达到上限会明确提示截断。

### 执行改名与结束门禁

**执行改名**复用搜索替换的精确规则、编码检测、Ignore、冲突预检和写盘顺序，不维护第二套改名引擎。执行范围固定为当前报告中的文本、文件名和目录名命中：

- 规则、名称或启用状态在分析后发生任何变化，按钮立即禁用，必须重新分析；Webview 只提交报告版本，实际路径和规则由 Extension Host 的冻结报告决定。
- 报告截断、存在冲突/错误、没有命中，或执行前重新预检发现命中位置、次数、目标路径已漂移时，均不弹写盘确认且不做部分修改。
- Git 仓库存在未提交、已暂存或未跟踪改动时阻止写盘，先保留可恢复基线；非 Git 目录允许执行，但确认框会明确提示无法依赖 Git 恢复。
- 写盘顺序固定为文本 → 文件名 → 最深目录到最浅目录；包含 `.github`、`.storybook`、`.vscode` 等分析报告中的 Web 点目录，仍跳过符号链接、二进制、大文件边界和通用构建目录。
- 确认框显示实际目录、计划项、替换次数和 Git 状态；未主动启用的智能候选永远不参与执行。
- 成功写盘后自动用同一规则重新扫描。总览显示 **目标已达到**、**本次计划完成数**和**剩余项**；失败项存在时不允许结束。

**结束任务**只有两个门禁满足其一才启用：重新扫描后没有精确命中且没有冲突/截断，即“目标已达到”；或本次冻结计划的全部项目都成功写盘，即“本次计划全部完成”。后一种情况允许保留人工决定不处理的仓库根目录建议或智能候选。结束动作只关闭当前 View；如需另一目录，回到 Primary 重新创建任务。

## TODO：结构化名称模式规则

2026-09-01 可行性结论：**只读正则发现可行，受约束的结构化名称转换可行，裸正则直接写盘不建议实施**。`0.8.0` 只归档方案，不增加正则输入框或新的写盘语义。

| 能力 | 可行性 | 决策 |
| --- | --- | --- |
| 正则只读发现、计数和候选提示 | 高 | 可作为后续独立扫描模式，但必须限制输入长度、运行时间和结果上限。 |
| “词段 + 受控连接符 + 大小写迁移”的结构化预览 | 高 | 推荐路线；先把每个动态命中编译成明确的源文本、目标文本和位置。 |
| 结构化规则写入文本内容 | 中高 | 需扩展冻结报告为逐命中计划，并增加文件内容指纹、字节区间和目标文本复验。 |
| 结构化规则改文件名/目录名 | 中 | 需额外处理空名称、路径分隔符、大小写文件系统、重叠改名和多源同目标冲突。 |
| 任意 JavaScript 正则 + `$1`/脚本式替换直接写盘 | 低 | 不进入产品路线；存在回溯耗时、零宽匹配、重叠语义、动态输出和编码偏移风险。 |

推荐提供受约束的“结构化名称模式”，而不是把裸正则表达式直接加入现有精确规则。目标是把旧名称拆成“词段 + 实际连接符”，再按目标模板映射或删减词段。例如：

```text
A <连接符1> B <连接符2> C
→ A1 <连接符1> B1 <连接符2> C1
→ A1 <连接符1> C1
```

- 连接符从命中内容捕获并原样复用，可覆盖空格、`-`、`_`、`.` 以及无连接符的 camel/Pascal 形式；不得把依赖范围放宽为任意字符。
- 每个词段按命中形态迁移大小写，例如全小写、首字母大写、全大写、camel/Pascal 词段分别得到对应目标形态；无法可靠分类的混合大小写只报告、不自动猜测。
- 目标模板允许重命名、保留或显式删除词段，但不能用自由脚本执行计算，也不能让替换结果再次进入同一轮匹配。
- 必须提供标识符/路径边界、最长匹配优先、重叠规则诊断、文件与目录目标冲突预览，并继续遵守二进制、大文件、symlink、Ignore、分页和 20,000 项上限。
- `/open-issue` 一类稳定短 URL、`OpenIssue*` 一类领域前缀以及缩写都必须作为独立契约决策；即使它们与完整项目名共享词段，也不能从删除某个词段自动推断为需要改名。
- 验收时要用大小写不敏感、允许受控连接符的发现扫描反查精确规则矩阵，把“小写空格形式”等未覆盖写法明确列为候选，不能静默漏过。
- 当前精确规则已经形成“只读分析、冻结计划、冲突与漂移门禁、显式确认、写盘复扫”的闭环；结构化名称模式若实施，也必须先生成可逐项审查的冻结计划，不能绕过现有门禁直接正则写盘。

现有 `ReplacementRule` 只有固定 `search → replace`，当前漂移门禁比较命中项目、次数和目标路径；动态正则输出可能在次数不变时改变实际文本，因此不能直接复用该身份。安全实施必须新增逐命中冻结数据：文件内容指纹、原始字节区间、完整原文、确定后的目标文本、所属规则和路径目标。执行前重新读取文件并逐项比对，任何一项漂移都整批阻止，不在写盘阶段重新运行模式。

建议分三阶段：

1. **S1 结构化只读预览**：自定义 parser 只接受词段、命名捕获和受控连接符；禁止任意回溯、lookaround、反向引用、零宽全局替换与自由脚本。扫描结果编译为有限的显式转换计划。
2. **S2 文本受控写盘**：冻结逐命中字节计划，按文件从后向前写入，复用现有编码、Git、Ignore、取消、确认和完成门禁；UTF-8/BOM/GBK 必须分别验证字符到字节偏移。
3. **S3 文件与目录名**：仅在 S2 稳定后开放；目标 basename 仍禁止 `/`、`\\`、`.`、`..` 和空值，并复用大小写临时路径、最深目录优先及全局路径冲突预检。

当前已实现“精确字面候选 + 完整名称覆盖排除 + 默认关闭”的提示层；它不使用正则，也不推断稳定短契约是否应改名。若未来确实需要专家级正则输入，应采用有确定运行上限的 RE2 类语义并先只读预览，不能直接使用 JavaScript `RegExp` 作为大型仓库写盘引擎。

## 关联规则

点击 **展开关联规则**可增加多行搜索/替换，每行可启用、排序、删除或通过末尾按钮继续派生。**+ 自定义规则**、**常用规则**、**CAA 规则**和每行末尾按钮都打开同一个添加对话框：分析得到的候选规则按行列出并可多选，底部始终保留一行空白 Source / Target 供手工填写。

```text
CaaStudy → TomBuild
Caa Study → Tom Build
KTCCaaStudy → KTMTomBuild
```

源、目标前缀是普通文本，例如 `KTC → KTM`；任一前缀为空时，不生成前缀或 CAA 组合规则，仍可使用基础替换与空格规则。自动生成行被手工修改后转为自定义规则，之后重新生成不会覆盖它。已经存在的 Source 不再出现在候选中；确定添加时也会再次去重，不覆盖旧规则。

**CAA 规则**在同一对话框内展示两种目标方案：

- **完整名称 I/E**：`PNXITemplateFeature → PNXICurveDivision`，默认勾选。
- **仅替换末词段 I/E**：`KTCIAutoCode → KTCIAutoBuild`，作为可选候选展示。

同一 Source 的不同 Target 方案不能同时加入；按对话框顺序保留第一个选中项。逐行按钮使用相同算法，可选择空格、前缀、CAA I 或 CAA E 规则。真实依据与边界见 [PNXCaaStudy CAA 命名规则调查](./PNXCaaStudy-CAA命名规则调查.md)。

关联规则 Dialog 已由 `ktc-associated-rule-picker` Web Component 统一承载：Picker 只展示候选并回传勾选结果，候选派生、同 Source 竞争和追加去重仍由 Model/Extension Host 负责；组件不直接访问 VS Code API。Picker 状态是只发回请求来源 View 的一次性 transient，不写入 Host durable state，也不会在 Webview 重建或后续普通状态更新时重新弹出。责任边界、行为冻结和保留 Browser 回执见[关联规则选择器组件化 Baseline 点检](./关联规则选择器组件化Baseline点检表.md)。

## 工作区规则档案

关联规则区提供 **规则档案…** 下拉和 **保存规则**按钮：

- 下拉只把已保存档案填入当前草稿，不自动预览、替换或再次保存。
- 只有点击 **保存规则**并确认名称后，才写入当前工作区 `.phoenix/search-replace.json`。
- 档案包含母规则、源/目标前缀、关联规则、替换范围、工作目录和 Ignore 选项。
- 同名档案由用户明确选择更新或另存；取消不会写文件。
- 文件缺失时只显示空列表，不自动创建；现有 JSON 损坏时拒绝覆盖。
- 搜索词、替换词和关联规则不写入机器级状态；内部最近目录只进 `workspaceState`，外部最近目录只进 `globalState`，均不加入 VS Code Settings Sync。

`.phoenix/search-replace.json` 是可读的项目配置，是否提交 Git 由项目决定。临时输入仍保存在 Webview state，与共享档案分离。

规则默认**精确匹配大小写**。勾选“同时匹配全大写”后，每条显式规则另派生一条全大写规则；不猜测驼峰以外的任意混合大小写。最长匹配优先，同长度按界面顺序，替换结果不再级联进入后续规则。

## 安全策略

- 文件名和文件夹名在单个 basename 内替换所有命中片段，不直接替换完整路径字符串。
- 当用户同时勾选多个级别时，执行顺序固定为**文本 → 文件名 → 文件夹**，与旧版 Windows 工具一致；未勾选的级别跳过，不改变其余级别的相对顺序。
- 文本阶段先遍历当前路径下的文件。每个文件只读取一次，并对同一份原始字节应用全部启用的关联规则：最长匹配优先、同长度按规则顺序，替换结果不再进入下一条规则。
- 文件夹阶段最后递归收集并按最深层到最浅层改名；每完成一个阶段都重新收集当前工作目录条目。
- **工作目录留空时，当前 VS Code 工作区根目录永不改名**：扫描只收集其内部条目，不会使打开的工作区失效。
- 工作目录指向工作区内部的非根目录时，该目录本身属于扫描条目，可以被改名。
- 工作目录指向工作区外部时，该目录成为独立根目录，同样不自动改名；结果 View 使用该实际根目录打开文件。
- 当勾选“文件夹名”并运行搜索/替换时，若根目录名称命中任一启用规则，Primary 面板下方仍只显示建议的新名称。大型项目改名 View 可对**非当前工作区**的分析根目录提供受控单层改名；当前工作区根目录和包含它的父目录始终拒绝改名。
- 提示中的“创建 TODO”会在工作区根目录创建并打开 `KT-AUTO-CODE-TODO.md`，列出当前名、建议名和手动改名步骤；仅在用户点击时写入，已有同名文件不覆盖。
- 目标路径已存在或多个源映射到同一目标时，替换前预检返回 `blocked`，不弹写盘确认框，也不执行部分改名。
- 写盘后结果行指向新路径，可继续定位文件或文件夹。
- 支持大小写-only 改名，通过临时名称保证在大小写不敏感文件系统上可执行。
- 自动跳过符号链接、常见构建目录、二进制后缀和含 NUL 的文件。
- 默认读取 `.phoenix/.ignore`；“包含 Ignore 路径”只用于明确的人工操作。
- 搜索不写盘，写盘前插件再次显示 Modal 确认。

## 编码行为

文本替换先检测文件编码，再按该编码生成匹配字节并在原始 Buffer 上精确替换。只有**原文件为 ASCII 且目标文本含非 ASCII 字符**时，ASCII 无法表达用户希望使用 UTF-8 还是 GBK，才使用关联规则区域的“默认编码”下拉框；其他情况保持检测到的原编码。完整决策见[搜索替换编码规则](./搜索替换编码规则.md)。

| 文件编码 | 当前行为 |
| --- | --- |
| ASCII | ASCII 目标保持 ASCII；目标含非 ASCII 时使用界面选择的 UTF-8 或 GBK 默认编码 |
| UTF-8 / UTF-8 BOM | 支持任意 UTF-8 旧名和新名；保留 UTF-8 是否带 BOM、换行和其他字节 |
| GBK | 支持可按 GBK 表示的旧名和新名；保持 GBK、原始换行和其他字节不变 |
| UTF-16 / UTF-32 / unknown | 列为跳过，不写盘 |

GBK 限制是有意的安全边界：Node.js 没有内置 GBK 编码器，在未引入经过验证的转码依赖前，不对包含非 ASCII 新旧名的 GBK 文件写盘。

## 当前界面形态

搜索值、替换值、级别、工作目录、最近目录下拉和 Ignore 选项放在 Side Bar；结果组件直接展示只读匹配与执行结果。完整结果保留在 Host，Webview 每次只接收 300 行；点击“继续加载”时按报告版本请求下一页，避免旧分页混入新结果。
