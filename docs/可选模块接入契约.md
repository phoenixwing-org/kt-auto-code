# 可选模块接入契约

KT Auto Code 是共享 Side Bar Shell。CAD 以及后续模块是独立 VS Code 扩展，但不重复实现 Activity Bar、Ribbon 或 Block 状态机。

## 面向用户的功能关系

![KT Auto Code 与 KT Auto CAD 功能关系](assets/KT-Auto-Code-CAD功能关系.png)

用户只安装 KT Auto Code 即可使用代码开发工具；加装 KT Auto CAD 后，会在同一个侧边栏中增加 CAD 文件、FCStd、BOM 与引用能力。下面章节只面向扩展开发者说明接入契约。

## 职责边界

| Shell（`kt-auto-code`） | 可选模块（例如 `kt-auto-cad`） |
| --- | --- |
| 发现 `ktAutoCodeModule` 清单 | 声明模块元数据与 Ribbon 工具 |
| 管理模块显示、当前模块和持久化 | 贡献原生 Header 勾选命令 |
| 渲染共享 Ribbon 与打开/当前样式 | 实现工具命令与业务状态 |
| 管理 Block 容器、Header、关闭和 MRU 历史 | 注册 Block provider，只返回工具内容 |
| 校验并分发模块命令 | 通过 Shell API 打开、关闭逻辑 Block |

数据流固定为：

```text
模块 manifest -> Shell 自动发现 -> 共享 Ribbon
Ribbon 点击 -> Shell showModuleTool -> 模块 command -> provider 内容挂入 Shell Block
详情关闭 -> Shell closeModuleTool -> 恢复最近的其他 Block
```

## Manifest 清单

可选模块在自己的 `package.json` 中声明：

```json
{
  "ktAutoCodeModule": {
    "id": "drawing-review",
    "title": "Review",
    "order": 30,
    "commandPrefix": "ktDrawingReview.",
    "tools": [
      {
        "id": "drawingReviewOpen",
        "shortTitle": "审图",
        "title": "打开审图",
        "description": "审图模块入口",
        "command": "ktDrawingReview.open",
        "icon": "extension:media/review.svg",
        "requirement": "none"
      }
    ]
  }
}
```

- `id` 使用小写字母、数字和连字符，并且在 Shell 中唯一。
- `order` 决定可选模块和工具组顺序。
- `commandPrefix` 限制工具只能调用本模块命令。
- 工具 `id` 当前必须在所有模块间唯一，建议使用模块前缀。
- `shell:` 图标来自基础插件；`extension:` 图标来自模块自身。
- `requirement` 只描述能力要求，依赖提示由模块详情 UI 展示。
- Ribbon 工具命令只调用 `showModuleTool` 打开或切换 Block；扫描、读取、查询等业务动作放入 provider 的 `headerActions/handleAction`，避免重新选择已打开 Block 时重复执行。

## Header 与 Block provider

模块自行贡献一对 Header `show/hide` 命令，命令内部按目标状态调用 Shell API v2 的 `toggleModule(id)`。原生 Header 的文字型 `toggled` 状态不明显，因此菜单通过互斥 `when` 显示 `☐ Module` 或 `☑ Module`；条件使用 `ktAutoCode.module.<id>.visible` 和 `ktAutoCode.module.<id>.installed`。Shell 会为所有已发现模块维护这些 context key。

模块不贡献自己的详情 View。激活后通过 Shell API 注册 provider：

```ts
shell.registerModuleBlockProvider("drawing-review", {
  render(toolId) {
    return {
      title: "审图",
      description: "当前图纸检查",
      status: "直接可用",
      headerActions: [{ id: "refresh", title: "刷新", icon: "↻" }],
      html: "<section>模块自己的内容</section>",
    };
  },
  handleAction(toolId, actionId) {
    // 只处理模块业务；不控制容器显隐。
  },
});
```

Shell 统一渲染 Block 标题、状态和 Header icon buttons，并把 `html` 片段挂入内容区。模块不创建 Activity Bar Container、Webview View，不重做 Ribbon，也不控制关闭或恢复行为。

## Shell API v2

共享类型位于 `src/moduleShellContract.ts`：

- `getModuleState()`：读取安装、显示和当前模块状态。
- `toggleModule(id)`：切换该模块是否出现在 Ribbon。
- `activateModule(id)`：让该模块成为统一 Block 容器的当前模块。
- `registerModuleBlockProvider(id, provider)`：注册模块 UI 内容提供者。
- `refreshModuleBlock(id)`：业务状态变化后刷新当前内容。
- `showModuleTool(id, toolId)`：登记并显示逻辑 Block。
- `closeModuleTool(id, toolId)`：关闭逻辑 Block并恢复 MRU Block。

新增模块只消费这份 API，不访问 `SidebarViewProvider`，也不复制 Code/CAD 分支。

## TODO：容器布局策略

- 在 Shell 增加 `exclusive`（排他显示）与 `split-vertical`（上下分栏同时显示）策略。
- 布局策略只改变 Block 容器的排列、展开和恢复规则，不修改 provider 的 HTML 与业务状态。
- Header action、关闭、MRU 和打开态继续由统一容器处理。
- provider 始终只实现单个 Block 内容，因此旧模块无需为新布局模式改造内部 UI。
