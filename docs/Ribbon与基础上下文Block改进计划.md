# Ribbon 与基础上下文 Block 改进计划

状态：completed（实现、自动验证与人工界面点检均完成）

Owner：KT Auto Code maintainers

适用版本：0.6.x

最后核验：2026-08-08

## 1. 目标

随着 Code、CAD 和后续可选模块增加，全部工具平铺会持续占用侧栏高度；当前把 Ribbon 与工具界面贡献为两个原生 View，又会出现可拖动分隔线和需要人工调节的空白高度。本轮将侧栏收敛为一个共享 Shell：

```text
KT AUTO CODE（一个 Webview View）
├─ 工具栏 Block（可折叠；按内容自动换行和增高；Header 只保留一个 `…`）
├─ 工作目录与 Ignore Block（可折叠；共享文件工具上下文）
└─ 当前工具 Block（可折叠；标题与明确的 `×`；内容区独立纵向滚动）
```

目标不是禁止用户调整整个侧栏或 View Container，而是取消 Ribbon 与工具内容之间的第二个原生 View 和可拖动分隔条。Ribbon 成为同一 Webview 内的普通内容区，高度只由当前入口数量、显示密度和可用宽度决定。

## 2. 调查结论

VS Code 的公开 `WebviewView` / `WebviewViewProvider` API 支持解析、显示、标题和可见性事件，但没有按 Webview 内容像素自动设置 View 高度、锁定 View 高度或禁止相邻 View 分隔条拖动的接口。`contributes.views[].initialSize` 只是初始权重，也不能形成固定高度。

因此采用以下方案：

- 只贡献一个 Webview View；Ribbon、基础上下文和当前工具均在其内部渲染。
- 三个区域使用 VS Code Source Control “存储库 / 更改”式全宽分区 Header，不用卡片外边距表达 Block。
- 三个 Block 可独立折叠，折叠状态只属于 Webview UI 会话；折叠任一区域不得影响另外两区域。
- 不用脚本测量高度，不模拟拖动条，不循环修改 `initialSize`。
- 页面本身不承担日常纵向滚动；前两个 Block 自然占高，当前工具 Block 填充剩余高度并在内容区内部滚动。
- 保留 VS Code 对整个 View Container 的移动、调整宽度和折叠能力。

参考：

- [VS Code Views UX Guidelines](https://code.visualstudio.com/api/ux-guidelines/views)
- [VS Code Panel UX Guidelines](https://code.visualstudio.com/api/ux-guidelines/panel)
- [VS Code Contribution Points](https://code.visualstudio.com/api/references/contribution-points#contributes.views)

## 3. Ribbon 定制模型

### 3.1 两档显示密度

只保留两档，避免同类设置不断增加：

| 模式 | 显示 | 用途 |
| --- | --- | --- |
| 图标与文字 | 图标 + 最多两行短标题 | 默认；入口清楚，适合新用户 |
| 仅图标 | 小图标；悬停显示完整名称 | 紧凑；适合工具较多或侧栏较窄 |

沿用 `ktAutoCode.sidebar.toolPickerStyle`，但设置说明和命令文案改为“图标与文字 / 仅图标”。不增加第三档尺寸。

### 3.2 置顶与更多菜单

- 每个模块维护自己的常驻工具集合。
- 已置顶工具显示在 Ribbon；未置顶工具进入该模块的 `…` 菜单。
- Shell 只有一个 `…`，位于“工具栏” Block Header 右侧；菜单内按 Code/CAD 分组列出全部工具，每行提供 Cursor 风格的固定/取消固定按钮。不在每个模块尾部重复放置 `…`。
- 窄侧栏中菜单以 Header `…` 为锚点，限制在 Webview 可视区并在需要时内部滚动，不得被 Primary 宽度或底部边界裁切。
- 点击菜单中的工具立即打开对应 Block；如果它未置顶，只作为“当前临时入口”显示，关闭或切换后仍回到 `…`。
- 当前工具不得因为未置顶而完全失去可见反馈。
- 点击已经打开且当前显示的 Ribbon 入口只保持当前 Block 并恢复焦点，不执行关闭。关闭必须点击 Tool Block 右上角明确的 `×`；不提供“再次点击即关闭”的可选行为，避免双击或误点丢失当前界面。
- 新安装的可选模块可以给少量核心工具默认置顶；后续新增工具默认进入 `…`，避免升级后打乱既有布局。

### 3.3 拖动排序

- Ribbon 内容区只允许拖动已置顶入口；`…` 菜单允许调整模块内全部工具的稳定顺序，使未置顶工具以后固定时也出现在用户选择的位置。
- 鼠标拖动入口即可调整同一模块内的顺序；拖动过程中显示来源半透明和目标插入提示。
- 不允许把工具拖到另一个模块；跨模块功能归属仍由 manifest 决定。
- `…` 中的列表顺序与 Ribbon 顺序一致；未置顶项排在置顶项之后，并保持模块 manifest 的稳定顺序。
- 键盘用户可以在 `…` 菜单中使用“上移 / 下移”完成等价排序，不能把拖动作为唯一入口。

排序算法保存稳定的 `toolId[]`，不保存数组位置数字：过滤已经卸载的 ID，保留仍存在的相对顺序，再把新 ID 追加到尾部。置顶集合与顺序分开保存，取消置顶不会丢失用户为该工具安排的位置。

### 3.4 模块连续排布

- Code、CAD 等模块仍有短标签或分隔标识，但每个模块不再强制从新的一行最左侧开始。
- 外层 Ribbon 统一换行；模块标签、工具入口和 `…` 按内容宽度连续排列。
- 不允许单个模块建立独立的全宽行或预留空白列。
- 窄侧栏可以自然换行，但不得出现页面级横向滚动。

## 4. 状态与配置归属

| 状态 | 存储 | 原因 |
| --- | --- | --- |
| `图标与文字 / 仅图标` | VS Code User Setting | 明确的机器级插件偏好，已有设置可兼容 |
| 置顶工具 ID 与排序 | Extension Host `globalState` | 本机 UI 偏好，不属于任何工程；Webview 重建后仍稳定 |
| 当前打开工具与 MRU | Host 会话状态 | 运行时导航，不改变置顶顺序 |
| 三个 Shell Block 的折叠状态 | Webview state | 纯界面状态；各自独立，不进入工程配置 |
| 当前工作目录、插件 Ignore 开关 | `workspaceState` | 每个工作区的临时操作上下文 |
| 最近外部目录 | `globalState` | 本机历史，绝不写入项目 `.vscode/settings.json` |

建议 schema：

```ts
interface KtcRibbonLayoutV1 {
  pinnedToolIds: string[];
  toolOrder: string[];
}
```

Webview 只能发出 `toggleToolPin`、`movePinnedTool` 等语义消息；Extension Host 校验工具 ID、模块边界并持久化，再广播规范化快照。不得只依赖 DOM 顺序或把布局写入工程设置。

## 5. 工作目录与忽略 Block

Ribbon 下方增加 Shell 级“工作目录与忽略”Block，供头文件、编码、搜索替换、UUID、成员排序和 CAA UI 等文件工具复用。目录是扫描候选集，Ignore 是候选集上的过滤器，两者必须在同一处表达：

```text
工作目录与忽略
[文件夹] [当前根 / 一级子目录 / 最近目录                 v]
Git Ignore：自动生效    [x] 插件 Ignore    [管理规则]
```

### 5.1 工作目录

- 下拉包含多根 VS Code 工作区、当前根目录的一级子目录，并优先标识 Git 目录。
- 文件夹按钮位于下拉右侧，可切换到一个工作区内部或外部目录。
- 不选时使用当前 Workspace Folder；多根工作区必须明确显示根目录名。
- 工作区内路径优先保存为相对路径；执行前由 Host 转为绝对路径并验证存在、目录类型和符号链接边界。
- 外部绝对路径只属于本机隐藏状态，不写 `.vscode/settings.json`。
- 工具只消费 Host 已解析的有效工作目录，不各自重复实现目录选择、缓存和展示。
- “搜索替换”移除自身重复目录行；其他文件工具从 Host 的同一 `ToolRunContext` 获取已解析目录。
- Git、Run、Codegen 文档选择等具有独立仓库/工程/文件上下文的功能不被公共目录强行改写。

### 5.2 Git Ignore 与插件 Ignore

本期只提供一项可选开关，避免用户同时判断多套相似选项：

- **Git Ignore 始终生效**：所选工作目录位于 Git 仓库内时，默认读取最近仓库根 `.gitignore`，不提供关闭 checkbox。
- **插件 Ignore 默认开启**：开启时把所选目录对应的 `.phoenix/.ignore` 作为附加过滤层；关闭时只停用插件规则，不绕过 Git Ignore。
- 有效候选集合为 `工作目录内条目 - Git Ignore -（已开启时）插件 Ignore`。
- 所选目录不属于 Git 仓库时，Git Ignore 层为空，只应用可选的插件 Ignore。
- 本期只解析所选目录所在的最近 Git 仓库；如果选择的是不属于 Git 的聚合父目录，不递归发现其下多个仓库。用户可从目录下拉快速切换到具体 Git 子目录。
- “管理规则”用于编辑/检查附加的 `.phoenix/.ignore`；详细预设、分析和文件编辑放在该 Block 的渐进展开区，不再占一个常驻 Ribbon 入口。
- 搜索替换原“包含 Ignore 路径”选项移除，避免它绕过默认 Git Ignore 或与公共开关冲突。

当前实现只在 `.phoenix/.ignore` 不存在时从根 `.gitignore` 复制一次，后续不会同步。迁移后 `.gitignore` 改为实时默认过滤来源，`.phoenix/.ignore` 只表达插件附加规则：

- 不自动重写或清空已有 `.phoenix/.ignore`；旧文件中与 `.gitignore` 重复的规则仅产生无害重复。
- 主界面移除“从 `.gitignore` 同步并覆盖”入口；兼容命令暂留一个版本，待确认没有自动化调用后删除。
- 当前扫描器按 Phoenix Wing 支持的 Ignore 规则子集解析最近仓库根 `.gitignore`；嵌套 `.gitignore`、全局 excludes 和完整 Git 否定/重包含语义仍是后续能力，不得宣称为完整 Git 语义。

### 5.3 工作集退场

工作集概念停止扩展，本轮不把它并入第二个 Block；完整消费者审计与退场步骤见[工作集退场与多目录范围调查](./工作集退场与多目录范围调查.md)：

- 从头文件、搜索替换等日常扫描的主界面移除工作集选择和“加入工作集”入口。
- 当前继续使用一个明确工作目录；多目录是否有必要尚未明确，不在本期实现。
- 新工具不得继续依赖 `.phoenix/worksets.json` 建立范围模型。
- 本期先保留旧配置文件、读取器和公共命令，避免直接破坏历史项目或尚未盘点的 Codegen/其他工具。
- 增加消费者审计 TODO；确认没有实际消费者和自动化调用后，再独立删除后端、配置 schema、命令与文档。
- 兼容期内工作集不得与工作目录、Git Ignore 或插件 Ignore叠加成新的用户规则。
- 现有 `worksets.json` 的处置明确暂停，不纳入本期修改或验收；后续 TODO 见[工作集退场与多目录范围调查](./工作集退场与多目录范围调查.md#9-todo暂停等待用户以后研究)。

## 6. 实施顺序

1. **单 View Shell**：manifest 只贡献一个 Webview View；清理双 View 广播、动态标题和旧诊断字段，Ribbon 与欢迎页/工具 Block 在同一 DOM 中。
2. **布局状态模型**：在 Host 增加 `KtcRibbonLayoutV1` 的规范化、持久化和消息守卫；为纯函数补单元测试。
3. **三 Block Shell 与定制菜单**：实现三个独立折叠 Header、工具 Block `×`、唯一 `…`、固定/取消固定、拖动、键盘上移/下移和模块连续换行；补 DOM/浏览器测试。
4. **显示密度**：沿用原设置并修正文案；验证两档布局、tooltip 和高对比度边框。
5. **工作目录与忽略 Block**：抽取共享目录/Ignore ViewModel 与 Host resolver；接入文件扫描类工具，默认执行最近仓库根 Git Ignore，可选叠加插件 Ignore，并删除重复 UI。
6. **工作集退场第一阶段**：隐藏日常入口并禁用写入，冻结 schema 和新消费；保留已有文件与兼容代码，不增加多目录 UI。
7. **兼容迁移**：第一次启动时从现有工具顺序生成初始布局；旧双 View 的已保存高度无需迁移，旧 View ID 不再注册。
8. **验收与归档**：全量测试、typecheck、architecture、docs、Registry 与本地 Wing 构建、真实 Extension Host 人工点检；通过后更新本计划状态和固定测试 worktree。

## 7. 自动测试要求

- manifest 只存在一个 `ktAutoCode.modulePanel`，不再包含 Ribbon 独立 View 或 `initialSize`。
- 布局规范化覆盖：空状态、未知工具、卸载模块、新增工具、重复 ID 和跨模块拖动拒绝。
- 置顶与排序重建 Webview 后保持；切换工作区不改变机器级 Ribbon 布局。
- 未置顶当前工具临时显示，但不写入置顶集合。
- `…` 中可以打开、置顶、取消置顶、上移和下移；所有动作有 `aria-label` 与键盘焦点。
- 整个 Shell 只有一个定制 `…`；窄宽下不裁切，置顶或排序后菜单保持打开。
- 三个 Block 可分别折叠且互不影响；工具 Block 的折叠按钮只收起内容，`×` 只关闭当前逻辑 Block。
- 长工具内容只在第三个 Block 内滚动；切换工具时分别恢复内部滚动位置，页面本身无日常纵向滚动。
- 图标与文字、仅图标在 300px、500px 侧栏宽度下无横向滚动。
- 深色、浅色、高对比度模式均有边框、hover、活动态和拖动目标反馈。
- 文件扫描类工具得到同一解析目录及 Ignore 开关；内部相对目录、多根工作区的单根选择、外部目录、Git/非 Git 目录均有 Host/纯函数测试。
- Git Ignore 默认生效且不能被插件开关绕过；插件 Ignore 开关只控制 `.phoenix/.ignore` 附加层。
- 旧 `.phoenix/.ignore` 不被迁移流程重写；重复规则规范化后不改变结果。
- 工作集 UI 不再从日常扫描入口可达，但兼容读取在删除前仍通过原有回归测试。

## 8. 人工点检

1. 页面显示“工具栏 / 工作目录与 Ignore / 当前工具”三个 VS Code 式全宽 Block；三个均可独立折叠，不存在可拖动的内部高度分隔条。
2. 切换两档密度，功能和顺序不变。
3. “工具栏” Header 右侧只有一个 `…`；取消固定一个工具后，可从其 Code/CAD 分组重新打开，当前入口临时可见。
4. 连续点击或双击当前入口，Block 不关闭、表单与结果不清空；只有明确点击右上角 `×` 才关闭。
5. 重新固定工具并拖到新位置；关闭、重新打开侧栏和重启 Extension Host 后顺序保持。
6. 用键盘完成同样的固定和上移/下移操作。
7. Code 与 CAD 入口连续排列，窄宽时自然换行，不出现整行空位或横向滚动。
8. 在头文件与搜索替换间切换，共享工作目录和插件 Ignore 开关保持一致；切换另一个 VS Code 工作区后使用该工作区自己的选择。
9. Git 仓库内被 `.gitignore` 排除的目录默认不参与扫描；关闭“插件 Ignore”只恢复 `.phoenix/.ignore` 独有条目，不恢复 Git 忽略项。
10. 日常界面不再出现工作集范围和“加入工作集”；旧配置文件不被自动删除或修改。
11. 未打开任何工具时，Ribbon 与欢迎内容同时正常显示。

### 8.1 最终人工结论（2026-08-08）

以下外层 UI 契约已由用户在固定测试 worktree 中点检通过，并同步固化到[前端开发规则](./前端开发规则.md#11-锁定的三-block-外层契约)：

- 三个主 Block 的数量、顺序和职责固定。
- 三个 Block 都可独立折叠。
- 第三个 Block 内部纵向滚动，Primary 页面不整体滚动。
- 第三个 Block 的折叠与 `×` 是两个独立操作。
- 标题、图标、样式及各 Block 内部功能允许继续改进。

此前已通过的唯一 `…`、窄侧栏菜单、置顶/排序后保持展开、当前工具独立 `×` 以及 Code/CAD 筛选入口继续有效。后续若要改变外层契约，必须先提示规则冲突并取得用户明确确认。

## 9. 非目标

- 不允许用户改变工具所属模块。
- 不把 Ribbon 布局同步进 Git 或团队 `.vscode/settings.json`。
- 不引入第三方拖拽库、Vue 或新的 Webview。
- 不改变工具领域算法、运行结果缓存和写盘确认规则。
- 不在本期提供“忽略/不忽略 Git Ignore”开关、递归多仓库 Ignore 聚合或全局 Git excludes 的额外配置界面。
- 不在本次布局改造中直接删除工作集后端和历史配置文件。
