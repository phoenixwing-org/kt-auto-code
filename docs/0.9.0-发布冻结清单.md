## 正式发布前置门禁

当前已锁定 Registry 依赖的本地实物缺少本轮必需能力：`kt-codegen` 的保存 checkpoint 语义及 Combo Select 通知、`code-core` 的可管理 Combo/清理组件、`run-node` 四个清理 API。版本引用检查只证明版本表和 lockfile 一致，不证明新能力已经发布。

1. [ ] 确认并发布包含本轮修订的 Wing 子包，或选择已经发布且通过能力验收的版本。发布须另外明确授权，不能由 Auto 内测打包隐式代办。
2. [ ] 更新 Auto 的精确 Registry 版本、lockfile 和批准版本表；不得加入本地路径或 override。重新验证 checkpoint、清理运行时、CAA 通知及真实制品。
3. [ ] 从明确的最终提交建立干净发布工作树，核对分支/版本/用户发布意图；不得使用仍有改动的开发目录作为冻结证据。
4. [ ] 按仓库固定 Node/pnpm 环境执行 `release:preflight`、`release:check`、`release:receipt`，要求同一提交与 Registry 来源证据。
5. [ ] 最终版本、制品哈希、手工验收和发布授权确认后，才执行上传、推送或标签动作。

本地 Wing 回执 `publishable: false` 只允许内测，不能改字段或以本地来源冒充正式门禁。当前未发布 Marketplace/Registry、未升级版本、未合并主分支；旧候选均保留，最新内测证据见[内测说明](0.9.0-内测说明.md)。
